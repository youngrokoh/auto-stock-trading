# ML 신호 데이터·모델 계약

- 상태: 구현 기준
- 작성일: 2026-08-21
- 승인: 사용자가 2026-08-21에 8-2 우선 착수, 일봉 2020-01-02 소급, 20거래일 초과수익 횡단면 순위 목표, ML 신호의 별도 전략 전용을 승인. 같은 날 생존 편향의 한계 기록 후 진행과 워크포워드 분할 파라미터(확장창·엠바고 20거래일·검증 60거래일 전진·최소 학습 250거래일)를 승인
- 개정 승인: 사용자가 2026-08-22에 재무 특징 추가(`features-2`, 결측은 계약대로 표본 제외, 특징은 v3와 같은 2종)를 승인
- 관련 결정: [ADR-0012 ML 신호의 전략 경계](../decisions/0012-ml-signal-boundary.md), [ADR-0004](../decisions/0004-ai-execution-separation.md)
- 관련 계약: [백테스트·규칙형 전략 계약](backtest-strategy-contract.md), [재무 지표 정의 계약](financial-indicator-contract.md)
- 관련 로드맵: [구현 로드맵](../plan/implementation-roadmap.md) 8-2단계

## 목적

OHLCV와 보조지표를 숫자 시계열로 바꿔 학습하고, 향후 20거래일 초과수익의 횡단면 순위를 예측한다.
예측은 `ml-rank` 전략의 신호로만 쓰이며 규칙형 전략을 대체하지 않는다.

## 사용자 승인 결정 (2026-08-21)

1. 8단계는 8-2(숫자 시계열 ML)부터 시작한다.
2. 생존 편향은 시점별 지수 구성 이력 원천이 없어 **한계로 기록하고 진행한다.** 성과는 낙관적으로
   치우친 값으로 읽으며, 규칙형 기준 전략도 같은 유니버스로 비교하므로 '규칙형 대비 개선' 판정
   자체는 유효하다. 전 종목(KOSPI 914) 확장이나 구성 이력 확보는 후속이다.
3. 일봉 이력을 **2020-01-02**부터 소급 수집한다. 모의환경 기간별시세가 2020년 구간도 정상
   반환함을 실측했다(2020-01-02~03-31 62행, 2023년 62행, 2024년 63행). 기존 2025-01-02 시작은
   API 한계가 아니라 우리가 정한 시작점이었다.
4. 목표는 **20거래일 초과수익의 횡단면 순위**다.
5. ML 신호는 별도 전략으로만 실행한다(ADR-0012).
6. 워크포워드 분할은 아래 §시점 정합과 워크포워드의 파라미터로 고정한다.

## 목표 (y)

시그널일 `T`의 종목 `s`에 대해

```text
excess(s, T) = (close(s, T+20) / close(s, T) - 1)
             - (bench(T+20) / bench(T) - 1)
y(s, T)      = 같은 T의 후보 종목 집합 안에서 excess의 백분위 순위 (0~1, 큰 값이 우수)
```

- `T+20`은 검증된 XKRX 달력의 20번째 다음 거래일이다. 창을 벗어나면 그 표본을 만들지 않는다.
- **목표 창은 파라미터다**(기본 20거래일, 2026-08-22 승인). 창을 바꾸면 **엠바고 하한도 같이 따라
  간다** — 엠바고를 기본값에 고정하면 60거래일 목표에서 학습 라벨이 검증 구간으로 40거래일 새어
  나간다. `ml.model`의 `target_definition`·`horizon_days`·`embargo_days`가 기준을 기록해 창이 다른
  모델을 나중에 구분할 수 있다.
- 벤치마크는 백테스트 계약과 같은 KODEX 200(`069500`)이다.
- 동점은 평균 순위를 나눠 갖는다(요인 순위와 같은 규칙).
- 순위를 쓰는 이유: 상승·하락 국면 모두에서 상대 비교가 성립하고, 상위 K 동일가중 전략에 바로
  대응하며, 종합 순위(v3)와 지표를 직접 비교할 수 있다.

## 특징 (X)

모든 특징은 **`trading_date <= T`인 확정 일봉만** 사용한다. 보조지표는 규칙형 전략과 같은 순수
함수(`domain/strategies/indicators.py`)를 호출하며 ML용 정의를 새로 만들지 않는다.

| 묶음 | 특징 |
|---|---|
| 수익률 | `ret_1`, `ret_5`, `ret_20`, `ret_60` (종가 기준) |
| 변동성 | `vol_20`, `vol_60` (일간 수익률 표준편차) |
| 캔들 | `body`, `upper_wick`, `lower_wick`, `gap` — 모두 가격으로 정규화 |
| 이동평균 | `dist_sma5`, `dist_sma20`, `dist_sma60` (종가 ÷ SMA − 1), `slope_sma20` (SMA20 5거래일 변화율) |
| 보조지표 | `rsi_14`, `macd_hist_norm` (MACD − 시그널, 종가로 정규화), `atr_14_norm` (ATR ÷ 종가), `bb_percent_b` (20, 2σ) |
| 거래 | `volume_ratio_20` (거래량 ÷ 20일 평균), `value_ratio_20` (거래대금 ÷ 20일 평균) |
| 시장 | `mkt_ret_20`, `mkt_vol_20` (벤치마크), `rel_ret_20` (`ret_20` − `mkt_ret_20`) |

- 특징 정의는 **버전 문자열**(`features-1`)로 고정한다. 하나라도 바꾸면 버전을 올리고, 이전
  모델은 이전 버전으로 남는다.
- 특징 창이 모자라면(신규 상장, 거래정지) 그 종목-일 표본을 만들지 않는다. 0이나 평균으로 채우지
  않는다.
- 정규화는 특징 계산 안에서 끝낸다. 학습 단계에서 표본 전체 통계로 스케일링하면 미래 정보가
  들어온다.

### 재무 특징 (`features-2`, 2026-08-22 사용자 승인)

| 특징 | 정의 |
|---|---|
| `earnings_yield` | 기본주당이익 ÷ 시그널일 종가 (PER의 역수) |
| `roe` | 지배주주 ROE (재무 지표 계약의 정의를 그대로 호출) |

- **지표 정의를 새로 만들지 않는다.** `compute_annual_indicators`·`basic_eps`를 v3와 같은 경로로
  호출한다. 화면·백테스트·ML이 같은 정의를 쓰지 않으면 결과를 비교할 수 없다.
- 시점 정합은 v3와 같다: **접수일이 시그널일보다 앞선** 연간 연결 보고서 중 가장 최근 것을 쓴다.
  접수일은 접수번호 앞 8자리이며 저장 시각(`valid_from`)은 우리의 수집 시각이라 쓰지 않는다.
- 재무를 아직 알 수 없거나 값이 없으면 **그 종목-일 표본을 만들지 않는다.** 가격 특징과 같은 규칙이며
  0·업종 평균으로 채우지 않는다. 결과적으로 학습 유니버스가 줄어드는 것은 계약이 의도한 대가다.
- `features-1` 모델은 그대로 남는다. **특징 집합은 모델별 속성**이므로 추론 경로는 모델에 저장된
  `feature_version`을 따라간다. 이름을 하드코딩하면 집합이 다른 모델에서 열 개수가 어긋난다
  (2026-08-22 실측 결함, [8단계 QA](../qa/phase-8-ml-verification.md) 참조).

## 시점 정합과 워크포워드

- 특징은 `T` 이하, 목표는 `T+1`~`T+20`이다. 특징 계산이 `T` 이후 행을 참조하지 않는지 접두
  시계열 재계산으로 검사한다(규칙형 전략의 `lookahead_input` 검사와 같은 방식).
- 분할은 **확장창 워크포워드**다.

```text
학습 [start .. b]  →  엠바고 20거래일  →  검증 [b+21 .. b+21+59]
다음 구간: b를 60거래일 전진
```

- **엠바고 20거래일이 계약의 핵심이다.** 학습 표본의 마지막 목표는 `b+20`까지의 미래를 본다.
  엠바고 없이 검증 구간을 `b+1`부터 잡으면 검증 초반이 학습 목표와 같은 미래를 공유해 성능이
  실제보다 좋게 나온다.
- 첫 학습 구간의 최소 표본은 250거래일 × 유니버스다. 미달이면 학습을 거부한다.
- 검증 구간은 60거래일씩 전진한다.

## 모델

| 순서 | 모델 | 목적 |
|---|---|---|
| 1 | Ridge 회귀 | 해석 가능한 기준선. 특징이 신호를 담는지 먼저 확인한다 |
| 2 | LightGBM | 주력 표 모델 |
| 3 | 1D CNN·LSTM | 위 둘이 규칙형을 넘어선 뒤의 실험 |

- 모델 파일은 LightGBM 텍스트·Ridge 계수 JSON처럼 **해당 모델의 안전한 네이티브 포맷**만 쓴다.
  Python pickle은 임의 코드 실행 위험 때문에 금지한다(기술 스택 §6.1).
- 학습은 고정 시드를 저장하고, 같은 입력·시드·하이퍼파라미터면 같은 모델 산출물이 나와야 한다.
- 하이퍼파라미터는 canonical JSON으로 저장한다.

## 저장 (`ml` 스키마)

- `ml.model`: 모델 ID, 이름, 버전, 알고리즘, 특징 정의 버전, 학습 창, 엠바고 일수, 목표 정의
  문자열, canonical 하이퍼파라미터, 시드, 산출물(네이티브 포맷 텍스트), 입력 일봉 버전 해시,
  유니버스 종목 수, 생성 시각.
- `ml.model_evaluation`: 모델별 워크포워드 구간(구간 번호, 검증 시작·종료), 지표 이름과 값.
- `ml.feature_importance`: 모델별 특징 이름과 중요도.
- 예측값은 저장하지 않는다. 백테스트가 저장된 모델로 추론하며, 실행 기록의 모델 ID·특징 버전이
  재현 근거다. 그림자 운용을 도입할 때 예측 저장을 별도로 정의한다.

## 평가 지표

| 지표 | 정의 |
|---|---|
| 순위 상관(IC) | 구간별 예측 순위와 실제 순위의 스피어만 상관, 구간 평균과 표준편차 |
| 상위 K 초과수익 | 예측 상위 10종목의 20거래일 평균 초과수익 |
| 적중률 | 상위 10종목이 벤치마크를 초과한 비율 |

- **최종 판정은 백테스트 결과로 한다.** 위 지표는 진단이며, 완료 기준은 `ml-rank` 실행이 같은
  창·같은 비용에서 `composite-rank`를 넘는지다.
- 구간별 지표를 모두 저장한다. 평균만 보고하면 한 구간에 성과가 몰린 것을 놓친다.

## 구현 결과 (2026-08-22)

- `features/price_features.py`가 계약의 23개 특징을 계산한다. 전체 시계열을 받아 날짜별 행을
  돌려주는 형태여서 접두 시계열 재계산과 값이 같은지 검사할 수 있다(계약 검증 1을 테스트로 고정).
- 특징 창이 모자라거나 값이 하나라도 없으면 그 행을 만들지 않는다. 0·평균으로 채우지 않는다.
  가장 긴 창이 60거래일 수익률이라 61번째 봉부터 행이 생긴다.
- 가격이 0 이하인 행은 나눗셈을 시도하지 않고 표본에서 빠진다.
- `features/targets.py`가 20거래일 초과수익과 횡단면 백분위(최고 1.0, 동점은 백분위 공유)를
  만든다. 후보가 둘 미만이면 상대 순위가 성립하지 않아 빈 결과다.
- `features/splits.py`의 `walk_forward_folds`는 **엠바고가 목표 창보다 짧으면 예외를 던진다.**
  학습 라벨이 학습 종료일 + 20까지의 미래를 보므로, 엠바고를 줄이는 것은 설정 실수가 아니라
  누출이다. 잘못된 값이 조용히 통과하지 않게 막았다.

### 기준선과 스키마 (2026-08-22)

- 리비전 `20260822_0025`가 `ml` 스키마와 `model`·`model_evaluation`·`feature_importance`를 만든다.
  `model`에는 `embargo_days >= horizon_days` CHECK를 두어 누출된 설정이 저장 단계에서도 막힌다.
- `ml/ridge.py`는 정규방정식 닫힌 해로 학습하고 계수 JSON으로만 직렬화한다(pickle 금지). 같은
  입력·시드면 같은 산출물이 나오는 것과, JSON 왕복 후 예측이 같은 것을 테스트로 고정했다.
- 표본은 시그널일·종목 순으로 정렬한 뒤 학습한다. 정렬하지 않으면 결과가 입력 순서에 의존한다.
- 정규방정식이 특이하면(상수 특징 등) 추측하지 않고 실패한다.
- `ml/evaluation.py`의 `fold_metrics`는 순위 상관(IC)·상위 K 초과수익·적중률과 **지표를 실제로
  계산한 표본 수**를 돌려준다. 횡단면이 없는 날은 통째로 제외하며, 제외한 날의 표본은 세지 않는다 —
  세면 지표가 더 많은 데이터에 근거한 것처럼 보인다.
- 외부 수치 라이브러리를 추가하지 않았다. 자세한 이유는 [기술 스택](../architecture/tech-stack.md) §6.1에 있다.

### ml-rank 전략 (2026-08-22)

- `ml_rank_strategy`가 ADR-0012의 신원(`ml-rank` / `ml_rank`)과 회차 생성기를 만든다. 엔진·비용·
  체결 모형은 규칙형 전략과 공유하고 회차 생성기만 교체한다.
- 실행 기록의 canonical 파라미터에 알고리즘·특징 버전·학습 창·엠바고를 담아 어떤 모델의 신호인지
  기록에서 읽을 수 있다.
- **창 겹침은 첫 시그널일 하나만 침범해도 실행 전체를 거부한다**(`train_window_overlap`). 겹친
  회차만 건너뛰면 남은 회차의 성과가 표본 밖 성과로 보고되지만 실제로는 학습 정보를 본 모델의
  결과다. 부분 실행보다 거부가 맞다.
- 시그널일에 특징이 없는 종목은 그 회차의 후보가 아니다. 창 전체에 후보가 없으면
  `no_signal_candidate`로 거부한다(v3와 같은 규칙).
- 예측값이 큰 종목이 상위이고, 동점은 종목코드 오름차순으로 끊는다.

### 학습 파이프라인 (2026-08-22)

- `application/ml/training.py`의 `ModelTrainer`가 로드 → 구간 분할 → 구간별 학습·평가 → 저장을
  잇는다. 학습 자체는 순수 함수가 하고 이 층은 조립만 한다.
- **구간마다 그 구간의 학습 표본만으로 다시 학습해 검증한다.** 최종 모델 하나로 모든 구간을
  평가하면 앞 구간 검증이 뒤 구간 데이터를 본 모델로 채점된다.
- 구간 지표는 `rank_ic`·`top_k_excess`·`hit_rate`를 구간별로 저장한다. 평균만 남기지 않는다.
- 학습 표본이 임계 미달이면 학습을 거부하고, 창에 구간이 하나도 안 잡히면 역시 거부한다.
- 특징 중요도는 선형 모델의 계수 절대값이다. 특징이 이미 정규화돼 있어 비교가 성립한다.
- `adapters/database/ml_dataset_reader.py`는 **확정 일봉만** 읽고, 벤치마크 확정 일봉이 있는
  날짜만 거래일로 본다(시장 특징이 같은 날짜를 요구한다). 종목·벤치마크가 모두 있는 날짜만 쓴다.
- 진입점은 `python -m auto_stock_trading.worker.ml --train-ridge`이며 예약하지 않는다.

회전율이 격차의 원인인지 확인하기 위해 보유 종목 수만 바꿔 측정했다(코드·규칙 변경 없음).

  v3·ML 전략의 기본 파라미터는 그대로다.

다음 개선 방향은 회전율 파라미터 조정이 아니라 예측 안정화(교체 임계, 예측 평활, 더 긴 목표 창)이며
모두 규칙 변경이므로 별도 승인이 필요하다.

## 예측 안정화: 교체 임계 (2026-08-22 사용자 승인)

회전율 진단이 예측 불안정성을 원인으로 지목해 교체 임계를 도입했다. 승인 결정은 세 가지다.

1. **방식은 교체 임계(버퍼)다.** 보유 중인 종목은 상위 K를 벗어나도 **상위 2K 안에 있으면 유지**한다.
   신호 자체는 건드리지 않으므로 "예측이 아니라 교체 방식이 문제였는가"를 분리해 판정할 수 있다.
2. **적용 범위는 `ml-rank`만이다.** ADR-0012가 규칙형을 비교 기준으로 보존하라고 하므로 v2·v3는
   그대로 둔다.
3. **버퍼 폭 2K는 사전에 고정하고 1회만 산정한다.** 표본 밖 창에서 여러 폭을 훑어 고르면 그 값은
   더 이상 표본 밖이 아니다.

### 구현

- 엔진의 회차 타입에 `retained`(유지 허용 종목)를 더했다. **매도만 막고 추가 매수는 하지 않는다** —
  목적이 회전율 감소이므로 목표 금액까지 채우지 않는다.
- v2·v3는 `retained`를 비워 보내므로 동작이 완전히 같다. 비교 기준이 보존된다.
- 보유하지 않은 종목이 유지 허용에 있어도 매수하지 않는다(테스트로 고정).

### 실측 (1회 산정)

| | 총수익률 | MDD | 회전율 | 체결 |
|---|---|---|---|---|
| 버퍼 없음 | +53.87% | −28.44% | 1,748% | 560 |
| 버퍼 2K | **+62.38%** | −29.47% | **1,692%** | 550 |
| `composite-rank`(v3) | +190.62% | −45.53% | 405% | 201 |

**개선이 작다. 회전율이 3%만 줄었다.** 버퍼는 "순위가 조금 밀린 종목"을 붙잡는 장치인데, 이 모델의
예측은 조금 밀리는 게 아니라 크게 밀린다 — 상위 10에서 빠진 종목이 상위 20 안에도 남지 않는다.
회전율 3% 감소가 그 증거다.

**결론: 교체 방식을 손대는 것으로는 해결되지 않는다.** 버퍼를 시도한 덕분에 "회전율만 줄이면 된다"는
추측이 배제됐고, 남은 원인은 예측 자체의 불안정성이다. 버퍼 폭을 늘려 재측정하는 것은 표본 밖 창에서
값을 훑는 일이므로 하지 않는다.

다음으로 근본적인 후보는 **목표 창 확대(20 → 60거래일)**다. 20거래일 초과수익 순위 자체의 노이즈가
크면 어떤 모델도 안정된 순위를 내지 못한다. 목표 정의 변경이므로 별도 승인이 필요하다.

- **v1의 문제는 표본이었다.** 5개년 수집 범위(FY2021~2025)로는 2020년 학습 시점에 접수된 사업보고서가
  없어 학습 초반 표본이 통째로 사라졌다. 유니버스가 117종목까지 줄고 구간 IC가 0.0053으로 거의
  0이었다. 계약의 결측 제외 규칙이 옳게 동작한 결과이며, 필요한 것은 규칙 완화가 아니라 과거 수집이었다.
- **v2는 FY2016까지 소급 수집한 뒤다.** 표본이 2.7배로 늘고 구간 지표가 4배 개선됐지만 백테스트는
  +72.86%로 거의 그대로였다.
- **v3는 IFRS 접두 결함을 고친 뒤다.** 표본은 4%만 늘었는데 백테스트가 **+72.86% → +119.49%**로
  뛰었다. 표본 수가 아니라 **학습 초반 구간(2020~2021)에 재무가 채워진 것**이 결정적이었다. 그
  구간의 최신 사업보고서는 FY2018 이하이고 우리는 그 접두를 읽지 못했다.
- **이것이 8단계에서 처음으로 방향이 맞은 개선이다.** 재무 특징을 더한 모델이 처음으로 가격 특징만
  쓴 모델을 넘었고(+119.49% 대 +79.72%), MDD와 회전율도 ML 중 가장 낮다.

### 구간 지표와 백테스트가 어긋난 기록

`lgbm-fund` v3의 구간 지표는 여전히 `lgbm-oos`보다 **낮다**(IC 0.0297 대 0.0446, 상위 K 초과수익
+0.0129 대 +0.0151). 그런데 백테스트는 v3가 40%p 높다. 이전 절들에서는 두 신호가 같은 방향을
가리켰는데 여기서는 어긋난다.

**해석을 단정하지 않고 기록한다.** 두 모델은 유니버스가 다르므로(130 대 192) 횡단면 자체가 달라
구간 지표를 직접 비교할 수 없다. 후보가 적은 쪽이 IC를 올리기 어렵다는 것과, 남은 후보가 재무를
공시하는 큰 기업으로 치우친다는 것이 동시에 성립한다. 계약 §평가 지표가 정한 대로 **최종 판정은
백테스트로** 하되, 구간 지표를 근거로 v3가 더 나은 예측기라고 주장하지 않는다.

### 규칙형 기준선 재실행 확인

접두 수정은 화면 지표와 v3 규칙형 전략이 공유하는 계산 경로를 바꾼다. 비교 기준이 함께 움직였는지
확인하기 위해 `composite-rank`를 같은 창으로 다시 실행했다.

| | 총수익률 | MDD | 회전율 | 체결 | `input_report_version_hash` |
|---|---|---|---|---|---|
| 수정 전 (2026-08-22) | 208.06% | −46.51% | 369.95% | 174 | `1d866eaf23c52436…` |
| 수정 후 (2026-08-23) | 208.06% | −46.51% | 369.95% | 174 | `1d866eaf23c52436…` |

**완전히 같다.** 원인을 측정으로 확인했다: 구 접두 `ifrs_`는 **FY2018 이하 보고서에만** 있고
(FY2016~2018 라인 60,844건, FY2019 이후 0건) 백테스트 창이 2023-09에 시작하므로 시점 정합 선택이
보는 가장 오래된 사업보고서는 FY2022다. 규칙형 기준선은 창이 짧아 결함을 우연히 피해 있었다.
따라서 위 비교 표의 `composite-rank` 값은 수정 전후로 같고 ML 비교는 공정하다.

## 재무 커버리지 개선 후 재측정 (2026-08-23)

[재무 지표 계약](financial-indicator-contract.md) §표준계정 결측 시 복원 규칙이 승인·구현되면서
FY2019~2022 ROE 계산 가능 비율이 81.6% → 91.4%가 됐다. 재무 특징과 v3 규칙형이 같은 함수를 쓰므로
둘 다 같은 창에서 다시 측정했다.

| 전략/모델 | 개선 전 | 개선 후 | 표본 | 유니버스 |
|---|---|---|---|---|
| `composite-rank`(v3) | +208.06% (MDD −46.51%) | **+253.99% (MDD −37.46%)** | — | 200 |
| `ml-rank`(`lgbm-fund`) | +119.49% (v3 모델, MDD −25.95%) | **+90.48%** (v4 모델, MDD −25.84%) | 87,933 → 95,418 | 130 → 138 |
| 벤치마크(KODEX 200) | +240.14% | +240.14% | — | — |

**같은 입력 개선이 두 전략을 반대 방향으로 움직였다.** 규칙형은 +46%p 올라 처음으로 벤치마크를
넘었고, ML은 −29%p 내려갔다. 회전율도 갈렸다(규칙형 370% → 408%, ML 1,186% → 1,320%).

구간 지표도 한 방향이 아니다: IC는 0.0297 → 0.0341로 올랐지만 상위 K 초과수익은 +0.0129 →
+0.0106, 적중률은 0.6167 → 0.5773으로 떨어졌다.

해석을 단정하지 않고 기록한다. 확실한 것은 세 가지다.

1. **v3 모델의 +119.49%는 결함이 있는 입력에서 나온 값이었다.** 그 수치를 개선의 근거로 계속
   인용하면 안 된다. 오늘 데이터에서 재무 특징 모델의 값은 +90.48%다.
2. **그래도 가격 특징만 쓴 모델은 여전히 넘는다**(+90.48% 대 `lgbm-oos` +79.72%). `lgbm-oos`는
   재무를 쓰지 않아 이번 개선에 영향받지 않으므로 이 비교는 유효하다. 즉 "재무 특징이 도움이
   된다"는 결론은 살아남았고, "얼마나"가 절반으로 줄었다.
3. **규칙형과의 격차는 오히려 벌어졌다**(119%p → 164%p). 8단계 완료 기준은 계속 미달이다.

같은 정보를 규칙형은 활용하고 ML은 못 하는 상태다. 유니버스가 130 → 138로 늘며 학습 횡단면이
바뀐 것, 그리고 늘어난 종목이 과거 표기가 불규칙한 기업이라 특징 분포가 이동한 것이 후보 설명이지만
측정하지 않았으므로 주장하지 않는다.

## 한계 (기록)

- **생존 편향.** 유니버스는 현재 KOSPI 200 구성 종목이다. 과거 시점의 실제 구성이 아니며 편출·
  상장폐지 종목이 없다. 2020년으로 확장하면 이 편향이 커진다. 시점별 구성 이력 원천을 확보하기
  전까지 성과는 낙관적으로 치우친 값으로 읽어야 한다.
- **비수정 종가 기반.** 유니버스 전체의 총수익 수정주가 데이터셋이 없어 배당·분할이 수익률을
  왜곡한다(v2·v3와 같은 한계).
- **수급 특징 없음.** 투자자별 매매는 현재 2종목만 보유하고 KIS가 최근 30거래일만 제공한다.
  유니버스 수집이 축적된 뒤 특징으로 추가하고 버전을 올린다.
- **재무 특징의 유니버스 축소.** `features-2`는 결측을 채우지 않으므로 학습 유니버스가 200 → 130
  종목으로 줄고 초기 구간이 얇다. 가격만 쓰는 `features-1`(192종목)과 구간 지표를 직접 비교할 수
  없다. 신규 상장·재무 미공시 종목은 이 특징 집합의 대상이 아니다.
- **재무 특징은 연 1회 갱신이다.** 시그널일이 접수일 사이에 있으면 같은 값이 최대 1년간 반복된다.
  일간 변동은 종가를 통해서만 들어온다(`earnings_yield`). 분·반기 보고서를 쓰면 연환산 추정이
  필요해 [재무 지표 계약](financial-indicator-contract.md) §원칙 4를 어기므로 쓰지 않는다.
- 분봉·시장 변동성 지수는 이력이 없어 제외한다.

## 검증 시나리오

1. 특징 계산이 접두 시계열 재계산으로 같은 값을 내고, `T` 이후 행을 참조하면 실패한다.
2. 엠바고 0과 목표 창 길이(20)의 검증 지표를 같은 표본으로 비교해 **효과 크기를 측정하고 기록한다.** 방향과 크기를 미리 단정하지 않는다(2026-08-22 실측에서 예상과 반대 방향이 나왔다).
3. 같은 입력·시드로 두 번 학습해 모델 산출물과 평가 결과가 같다.
4. 학습 창과 겹치는 창으로 `ml-rank` 백테스트를 실행하면 `train_window_overlap`으로 거부된다.
5. 모델이 없으면 `ml-rank`가 거부되고 `composite-rank`·`cross-momentum`은 정상 실행된다.
6. 워크포워드 구간별 IC와 상위 K 초과수익을 저장하고, 한 구간 집중 여부를 확인한다.
7. 같은 창에서 `ml-rank`와 `composite-rank`를 실행해 비용 후 성과를 비교한다.
8. 재무 특징이 접수일 이후에만 쓰이고(접수일 당일은 아직 아님), 값이 하나라도 없으면 그 종목-일
   표본이 만들어지지 않는다.
9. 추론 경로가 **모델에 저장된 특징 집합**을 따라간다. `features-1` 모델과 `features-2` 모델을
   같은 코드로 실행해 열 개수가 어긋나지 않는지 확인한다.
