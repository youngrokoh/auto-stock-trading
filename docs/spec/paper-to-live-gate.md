# 모의투자·실전투자 전환 게이트

- 상태: 승인
- 승인일: 2026-08-11
- 기본 상태: 실전투자 비활성
- 관련 정책: [거래 안전 정책](trading-safety-policy.md), [시장 데이터 및 시점 정책](market-data-policy.md)

## 1. 원칙

실전투자는 기능 구현 완료만으로 활성화되지 않는다. 전략별 검증, 모의운영, 운영 안전성과 사용자의 명시적 승인이 모두 있어야 한다.

- 게이트 통과는 수익을 보장하지 않는다.
- 전략, 데이터, 특징, 비용 또는 주문 로직의 주요 버전이 바뀌면 승인이 만료된다.
- AI 신호는 최초 실전 단계에서 그림자 모드로만 기록하며 주문 수량에 반영하지 않는다.
- 승인 기록이나 실전 자본 한도가 없으면 실전 자격증명이 존재해도 주문을 차단한다.

## 2. 단계

```text
백테스트 후보
→ 표본 밖 검증 통과
→ 모의투자 승인
→ 모의운영 게이트 통과
→ 사용자 실전 승인
→ 제한적 실전
→ 관찰 후 한도 재승인
```

## 3. 백테스트 게이트

전략 버전마다 다음 조건을 모두 충족해야 한다.

### 데이터와 재현성

- 최소 3년 또는 750거래일 중 더 긴 범위가 존재한다.
- 상승·하락·고변동 구간을 포함한다.
- 데이터, 특징, 전략, 비용 프로필과 코드 버전이 고정돼 있다.
- 같은 입력으로 주문 목록과 성과가 동일하게 재현된다.
- 미래정보 누출, 생존편향, 수정주가와 거래정지 검사가 통과한다.
- 현재 유효 세금과 보수적 수수료·슬리피지 가정을 포함한다.

### 표본 밖 성과

- 시간 순서 기반 워크포워드 검증을 3개 이상 구간에서 수행한다.
- 표본 밖 거래비용 후 샤프지수가 0.7 이상이다.
- 표본 밖 최대 낙폭이 15% 이하이고 사전에 정한 전략 한도 이하다.
- 3개 이상의 평가 구간 중 2개 이상에서 거래비용 후 수익이 양수다.
- 벤치마크 초과수익이 전략 목표라면 표본 밖 초과수익이 양수다.
- 단일 종목 또는 단일 시기의 수익 기여도가 전체 수익의 50%를 넘지 않는다.

성과 기준을 사후에 낮춰 통과시킬 수 없다. 기준 변경은 새로운 전략 평가 버전과 승인 사유를 요구한다.

## 4. 모의운영 게이트

다음 조건을 모두 만족하는 기간까지 모의투자를 계속한다.

- 60거래일 이상 운영한다.
- 10회 이상의 예정 리밸런싱 주기를 완료한다.
- 20건 이상의 체결 주문을 관찰한다.
- 중복 주문이 0건이다.
- 내부 주문·체결·잔고와 증권사 상태의 미조정 건이 0건이다.
- 계획 대비 실제 모의 체결 차이와 슬리피지를 보고서로 확인한다.
- 최근 20거래일 동안 심각도 높은 주문·데이터 장애가 0건이다.
- 예정 실행시간 기준 서비스 가용성이 99% 이상이다.
- 비상정지, 부분체결, 주문 거절, 인증 만료, 서버 재시작과 데이터 지연 시나리오가 통과한다.

기간, 리밸런싱 횟수와 주문 수 중 하나라도 부족하면 나머지 조건이 좋아도 실전으로 전환하지 않는다.

## 5. 승인 자료

실전 전환 요청에는 다음 내용을 하나의 변경 불가능한 승인 기록으로 저장한다.

- 전략과 파라미터 버전
- 코드 커밋과 데이터셋·특징·비용 프로필 버전
- 백테스트와 모의운영 기간 및 평가 결과
- 허용 계좌와 거래 환경
- 허용 종목군과 주문 유형
- 실전 자본 한도 `live_cap_krw`
- 종목·총투자·주문·일일 손실 한도
- 승인자, 승인시각, 만료 조건과 사유

`live_cap_krw`는 기본값을 제공하지 않는다. 사용자가 원화 금액을 명시하지 않으면 실전 주문을 활성화할 수 없다.

## 6. 최초 실전 한도

최초 승인 시 다음 한도보다 완화할 수 없다.

| 항목 | 최초 실전 상한 |
|---|---:|
| 실전 자본 | 사용자 지정 `live_cap_krw`와 계좌 NAV의 10% 중 작은 값 |
| 총 투자 비중 | 승인된 실전 자본의 20% |
| 종목별 비중 | 승인된 실전 자본의 2% |
| 주문 1건 | 승인된 실전 자본의 1% |
| 하루 주문 시도 | 5건 |
| 일일 손실 | 승인된 실전 자본의 -0.5% |
| 동시 실행 전략 | 1개 |

- 국내 현금 주식·ETF의 지정가 주문만 허용한다.
- 레버리지·인버스 ETF, 신용, 미수, 공매도와 시간외 주문을 금지한다.
- 서버 재시작과 거래일 변경 시 실전 활성 상태를 해제한다.
- 사용자는 거래일마다 계좌, 전략, 한도와 장 상태를 확인해 다시 활성화한다.

## 7. 관찰과 확대

최초 실전 한도는 최소 20거래일 동안 유지한다. 이 기간에 다음 조건을 모두 충족해야만 한도 변경을 검토할 수 있다.

- 중복 주문과 상태 불일치가 없다.
- 실제 수수료·세금·슬리피지가 승인 비용 프로필과 허용 오차 안에 있다.
- 위험 한도 위반 주문이 모두 사전에 차단됐다.
- 모의투자 대비 성과 차이를 설명할 수 있다.
- 비상정지와 수동 주문 취소가 정상 동작한다.

한도 확대는 자동으로 수행하지 않는다. 새 한도, 근거와 만료 조건을 사람이 다시 승인해야 한다.

## 8. 즉시 중단과 모의투자 복귀

다음 사건 중 하나라도 발생하면 신규 실전 주문을 즉시 차단하고 모의투자로 복귀한다.

- 중복 또는 승인되지 않은 주문 발생
- 주문·체결·잔고 조정 실패
- 일일 손실 또는 노출 한도 도달
- 오래된 데이터로 주문 시도
- 모의·실전 자격증명 또는 계좌 혼용
- 감사 로그 누락
- 비상정지 실패
- 승인되지 않은 전략·코드·데이터 버전 감지

기존 미체결 주문은 취소를 시도하되 보유 포지션은 자동 시장가 청산하지 않는다. 사고 원인, 영향과 복구 검증을 기록하고 새 승인을 받기 전까지 실전을 다시 활성화하지 않는다.

## 9. 완료 조건

- 게이트 각 조건을 기계가 판정할 수 있는 필드와 테스트로 표현한다.
- 승인되지 않은 환경·계좌·전략·버전·자본 한도의 실전 주문이 차단된다.
- 승인 만료와 모의투자 복귀가 감사 로그에 남는다.
- 실제 주문 활성화에는 사용자 이중 확인이 필요하다.
