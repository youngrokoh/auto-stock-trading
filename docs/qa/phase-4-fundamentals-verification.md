## 실측으로 정정된 계약 항목 (사용자 승인)

- 자본변동표(SCE)는 같은 원문 순서(`ord`)를 자본 구성요소별 여러 행이 공유한다(예: 2021 사업보고서 `기말자본` ord=13 반복). 라인 유일키를 응답 순번 `(report_id, line_seq)`로 정정했다.
- `account_id` 실측 최대 길이 180자 — 컬럼 폭을 `VARCHAR(255)`로 정정했다.

## 기업 분석 화면 검증 (2026-08-17)

승인 디자인 2b(A 지표 KPI 7 / B 실적 차트·재무제표 / C 지표·가치 / D 수급·공시)를 승인
토큰·프리미티브로 구현하고 실제 브라우저로 확인했다.

- e2e 12건(운영 개요·시장 데이터·기업 분석·갤러리 × 모바일 390·태블릿 768·데스크톱 1360)
  통과: 콘솔 오류 0, 가로 넘침 없음, 연결 URL 미노출, 손익계산서 탭 전환, 개별 전환 시
  ROE "지배주주 계정 없음" 표시.
- 세 폭과 다크 모드 전체 페이지 스크린샷을 육안 확인: 태블릿 접기 규칙(레일 유지·내비
  숨김·1열·KPI 3열) 유지, 7번째 KPI는 태블릿·모바일에서 전체 폭으로 접힘, 재무제표 구분
  탭 줄바꿈 정상, 다크 토큰 일치.
- 백엔드가 없는 가치 지표·수급·공시 연결은 값 생성 없이 사유를 적은 빈 상태 카드다.
- 재무제표 카드의 금액은 DART 원문 라인 그대로이며(자산총계 566,942,110,000,000 표시
  확인) KPI의 조 단위 축약은 표시 전용이다.

### 이 검증이 드러낸 지표 한계와 해소 (2026-08-21)

유니버스 수집 직후에는 [재무 지표 정의 계약](../data/financial-indicator-contract.md)이 손익 입력을
`sj_div = IS`로 고정하고 있었다. 2025 연결 사업보고서 198건 중 `IS`를 별도 제출한 곳은 51건뿐이라
나머지 147종목의 성장성·수익성 지표가 전부 `MISSING_ACCOUNT`였다(SK하이닉스 실측). 사용자가 같은 날
`IS` → `CIS` 우선순위 조회를 승인해 계약을 개정하고 구현했다.

| 항목 | 값 |
|---|---|
| 2025 영업이익률 계산 가능 종목 | 개정 전 51 / 200 → 개정 후 **178 / 200** (사용 구분 `IS` 51, `CIS` 127) |
| 기존 검증값 불변 | 삼성전자는 `IS`를 제출하므로 매출액증가율 10.88 / 영업이익률 13.07 / 부채비율 29.94가 그대로다(우선순위 규칙 1의 목적) |
| SK하이닉스 수동 대조 | 매출액증가율 (97,146,675−66,192,960)÷66,192,960×100 = 46.76 / 영업이익증가율 (47,206,319−23,467,319)÷23,467,319×100 = 101.16 / 영업이익률 47,206,319÷97,146,675×100 = 48.59 / ROE 42,919,287÷((기초+기말 지배지분)÷2)×100 = 44.15 — API 응답과 일치 |
| 외부 대조 | 위 전기 금액 66.19조·23.47조가 SK하이닉스 2024 공개 실적과 일치해 `CIS` 행을 옳게 읽었음을 확인 |
| 사용 구분 노출 | 응답의 `figures`·`inputs`가 실제로 읽은 구분(`CIS`)을 담아 어느 재무제표에서 왔는지 감추지 않는다 |
| 남은 20종목 | 전부 금융업(보험·증권·은행·지주·카드)이다. `ifrs-full_Revenue`·`dart_OperatingIncomeLoss`를 쓰지 않고 영업수익·순이자수익 등으로 태깅하므로 계정 매핑을 새로 정의해야 한다(별도 결정). 2025 사업보고서가 없는 신규 상장 2종목을 합쳐 계산 불가 22종목 |

안정성 지표(부채비율·유동비율)는 `BS` 기준이라 개정 전후 동일하다.

| 2 | 215,462,914,687 | −2,359,239,549 | 213,103,675,138 | 불일치 |
| 2 | 215,462,914,687 | −2,247,393,764 | 213,215,520,923 | 불일치 |

표준계정 `ifrs-full_ProfitLoss`(당기순이익) 190,401,937,316과 정확히 맞는 조합이 하나뿐이라
192,761,176,865가 채택됐다. 나머지 후보 215,462,914,687은 총포괄손익 지배주주분이다 —
**이름으로 골랐다면 절반의 확률로 총포괄손익을 순이익으로 썼을 것이다.**

**자본 차감:** 자본총계 1,846,502,193,853 − 비지배지분 6,391,720,944 = 1,840,110,472,909(기말),
1,649,991,371,524 − 3,728,265,944 = 1,646,263,105,580(기초). 둘 다 표준계정이므로 이름을 쓰지 않았다.

**독립 대조 두 가지가 모두 맞았다.**

1. 손계산 ROE = 192,761,176,865 ÷ ((1,646,263,105,580 + 1,840,110,472,909) ÷ 2) × 100 =
   **11.06%** — API 응답값과 일치.
2. 같은 보고서의 자본변동표(SCE)가 기말자본을 지배주주지분 1,840,110,472,909 / 비지배지분
   6,391,720,944로 직접 보고한다. 우리가 차감으로 복원한 값이 **발행사 자신의 표기와 같다.**
   (SCE는 같은 계정 ID를 자본 구성요소별 여러 행이 공유해 지표 입력으로 쓰지 않지만, 대조에는
   쓸 수 있다.)

응답의 `resolution`이 두 값을 각각 `identity_verified`·`standard_difference`로 표시하고,
기업 분석 화면은 해당 셀에 `†`를 붙인다. 삼성전자는 전 연도 `standard_account`이므로 표시가 없다.

## 우선주 반영 검증 (2026-08-23)

승인된 우선주 설계 4건을 실데이터로 확인했다.

**주식종류 사실.** `--collect-share-classes`로 KIS 마스터에서 `groups=804 new_versions=914
refused=0`을 적재했다. 짝짓기 예외가 0인 것이 사전 측정(접두 공유 군 95개 전부에서 보통주 1개,
고아 우선주 0개)과 일치한다. 유니버스 200종목 중 39개 회사가 우선주 46종목을 가진다.

**우선주 시세.** `--collect-preferred-quotes`로 46종목 전부 수집했다(`collected=46 failed=0`).
영문자가 섞인 단축코드(`00088K`)도 정상이다.

**시가총액.** 삼성전자 실측:

| 클래스 | 가격 | 주식수 | 시가총액 |
|---|---|---|---|
| 005930 보통주 | 281,500 | 5,846,278,608 | 1,645,727,428,152,000 |
| 005935 우선주 | 207,000 | 802,371,203 | 166,090,839,021,000 |
| **합계** | — | — | **1,811,818,267,173,000** |

이전에는 보통주분만 시가총액으로 표시했으므로 **실제의 90.8%**였다. API 응답의
`market_cap_total`이 손계산과 정확히 일치한다.

**BPS·PBR.** 우선주가 없는 SK하이닉스(`000660`)는 계산되고 저장 사실로 대조했다:
FY2025 지배주주지분 120,516,178,000,000 ÷ 보통주 730,492,365주 = **164,979.38원**(API와 일치),
PBR 10.49. 우선주가 있는 삼성전자·한화는 `PREFERRED_ALLOCATION_REQUIRED`로 빈 값이다.

**비유동 우선주.** 한화3우B(`00088K`)는 거래량 0으로 전일 종가만 돌아온다. 클래스별 기준시각이
응답에 그대로 드러난다. 같은 회사의 보통주(`000880`)는 2026-08-21 배치 시세라 **합계가 서로 다른
기준시각을 섞는다** — 그래서 클래스별 `as_of` 노출이 필수다(합계 하나만 보여주면 알 수 없다).

### 구현 중 발견한 결함 (수정)

**종목 행을 KOSPI 전 종목에 만들었다.** 주식종류 사실은 전 종목(914)에 저장하는 것이 맞지만
`reference.instrument` 행까지 만들어 종목 목록이 201 → **915**가 됐고, 그중 668개는 참조가 하나도
없는 빈 종목이었다. 종목 행은 **시세를 수집하는 대상만** 만들도록 고쳤고(우선주 스윕이 대상별로
생성), 참조 0·프로필 없음·2시간 내 생성 조건으로 668개를 삭제해 247개(유니버스 200 + ETF 1 +
우선주 46)로 복구했다.

**조회 저장소가 즉시 연결 풀을 열었다.** `create_app`의 기본 factory가 주식종류 저장소를 만들 때
엔진을 바로 생성해 **앱 하나당 연결 풀 하나**가 늘었다. API 테스트는 앱을 12곳에서 만들고 그중
5곳만 lifespan을 돌려 엔진을 닫는다. 전체 스위트에서 통합 테스트 하나가 `DBAPIError`로 깨졌고
(실측 `max_connections=100`, 실행 중 62개 사용), 엔진을 **첫 사용까지 만들지 않도록** 고친 뒤
전체 스위트가 통과했다.

원인 판단은 **정합하는 증거**로 기록한다(증명이 아니다). 실패-통과 사이의 유일한 변경이 이 수정
하나이고, 첫 실패 실행은 **다른 테스트**(거래 통보 저장)에서 깨졌다 — 특정 외래키 문제라면 같은
곳이 깨진다. 무작위 피해자는 자원 압박의 특징이다. 좁은 조합(`tests/api` + 해당 파일,
`tests/market_data` 전체)으로는 재현되지 않았고 각 방향 관측이 1회씩이다.

교훈: 쓰지 않는 조회 저장소가 연결 풀을 여는 것은 원인 규명과 별개로 잘못이다. **테스트를 맞추는
대신 구현을 고쳤다.**

**남은 부수 효과(결정 필요):** 우선주 46종목이 종목 목록에 들어오면서 운영 개요의 '종목코드
오름차순 상위 10개' 미리보기 중 5개가 우선주가 됐다. 사실로는 맞지만(수집 대상이다) 전략·주문
대상이 아닌 종목이 미리보기 절반을 차지한다. 승인 범위 밖이라 화면은 바꾸지 않았고 e2e 단언만
숫자·종목명 고정에서 형태 확인으로 바꿨다. 미리보기를 보통주로 한정할지는 별도 결정이다.

## 남은 범위

- BPS·PBR — 우선주(종목·주식수·자본 배분) 반영 설계 확정 후
- 금융업의 매출액·영업이익 기반 지표는 업종 사유로 미제공한다(2026-08-21 승인). 업종별 top-line 매핑은 회계 판단이 필요해 만들지 않는다
- **기본주당이익은 우선주 미상장 회사만 복원한다**(2026-08-23 승인). 우선주가 상장된 회사는 복원하지 않으며, 상장 이력의 시점 정합은 오늘의 마스터 파일로만 판정하는 한계가 있다.
- (이전 기록) 복원 규칙 도입 시점의 결정: 기본주당이익은 복원하지 않는다 — 검증 항등식이 없어 계정명으로 읽으면 우선주 EPS를 집을 위험이 있다. 따라서 FY2019~2022 'ROE·EPS 둘 다 계산' 비율의 상한은 EPS 커버리지(82.7%)이며, ROE를 더 올려도 그 상한에 막힌다
