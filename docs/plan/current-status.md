## 다음 세션 시작 규칙

다음 세션은 이 문서를 먼저 읽고 현재 Git 상태와 원격 `main`을 확인한다. 완료된 기반 작업을 다시 만들지 않고 아래의 미승인 상태와 다음 작업부터 이어간다.

- 0단계 제품 범위, 거래 안전, 시장 데이터 시점과 실전 전환 정책 승인

- GitHub `main` 저장소 연결과 최초 게시

## 반드시 기억할 디자인 상태

현재 웹 화면은 기능과 실행 환경을 검증하기 위해 구현한 프로토타입이다.

- 사용자는 현재 화면 디자인을 승인한 적이 없다.
- 디자인 문서, 화면 캡처, 시각 QA의 `PASS` 또는 `APPROVE`는 구현 품질 판정일 뿐 사용자 컨펌이 아니다.
- 현재 색상, 레이아웃과 컴포넌트를 최종 디자인으로 소개하거나 이를 전제로 새 화면을 확장하지 않는다.
- 사용자가 디자인 방향을 명시적으로 선택하기 전까지 [디자인 시스템](../design/design-system.md)은 `초안 · 사용자 미승인` 상태를 유지한다.
- 백엔드와 인프라 기반은 승인 여부와 무관하게 계속 사용할 수 있다.

## 다음 작업 1: 디자인 방향 승인

다음 세션의 첫 작업으로 권장한다. 구현 코드를 먼저 바꾸지 않고 아래 순서로 진행한다.

1. 자동매매 서비스가 주로 제공할 화면과 정보 밀도를 기준으로 디자인 요구사항을 짧게 확인한다.
2. 서로 분명히 다른 디자인 방향 2~3개를 동일한 대시보드 콘텐츠로 제안한다.
3. 데스크톱과 모바일 핵심 화면을 함께 제시하고 색상, 정보 구조, 밀도와 상호작용 차이를 설명한다.
4. 사용자가 한 방향 또는 조합을 명시적으로 선택한다.
5. 선택 내용을 디자인 토큰과 컴포넌트 규칙에 반영하고 디자인 문서 상태를 `승인`으로 변경한다.
6. 승인된 방향으로 기존 프로토타입을 수정하고 실제 브라우저 QA를 다시 수행한다.

디자인 승인 전에는 3단계 시장 대시보드와 이후 기업·ETF·전략 화면의 본격적인 UI 확장을 시작하지 않는다.

## 다음 작업 2: 2단계 KIS 시장 데이터 수직 슬라이스

디자인 승인과 독립적으로 진행할 수 있는 다음 기술 작업이다.

1. 한국투자증권 모의투자 API 사용 가능 여부와 로컬 자격증명 보관 방법을 확인한다.
2. 접근 토큰 발급·만료·갱신과 호출 제한을 처리하는 최소 KIS 어댑터를 구현한다.
3. 원본 응답과 정규화 데이터를 분리할 PostgreSQL 스키마를 마이그레이션한다.
4. 삼성전자와 대표 국내 ETF 한 종목씩 종목정보·현재가·일봉을 수집한다.
5. 같은 구간을 반복 수집해도 중복되지 않도록 멱등성을 검증한다.
6. 출처와 기준시각을 포함한 읽기 전용 API를 제공한다.
7. 모의 API 또는 계약 fixture로 자동 테스트한 뒤 실제 KIS 모의투자 환경에서 수동 검증한다.

자격증명은 문서, Git, 브라우저 번들과 로그에 기록하지 않는다. 실전 주문 기능은 이 단계에 포함하지 않는다.

## 권장 진행 순서

```text
디자인 방향 제안·사용자 승인
    ↓
2단계 KIS 인증·시장 데이터 수직 슬라이스
    ↓
정확성과 중복 방지 통합 검증
    ↓
승인된 디자인으로 3단계 시장 대시보드 구현
```

## 다음 세션 완료 조건

디자인 작업 세션이라면 사용자가 선택한 방향과 승인 범위가 문서에 남아야 한다. 기술 구현 세션이라면 실제 KIS 모의환경에서 대표 주식·ETF의 데이터가 수집되고, 반복 실행과 기준시각 검증이 통과해야 한다.
