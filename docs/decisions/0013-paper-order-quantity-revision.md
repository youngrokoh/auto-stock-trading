# ADR-0013: 미체결 수량 축소 경계 (부분 취소)

- 상태: 제안
- 작성일: 2026-08-24
- 승인: **없음.** 이 문서는 결정이 아니라 결정을 받기 위한 초안이다. 승인 전에는 구현하지 않는다
- 관련 결정: [ADR-0011 모의투자 주문 정정 경계](0011-paper-order-revision.md), [ADR-0008 모의투자 주문 제출·체결 동기화 경계](0008-paper-order-submission.md), [ADR-0007 모의투자 주문 계획과 위험검사 경계](0007-paper-order-planning-and-risk.md)
- 관련 정책: [거래 안전 정책](../spec/trading-safety-policy.md), [모의투자·실전투자 전환 게이트](../spec/paper-to-live-gate.md)
- 관련 계약: [주문 제출·체결 동기화 계약](../data/order-submission-contract.md), [주문 계획·위험검사 데이터 계약](../data/order-planning-risk-contract.md)

## 배경

로드맵과 인계 문서는 남은 7단계 항목을 "**수량 정정**"이라고 적어 왔다. 이 초안을 쓰면서 원천
문서를 확인한 결과 **그 이름이 틀렸다.** 증권사 API에 수량을 바꾸는 정정은 없다.

### 원천 확인 (2026-08-24, 공식 KIS 저장소 API 문서)

`examples_llm/domestic_stock/order_rvsecncl/order_rvsecncl.py`의 API 설명 세 문장이 설계를 규정한다.

1. **"정정은 원주문에 대한 주문단가 혹은 주문구분을 변경하는 사항으로, 정정이 가능한 수량은
   원주문수량을 초과 할 수 없습니다"**
   → 정정이 바꾸는 것은 **단가 또는 주문구분**이다. 수량은 정정의 대상이 아니라 "원주문 중 얼마를
   정정할지"를 가리키는 범위다. 그리고 원주문수량을 넘을 수 없으므로 **수량 증가는 API에 존재하지
   않는다.**
2. **`qty_all_ord_yn`은 "잔량전부주문여부(Y:전량, N:일부)"** 다.
   → `N`은 "잔량 중 일부에 대해" 정정·취소한다는 뜻이다.
3. **"주식주문(정정취소) 호출 전에 반드시 주식정정취소가능주문조회 호출을 통해 정정취소가능수량
   (output > psbl_qty)을 확인하신 후 정정취소주문 내시기 바랍니다"**
   → 공식 절차가 요구하는 사전 조회가 **모의환경 미지원**이다(ADR-0008 실측: `VTTC8036R`,
   `rt_cd=1`, `msg_cd=90000000`). 모의에서는 증권사가 인정하는 정정취소가능수량을 **알 수 없다.**

### 따라서 실제 필요한 동작은 두 개다

| 원하는 결과 | API 동작 | 지금 구현 |
|---|---|---|
| 미체결 노출을 줄이고 나머지는 그대로 둔다 | **취소** `RVSE_CNCL_DVSN_CD=02` + `QTY_ALL_ORD_YN=N` + 취소수량 | 없음 — `QTY_ALL_ORD_YN="Y"` 고정 |
| 미체결 일부만 다른 가격으로 바꾼다 | **정정** `01` + `N` + 정정수량 | 없음 — `QTY_ALL_ORD_YN="Y"` 고정 |

두 경로 모두 `QTY_ALL_ORD_YN`이 `"Y"`로 하드코딩돼 있어 막혀 있다(`kis_orders.py`). ADR-0011이
"수량은 건드리지 않는다"고 한 것은 결과적으로 맞았지만, 이유가 "목표 포지션 재계산 규칙이 필요하다"가
아니라 **정정은 애초에 수량을 바꾸지 않는다**였다.

### 이 초안이 다루는 범위

**부분 취소만** 다룬다. 노출을 줄이는 것이 로드맵 항목의 실제 의도이고, 부분 정정(일부만 가격 변경)은
주문 하나를 두 가격으로 쪼개 내부 모델과 증권사 사실을 어긋나게 하므로 별도 결정으로 남긴다.

## 실측 (2026-08-24 장중, 사용자 승인)

모의계좌에서 미체결 주문을 만들어 확인했다. 상세는
[7단계 QA](../qa/phase-7-order-planning-verification.md) §부분 취소 실측에 있다.

**모의환경은 부분 취소를 지원한다.**

| 시험 | 결과 |
|---|---|
| 존재하지 않는 주문번호로 `Y`/`N` 탐침 | 둘 다 `40320000`(원주문 없음) — **파라미터 미지원이 아니다** |
| 카카오 14주 중 5주 취소 | `rt_cd=0`, 잔여 **9주** 확인 |
| 한온시스템 146주 중 100주 → 이어서 30주 | 둘 다 성공, 각각 새 주문번호 |
| 잔여 초과(17주) 시도 | **거절** `40430000` "취소수량이 취소가능수량을 초과합니다" |
| 잔여 정확(16주) 시도 | 성공 — 146 − 100 − 30 = 16 |

확정된 사실:

1. `QTY_ALL_ORD_YN="N"` + 명시 `ORD_QTY`가 동작한다. `ORD_QTY`는 **취소할 수량**이며 나머지는 열린
   채로 남는다.
2. 연속 부분 취소가 누적되고 잔여가 정확히 추적된다.
3. **초과 취소는 증권사가 막는다**(`40430000`). 우리가 잔여를 잘못 알아도 없는 수량이 취소되지 않는다.
   공식 절차가 요구하는 사전 조회(정정취소가능주문조회)가 모의 미지원이지만, 이 fail-closed가 그
   공백을 메운다.
4. 각 부분 취소는 **자체 주문번호를 새로 받고** 원주문번호로 대상을 가리킨다(정정과 같은 규칙).
   **원주문번호는 살아 있어** 다음 취소의 대상이 된다.

### 호가 우선순위 — 추론이며 관측이 아니다

원문 규정을 찾지 못했고 호가 우선순위를 관측하는 API도 없다. 다만 실측이 강한 근거를 준다: 부분 취소
후에도 **원주문번호가 그대로 취소 대상으로 남았고** 잔여 수량은 재진입되지 않았다. 즉 잔여는 새 주문이
아니라 **원주문 그대로**다. 새로 넣은 것이 없으므로 우선순위가 초기화될 이유가 없다.

이것은 합리적 추론이지만 호가창을 직접 본 것이 아니다. 규정 원문이 확보되면 교체한다.

## 아직 확인되지 않은 것

1. 부분체결된 주문에 부분 취소를 보낼 때의 기준(원주문수량인지 잔량인지). 부분체결을 의도적으로
   만들기 어려워 측정하지 못했다. 위 실측 3(초과 취소 거절)이 안전망이 되므로 구현을 막지는 않는다.

## 제안하는 결정

### 1. 부분 취소도 사람이 CLI로 대상과 수량을 지정할 때만 일어난다

ADR-0007 결정 1, ADR-0008 결정 1의 경계를 유지한다. 재계획이 자동으로 부분 취소하는 경로와 HTTP 쓰기
경로는 만들지 않는다.

### 2. 취소 수량은 사람이 지정한다 — 엔진 목표에서 계산하지 않는다

**초안 작성 중 뒤집은 판단이다.** 처음에는 ADR-0011이 절대 지정가를 금지한 것과 같은 이유로 "엔진이
계산한 목표 수량에 맞춘다"를 제안했다. 그러나 취소는 정정과 성질이 다르다.

- 정정은 **새 노출을 만든다**(체결 가능성을 되살린다). 그래서 사람이 값을 주면 한도 우회 경로가 된다.
- 취소는 **노출을 줄인다**. 어떤 한도도 새로 위반할 수 없다. 사람이 수량을 정하는 것이 위험을 만들지
  않는다.
- 엔진 목표에 묶으면 "지금 이만큼만 줄이고 싶다"는 정당한 운영 의도를 표현할 수 없다. 목표가 0이면
  전량 취소만 가능해진다.

따라서 취소 수량은 사람이 지정하고, 잔량을 초과하는 요청은 거부한다.

### 3. 위험검사는 하지 않는다 — 노출 감소는 검사 대상이 아니다

ADR-0011은 정정에 전수 위험검사를 요구했다. 그 이유는 정정이 새 노출을 만들기 때문이다. 부분 취소는
노출을 줄이므로 정책 §3·§4의 어떤 한도도 새로 위반할 수 없다.

**리스너 부착 조건도 요구하지 않는다.** ADR-0009 결정 3이 리스너를 요구한 이유는 "체결 사실을 장중에
확인할 수 없는 주문을 만들지 않기 위해"다. 부분 취소는 주문을 만들지 않고 줄인다. 오히려 리스너가
없을 때 노출을 줄이는 것을 막으면, 통보가 끊긴 상황에서 사람이 위험을 줄이는 수단을 잃는다.

비상정지가 미체결 전량 취소를 리스너 조건 없이 수행하는 것과 같은 논리다.

### 4. 취소 수량은 응답·통보로 확인된 값만 반영한다

취소 요청과 체결이 경합할 수 있다. 우리가 보낸 수량을 사실로 기록하지 않고, 증권사 응답과 체결통보로
확인된 값만 내부 수량에 반영한다. 확인되지 않으면 `ACCOUNT_NOT_RECONCILED`로 자동매매를
정지한다(ADR-0008 결정 3의 규칙 그대로).

### 5. 취소 주문번호는 이벤트에 남기고 원주문번호는 유지한다

실측대로 부분 취소는 자체 주문번호를 받지만 **원주문번호가 살아 있다**. 정정과 달리 내부
`broker_order_id`를 갱신하지 **않고**(원주문이 그대로 대상이므로) 취소 주문번호를 이벤트에만
남긴다. 정정에서 번호를 갱신해야 했던 이유(이후 체결이 새 번호로 온다)가 취소에는 없다.

### 6. 상태 전이는 없다. 수량 변화는 이벤트로 남긴다

부분 취소는 체결이 아니므로 `SUBMITTED`·`PARTIALLY_FILLED`가 유지된다. 취소 전후 수량을 주문
이벤트에 남겨 이력이 성립하게 한다. 전량이 취소되면 기존 취소 경로와 같이 `CANCELED`가 된다.

### 7. 실패와 거절은 fail-closed다

증권사가 거절하면 수량·주문번호·상태를 바꾸지 않고 사유를 남긴다. 전송 실패는 `api_failure`로
기록하고 정책 §3의 연속 실패 규칙을 따른다.

## 선행 조건: 체결통보 리스너의 취소 반영 결함

**실측 중 발견했다.** 리스너가 취소 확인 통보를 **통보된 수량과 무관하게 전량 취소로 적용**한다.

- 카카오 14주 중 5주를 취소했더니 통보는 `quantity=5`를 실었는데 내부 주문은 `canceled`(14주)가 됐다.
- 그 결과 비상정지가 그 주문을 대상에서 제외해 `cancel_requested=1`로 끝났고, **증권사에 남아 있던
  9주를 취소하지 않았다.** 수동으로 정리했다.
- 두 번째 시험에서도 재현됐다(`cancel_requested=2`, 3건 중 2건). 그때는 잔여가 0이라 실제 피해가
  없었다.

**지금은 잠재 결함이다.** 프로덕션 경로가 전량 취소만 보내므로 통보 수량과 주문 수량이 항상 같다.
그러나 부분 취소를 도입하면 **즉시 실제 결함이 된다** — 내부는 취소됨, 증권사는 열려 있음, 비상정지는
그 주문을 건드리지 못하는 상태다. 사람의 마지막 통제 수단이 무력화되는 형태다.

따라서 이 ADR이 승인되면 **부분 취소 구현보다 먼저** 리스너가 통보된 수량만 반영하도록 고쳐야 한다.
이것이 결정 4("응답·통보로 확인된 값만 반영")가 필요한 이유의 실측 근거다.

## 결과

승인되면:

- 미체결 노출을 전량 취소 없이 줄일 수 있다.
- 잔여는 재진입되지 않은 **원주문 그대로**이므로 호가 우선순위가 유지된다고 볼 근거가 있다
  (§호가 우선순위 — 추론이며 관측이 아니다).
- 초과 취소를 증권사가 막으므로, 우리가 잔여를 잘못 알아도 없는 수량이 취소되지 않는다.

승인되지 않으면:

- 노출 축소는 계속 전량 취소 + 재계획이다. **지금까지 이것이 손실로 이어진 관측은 없다** — 모의 실주문은
  즉시 전량 체결되거나(2026-08-19) 의도적으로 지정가를 벌려 미체결로 남긴 경우(2026-08-21)뿐이었고,
  후자는 전량 취소로 정리했다.

## 대안

- **엔진이 취소 수량을 계산**: 사람이 숫자를 정하지 않아 감사가 깔끔하다. 그러나 "지금 이만큼만 줄인다"를
  표현할 수 없고, 노출 감소에는 한도 우회 위험이 없어 제약할 이유가 없다(위 결정 2).
- **부분 정정도 함께 도입**: 일부만 가격을 바꿀 수 있다. 그러나 주문 하나가 두 가격으로 쪼개져 내부
  모델(주문 1행 = 가격 1개)과 증권사 사실이 어긋난다. 별도 결정으로 남긴다.
- **부분 취소에도 전수 위험검사**: 일관돼 보인다. 그러나 통과 실패로 노출 축소가 막히는 경로가 생긴다 —
  안전 장치가 안전 행동을 막는 형태다.
- **전량 취소 유지**: 추가 상태가 없다. 우선순위 유지가 부정되면 이 대안이 정답이다.

## 승인이 필요한 질문

1. 로드맵 항목의 이름을 "수량 정정"에서 **"미체결 수량 축소(부분 취소)"**로 정정하는가?
2. 부분 취소를 도입하는가?
3. 취소 수량을 사람이 지정하는가, 엔진이 계산하는가? (초안 제안: 사람)
4. 부분 취소에 위험검사·리스너 조건을 면제하는가? (초안 제안: 면제)
5. 아래 §선행 조건(리스너 결함)을 먼저 고치는 것을 전제로 하는가? (초안 제안: 전제로 한다)

## 재검토 조건
