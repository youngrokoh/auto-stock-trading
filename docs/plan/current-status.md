## 다음 세션 시작 규칙

다음 세션은 이 문서를 먼저 읽고 현재 Git 상태와 원격 `main`을 확인한다. 완료된 기반과 승인된 디자인 방향을 다시 결정하지 않고 아래 다음 작업부터 이어간다.

- 백엔드·프론트엔드·브라우저·문서 CI
- GitHub `main` 저장소 연결과 최초 게시
- Research Grid와 Night Watch 안전 표현을 결합한 클로드 화면 디자인 승인
- KIS 인증·시장 데이터 첫 수직 슬라이스 코드와 데이터베이스 리비전
- 삼성전자·KODEX 200 종목정보, 최신 현재가, 비수정 일봉 읽기 API
- `XKRX` 국내 시장 달력·휴장일 데이터 계약

- KRX 공식 연간 휴장 일정 수집과 KIS 실전 전용 당일 개장 여부 보완 확인 경계
- KRX 보도자료·공식 PDF 기반 수능일·연초 개장일 임시 정규장 시간 수집과 연간 일정 합성
- 시장 달력 PostgreSQL 실행 claim, 서울 기준 Taskiq 예약과 KRX 전용 Compose scheduler 프로필
- 실전 읽기 전용 KIS `CTCA0903R` 당일 응답과 중복 호출 차단 검증
- worker 전용 실전 secret과 비밀정보 없는 scheduler 플래그를 분리한 KIS 자동 확인 활성화
- 비수정 `market_bar` 버전·확정 상태 마이그레이션, 이력 보존 저장소와 현재 버전 읽기 API
- 기업행사 도메인 타입, `market.corporate_action` 마이그레이션과 사실 버전 저장소

## 반드시 기억할 디자인 상태

- 사용자는 2026-08-12에 [클로드 화면 디자인 사양](../design/claude-design/screen-design-spec.md)과 [HTML 시안](../design/claude-design/screen-mockups.html)을 공식 디자인 방향으로 승인했다.
- 2026-08-17에 승인 토큰·프리미티브(좌표 셀, 데이터 표, 상태 배지, 경고 배너, 반응형 앱 셸)와 운영 개요(`/`), 시장 데이터(`/market`), 구성요소 갤러리(`/showcase`)를 승인 디자인으로 구현했고 390·768·1360px 실브라우저 QA를 통과했다([3단계 검증](../qa/phase-3-market-dashboard-verification.md)). 태블릿 접기 규칙은 같은 날 사용자가 확정했다(레일 유지·내비 숨김·1열·KPI 3×2).
- 시안의 가격, 수익률, 계좌, 주문과 포지션 숫자는 레이아웃 예시이므로 하드코딩하지 않는다. 모든 표시 값은 실제 API에서 오고, 백엔드가 없는 영역은 값 생성 없이 빈 상태 규칙으로 표시한다.
- 이후 화면(기업 분석, ETF 탐색, 전략 연구, 모의매매 콘솔 등)도 같은 토큰과 프리미티브로 확장한다.

자격증명은 문서, Git, 브라우저 번들과 로그에 기록하지 않는다. 실전 주문 기능은 이 단계에 포함하지 않는다.

## 다음 기술 작업 완료 조건

기업행사 사실 버전 저장소에 이어 OpenDART 현금배당 수집을 완료했다. 실제 삼성전자 2026-04-30 공시 원문을 fixture로 사용해 공시검색·원본 ZIP 수집, `현금ㆍ현물배당결정` 엄격 파싱, 재수집 멱등성과 기재정정의 버전 연결을 PostgreSQL에서 통합 검증했다. 2026-08-17에는 사용자가 발급한 OpenDART 키(`.secrets/dart-api-key`)로 실제 API에서 2026년 배당 3건(566원·372원·374원)을 수집하고 멱등 재수집과 공개 원문 대조까지 검증했다. 같은 날 KODEX 200 분배금을 운용사 공식 API에서 수집해 2024~2026년 이력 11건을 적재했고, 재수집 멱등성과 '26.7월 월말배당 공지문(183원) 대조를 검증했다. 이어 사용자 승인 규칙(KRX T+2 결제, 검증된 달력만 사용)으로 배당·분배락일 확정 경계를 구현해 실제 10건이 `verified`로 확정됐고 2024년 4건은 달력 미커버로 `pending`을 유지한다. 수정계수 계산기와 수정주가 데이터셋 저장소를 구현·통합 검증했으며, 일봉 확정 전의 실데이터 발행 시도는 계약대로 `unconfirmed_bar_in_range`로 차단됐다(실패 기록 보존). 이어 일봉 재조회 확정 흐름을 구현해 실제 KIS 모의환경에서 7월~8월 일봉 64개를 확정했고, KODEX 200 분배락(2026-07-30)을 반영한 `total_return` 데이터셋 등 4건을 실제 발행해 계수와 수정 종가를 수동 대조했다. 2026-08-17에는 계약의 필수 조회 계약을 따르는 읽기 API를 구현했다. 기업행사는 현재·이력·`knowledge_cutoff_at` 시점 조회를, 수정주가는 종목·방식별 최신 발행 데이터셋과 파생 일봉·개별 계수, 데이터셋 ID 조회와 기업행사별 영향 데이터셋 목록을 제공하며, 응답은 방식·기간·지식 기준시각·알고리즘 버전·입력 해시·데이터셋 ID·출처와 비수정 일봉·기업행사 버전 계보를 항상 포함한다. 실제 발행 데이터로 계수 0.9979577032531667, 수정 종가 89422, 수집 이전 cutoff의 빈 응답(미래정보 차단)과 404·422 오류 계약을 검증했다. 같은 날 사용자가 분봉 데이터 계약을 승인해 비수정 1분봉 수집을 구현했다. 검증된 달력이 최신 거래일과 세션 창을 결정하고(휴장일은 직전 거래일, 미커버·충돌은 fail-closed), 구간 종료 후 두 관측이 일치한 분봉만 확정되며, 모의환경 당일분봉 API 한계로 과거 백필은 불가능해 거래일마다 수집한다. 실제로 2026-08-14 세션 분봉 391개씩을 수집·재수집해 전량 확정했고 시가·종가·고저 포락선·원본 누적 거래량이 확정 일봉과 일치했다. 종가 단일가 행의 2배 거래량 반환은 원본 그대로 보존하고 실측 한계로 계약에 기록했다(사용자 승인). 이어서 승인 디자인 기반 3단계 시장 대시보드를 1차 구현했다. 종목 목록 읽기 API(`GET /api/market-data/instruments`)를 추가하고, 승인 토큰·프리미티브 위에 운영 개요와 시장 데이터 화면을 실제 API 데이터로 재구축했으며(배치 수집 시세는 기준시각과 지연 상태를 항상 노출, 미확정 일봉은 지표 계산 제외), 390·768·1360px 실브라우저 QA와 e2e 9건, vitest 16건(SMA·RSI·MACD·볼린저 수치 벡터 포함)을 통과했다. 태블릿 접기 규칙은 사용자가 확정해 디자인 계약에 기록했다. 이어 4단계 첫 단계로 사용자가 승인한 재무제표 데이터 계약에 따라 OpenDART 전체 재무제표 수집을 구현했다. 보고서(사업연도×유형×연결구분) 단위 사실 버전이 접수번호를 근거로 저장되고, 같은 접수번호 재수집은 멱등이며 정정 공시는 이전 버전을 보존한 새 버전이 된다. 실제 키로 삼성전자 14개 보고서(2021~2025 사업보고서, 2026 1분기·반기 × 연결·개별)를 수집해 자산총계와 라인 수를 DART 원문과 대조했고, 미제출 2026 3분기는 계약대로 건너뛰었다. 실수집에서 발견한 두 가지(자본변동표 `ord` 중복, `account_id` 최대 180자)는 사용자 승인으로 계약을 정정해 반영했다(`line_seq` 유일키, `VARCHAR(255)`). 이어 사용자가 승인한 재무 지표 정의 계약(연결·연간 사업보고서 기준, 같은 보고서의 당기·전기 금액만 사용, ROE 지배주주 기준, 가치지표는 상장주식수 정규화 수집 후 후속)에 따라 성장성 3종·수익성 4종·안정성 2종을 백엔드가 조회 시점에 계산하는 읽기 API를 구현했다. 응답은 지표마다 수식·입력 계정과 금액·근거 접수번호를 포함하고, 필요한 계정이 없으면 값 없이 사유 코드를 담는다(개별 재무제표의 ROE가 실제로 `MISSING_ACCOUNT`). 실제 삼성전자 연결 5개년 지표를 DART 원문 금액 수동 재계산과 대조했다(2025 매출액증가율 10.88%, 영업이익률 13.07%, 부채비율 29.94% 등). 승인 디자인 기업 분석 화면(`/analysis`)은 KPI 7셀, 실적 막대 차트, 원문 재무제표 라인 표(보고서·구분 전환), 연도별 지표 표와 근거 공시 카드를 이 API로만 구성하고 가치지표·수급·공시 연결은 빈 상태로 두었으며, e2e 12건과 390·768·1360px·다크 실브라우저 QA를 통과했다. 다음 기술 작업은 4단계 후속(상장주식수 정규화 수집과 가치지표, 외국인·기관 수급, 공시 연결)이며, KIS 수정주가 대조는 분할 이력 종목 확보 시 수행한다. 기본 Compose와 모의환경은 계속 KIS 자동 확인이 꺼져 있고 실전 달력 전용 worker만 자격증명을 받는다. 사용자는 별도로 KIS 화면의 값과 거래일을 최종 육안 대조한다. 승인 디자인 구현 세션에서는 공통 프리미티브와 대상 화면이 390px, 768px, 1360px 실제 브라우저 QA를 통과해야 한다.
