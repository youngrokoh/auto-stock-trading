# 시장 데이터 및 시점 정책

- 상태: 승인
- 승인일: 2026-08-11
- 초기 범위: 국내주식·국내 ETF, 일봉 전략
- 관련 정책: [거래 안전 정책](trading-safety-policy.md)
- 관련 데이터 계약: [국내 시장 달력 데이터 계약](../data/market-calendar-data-contract.md), [기업행사·수정주가 데이터 계약](../data/corporate-action-adjusted-price-data-contract.md)

## 구현 기록

2026-08-14에 2단계 첫 수직 슬라이스로 KIS 모의투자 인증 어댑터, 국내주식·ETF 종목정보·현재가·비수정 일봉 저장과 읽기 API를 구현하고 실제 모의 API로 반복 수집을 검증했다.

- 일봉 요청은 `FID_ORG_ADJ_PRC=1`을 사용하며 `adjusted=false`로 저장한다.
- 원본 응답은 append-only로 보존하고 종목·최신 현재가·일봉은 고유키로 upsert한다.
- KIS 현재가 REST 응답에 거래소 체결시각이 없으므로 이번 단계의 `quote.as_of`는 UTC 수신시각이다. 실시간 스트림 도입 시 거래소 시각을 별도 필드로 보존한다.
- 수정주가 데이터셋, 기업행사와 분봉은 이 정책대로 후속 2단계에서 구현한다.
- KIS 모의환경은 종목 상세 TR `CTPF1002R`을 지원하지 않으므로 현재가와 일봉만 호출하고, 최소 종목 식별정보의 이름은 일봉 응답 요약에서 구성한다. 상장일·상장폐지일·영문명은 실전 상세조회 또는 후속 종목 마스터 수집 전까지 비어 있다.
- 실제 모의 API에서 두 종목을 같은 범위로 두 번 수집해 정규화 행 수가 유지되고 원본 응답만 실행당 4건 추가됨을 확인했다.
- 승인된 [ADR-0005](../decisions/0005-kis-token-and-rate-coordination.md)에 따라 접근 토큰과 모의 REST 1.05초 호출 간격을 Valkey에서 프로세스 간 공유한다. Valkey 장애 시 개별 worker 호출로 우회하지 않는다.
- 2026-08-16에 `XKRX` 정규장의 거래일·휴장일·단축장, 사실 버전과 당일 확인 상태를 정의한 [시장 달력 데이터 계약](../data/market-calendar-data-contract.md)을 작성했다.
- 같은 날 `reference.market_calendar` 리비전과 도메인·PostgreSQL 저장소를 구현했다. 동일 사실은 현재 버전을 재사용하고, 정정은 이전 버전을 보존하며, KIS가 KRX 현재 사실과 충돌하면 버전을 바꾸지 않고 `conflict`와 비밀정보 없는 동기화 오류를 기록한다.
- 같은 날 KRX 공식 `[01023] 휴장일` 연간 응답을 정상장·주말·공식 휴장일 세션으로 정규화하는 어댑터와 KIS 실전 전용 국내휴장일조회 `CTCA0903R`의 당일 `opnd_yn` 보완 확인을 연결했다. KRX 범위는 한 트랜잭션으로 저장하고 KIS가 다르면 `conflict`로 차단한다.
- 같은 날 [KRX 보도자료](https://open.krx.co.kr/contents/OPN/05/05000000/OPN05000000.jsp)의 임시 거래시간 공지와 공식 PDF를 수집해 연간 일정에 합성했다. 수능일과 연초 개장일의 주식·ETF 정규장 변경만 지원하며, PDF 원문·공지 번호·첨부 메타데이터를 근거로 보존하고 알 수 없는 임시 변경 형식은 전체 수집을 실패시킨다.
- 같은 날 승인된 [ADR-0006](../decisions/0006-market-calendar-scheduling.md)에 따라 서울 기준 KRX·KIS Taskiq 예약, PostgreSQL 영속 실행 claim과 Compose 단일 scheduler 프로필을 구현했다. 기본 실행은 scheduler가 꺼져 있고 프로필 활성화 시에도 KRX만 켜진다.
- 같은 날 분리한 실전 읽기 전용 자격증명으로 `CTCA0903R`을 1회 수동 검증했다. `2026-08-16` 응답의 `opnd_yn=N`이 KRX 휴장 세션과 일치해 `confirmed`가 됐고, 재실행은 영속 claim에서 외부 호출 없이 종료됐다. KIS 자동 확인은 사용자의 별도 활성화 결정 전까지 계속 꺼져 있다.
- 같은 날 사용자 승인 후 실전 달력 전용 Compose override를 추가했다. worker만 실전 secret을 받고 scheduler는 비밀정보 없이 `live` 환경과 활성화 플래그로 KIS 예약을 등록한다. 기본 Compose와 모의환경에는 이 활성화를 적용하지 않는다.
- 같은 날 기업행사 사실 버전, 비수정 일봉 버전, `split_adjusted`·`total_return` 파생 데이터셋과 point-in-time 규칙을 구체화한 [기업행사·수정주가 데이터 계약](../data/corporate-action-adjusted-price-data-contract.md)을 작성했고 사용자가 구현 기준으로 승인했다.
- 같은 날 비수정 `market_bar`를 사실 버전 저장으로 전환했다. 기존 20개 행은 `version=1`, `pending`으로 보존했고, 동일 사실 재수신은 근거만 갱신하며 정정은 이전 확정 버전을 남기고 새 `pending` 버전을 만든다. 일봉 읽기 API는 현재 사실의 버전과 확정 상태를 함께 제공한다.
- 같은 날 기업행사 도메인 타입과 `market.corporate_action` 사실 버전 저장소를 구현했다. 같은 출처 사건의 반복 처리는 버전을 늘리지 않고, 정정·취소는 이전 버전을 보존하며, 조회는 현재 사실·정정 이력과 `knowledge_cutoff_at` 당시 알 수 있었던 버전 선택을 제공한다.
- 같은 날 OpenDART 현금배당 수집을 구현했다. 공시검색 목록과 공시서류 원본 ZIP의 거래소 서식 HTML을 인증정보 없이 append-only 보존하고, `현금ㆍ현물배당결정` 서식만 엄격 파싱해 `announced`·`pending` 사실로 저장한다. 접수번호가 다른 기재정정은 같은 종목·유형·배당기준일이 일치할 때만 같은 논리 사건의 새 버전으로 연결하고, 불확실한 연결은 병합하지 않는다. 목록 접수일에는 시각이 없으므로 `available_at`은 수신시각으로 보수 처리하며 배당락일은 저장하지 않고 후속 확인 전까지 계산 조건 미충족 상태로 둔다. ETF 분배금과 액면분할 수집은 후속 작업이다.
- 2026-08-17에 사용자 승인에 따라 배당·분배락일을 KRX T+2 결제 규칙과 검증된 `XKRX` 달력으로 도출하는 확정 경계를 구현했다. 실제 DB에서 2025~2026년 배당·분배금 10건이 `verified` 새 버전으로 확정됐고(연말휴장·설연휴를 달력으로 정확히 건넘), 2024년 4건은 달력이 없어 `pending`으로 남았다.
- 같은 날 수정계수 계산기와 `split_adjusted`·`total_return` 데이터셋 저장소를 구현했다. 입력 해시·계수 반올림·knowledge cutoff 버전 선택·정정 시 새 데이터셋 생성·발행 차단 사유를 PostgreSQL에서 통합 검증했고, 실데이터 생성 시도는 미확정 일봉 때문에 계약대로 `failed`(`unconfirmed_bar_in_range`)로 차단됐다. 실제 발행은 일봉 재조회 확정 흐름 구현 후 가능하다.
- 같은 날 일봉 재조회 확정 흐름을 구현했다. 최종 상태 플래그가 없는 KIS 일봉은 서울 기준 해당 거래일 15:40 이후의 관측 두 번(저장된 현재 사실과 재조회 응답)이 정확히 일치할 때만 `confirmed`로 전환하고, 장중 첫 관측은 확정 근거로 쓰지 않으며, 재조회 값이 다르면 확정 대신 새 `pending` 정정 버전을 만든다. 실제 KIS 모의환경에서 7월~8월 일봉을 수집·재조회해 두 종목 64개 일봉이 모두 확정됐고, 확정된 일봉으로 KODEX 200 분배락(2026-07-30, 183원)을 반영한 `total_return` 수정주가 데이터셋 등 4건을 실제 발행했다. 계수 0.9979577032531667과 락일 직전 수정 종가 89422(=89605−183)를 수동 계산과 대조했다. KIS 수정주가 대조(계약 검증 시나리오 9)는 현금 사건만 있는 현재 종목에서는 차이 없음이 예상되므로 분할 이력 종목 확보 시 수행한다.
- 같은 날 사용자가 [국내 분봉 데이터 계약](../data/minute-bar-data-contract.md)을 승인했고(재관측 일치 2회 확정, 백필 없는 당일 축적), 비수정 1분봉 수집·버전 저장·확정과 읽기 API를 구현했다. 실제 모의환경에서 두 종목의 2026-08-14 세션 분봉 391개씩을 수집·재수집해 전량 확정했으며, 시가·종가·고저 포락선·원본 누적 거래량이 확정 일봉과 일치했다. 종가 단일가 행의 분당 거래량 2배 반환과 일봉의 시간외 포함 범위 차이는 실측 한계로 계약에 기록했고 사용자가 검증 시나리오 조정을 승인했다.
- 같은 날 계약의 필수 조회 계약을 따르는 기업행사·수정주가 읽기 API를 구현했다. 기업행사는 현재·이력·`knowledge_cutoff_at` 시점 조회를, 수정주가는 종목·방식별 최신 발행 데이터셋, 데이터셋 ID 조회와 기업행사별 영향 데이터셋 목록을 제공하며, 응답은 방식·기간·지식 기준시각·알고리즘 버전·입력 해시·출처·계보를 항상 포함하고 원본·수정 여부를 불리언 하나로 표현하지 않는다. 실제 발행 데이터로 계수·수정 종가·point-in-time 차단과 404·422 오류 계약을 검증했다.
- 2026-08-17에 사용자가 발급한 OpenDART 키로 삼성전자 2026년 현금배당 3건(결산 566원, 1분기 372원, 2분기 374원)의 실제 수집을 검증했다. 재수집은 사실 버전을 늘리지 않고 원본만 추가했으며, 2분기 공시는 공개 DART 뷰어 원문과 일치했고 저장 원본·지문에 인증키가 없음을 확인했다.
- 같은 날 KODEX 200 ETF 분배금 수집을 구현하고 실제 운용사 공식 API로 검증했다. 삼성자산운용 KODEX 분배금 데이터에서 2024~2026년 지급 이력 11건(지급기준일·세전 주당분배금·실지급일)을 `confirmed`·`pending`으로 저장했고, 재수집은 버전을 늘리지 않았으며 2026-07-31 분배금 183원이 운용사 '26.7월 월말배당 공지문과 일치했다. 분배락일은 저장하지 않고 확정 경계는 후속 작업이다. KRX 정보데이터시스템은 화면 종속 세션 게이트로 자동 수집 출처에서 제외했다.

## 1. 시간 기준

- 저장 기준시각은 UTC로 통일한다.
- 원천 데이터의 거래소 시각과 API 수신시각을 별도 보존한다.
- 국내 시장 판단과 사용자 표시는 `Asia/Seoul`을 사용한다.
- 미래 미국 시장 지원 시 거래소별 시간대와 서머타임 규칙을 별도로 추가한다.

KRX 주식·ETF 정규장은 09:00~15:30이고 호가 접수는 08:30부터 시작한다. 초기 자동매매는 정규장 중 09:05~15:15만 주문 가능시간으로 사용하며 시간외 거래는 지원하지 않는다. 공식 기준은 [KRX 주식시장 거래시간](https://global.krx.co.kr/contents/GLB/06/0602/0602010201/GLB0602010201T1.jsp)과 [KRX ETF 거래제도](https://global.krx.co.kr/contents/GLB/06/0605/0605010101/GLB0605010101T1.jsp)를 따른다.

거래일은 평일 여부로 추정하지 않는다. KRX 공식 휴장일과 증권사 거래 가능 응답을 함께 사용하며, 임시 휴장이나 개장시간 변경은 `market_calendar`의 버전된 세션으로 반영한다.

연간 기준 일정은 [KRX 휴장일 화면](https://global.krx.co.kr/contents/GLB/05/0501/0501110000/GLB0501110000.jsp)의 공식 목록과 [KRX 거래일·휴장 규칙](https://global.krx.co.kr/contents/GLB/06/0602/0602010201/GLB0602010201T1.jsp)을 함께 사용한다. 이 응답에 없는 수능일·연초 개장일의 임시 정규장 시간은 KRX 보도자료 목록과 공식 PDF에서 대상일, 주식·ETF 범위, 변경 전 `09:00~15:30`, 변경 후 시간을 모두 확인한 뒤 같은 연간 범위에 합성한다. 공지 형식, 대상 범위, 기준 시간이 계약과 다르면 기존 정책을 추정으로 완화하지 않고 수집을 실패시킨다. 자동 스케줄러는 승인된 [ADR-0006](../decisions/0006-market-calendar-scheduling.md)에 따라 KRX 선행 수집, KIS 당일 확인과 PostgreSQL 영속 중복 방지를 적용한다.

## 2. 데이터 계층

```text
외부 API 응답
    ↓
원본 데이터: 수신 내용, 출처, 요청 식별자, 수신시각
    ↓
정규화 데이터: 종목 식별자, 거래소 시각, 가격·수량·통화
    ↓
파생 데이터: 수정주가, 보조지표, 순위, 학습 특징
```

- 원본 데이터는 인증정보와 계좌번호를 제거한 뒤 보존한다.
- 정규화 오류가 발생해도 원본 데이터를 수정하지 않는다.
- 파생 데이터에는 계산식 버전과 입력 데이터 버전을 기록한다.
- 정정 수신 시 기존 사실을 삭제하지 않고 새 버전과 정정 관계를 남긴다.

## 3. 종목 식별

종목코드 문자열만으로 종목을 식별하지 않는다.

```text
InstrumentId
= 국가 + 거래소 + 종목코드 + 상품유형 + 통화
```

종목 마스터에는 상장일, 상장폐지일, 거래 상태, 주식·ETF 구분, 업종과 원천 데이터 기준일을 저장한다. 코드 재사용과 시장 간 동일 코드 충돌을 고려해 내부 식별자는 별도로 발급한다.

상장주식수는 KIS 시세 응답에서 함께 관측해 `reference.listed_share_count`에 버전 사실로 저장한다(2026-08-17 구현). 같은 값 재관측은 버전을 늘리지 않고, 증자·소각으로 값이 바뀌면 이전 버전을 보존한 새 버전이 된다. 세부 규칙과 가치지표 사용처는 [재무 지표 정의 계약](../data/financial-indicator-contract.md)을 따른다.

## 4. 데이터 신선도

| 데이터 | 정상 | 지연 | 주문 차단 |
|---|---|---|---|
| 정규장 현재가 | 수신 후 30초 이내 | 30초 초과 120초 이하 | 10초 초과 시 해당 시세 기반 주문 차단 |
| 실시간 스트림 | 연결 및 heartbeat 정상 | 재연결 중 | 연결 상실 즉시 신규 주문 차단 |
| 분봉 | 해당 구간 종료 후 확정 | 다음 구간까지 미수신 | 미확정·누락 분봉 사용 금지 |
| 일봉 | 최종 검증 완료 | 검증 대기 | 검증 전 신호 생성 금지 |
| 종목 마스터 | 최근 거래일 기준 | 1거래일 초과 | 거래 상태 불명 종목 주문 차단 |
| 시장 달력 | 당일 07:00 이전 확인 | 재확인 필요 | 당일 세션 미확정 시 스케줄 실행 금지 |

UI가 정상으로 표시하는 30초 기준과 주문 위험검사의 10초 기준은 의도적으로 다르다. 화면 조회 가능 상태가 곧 주문 가능 상태를 의미하지 않는다.

## 5. 일봉 확정과 신호 시점

일봉 전략은 다음 순서를 지킨다.

```text
거래일 D 정규장 종료
→ 15:40 이후 일봉 1차 수집
→ 원천의 최종 상태 또는 재조회 일치 확인
→ 거래일 D 일봉 확정
→ 특징과 신호 계산
→ 다음 거래일 D+1의 09:05 이후 주문 가능
```

- 거래일 D 종가로 만든 신호를 같은 종가에 체결했다고 가정하지 않는다.
- 최종 상태 플래그가 없으면 15:40 이후 두 번 조회한 OHLCV가 일치해야 확정한다.
- 정정된 일봉은 데이터 버전을 올리고 영향을 받은 특징과 백테스트를 재계산한다.
- 미확정 일봉은 차트에 잠정값으로 표시할 수 있지만 전략 입력에는 사용하지 않는다.

## 6. 가격과 기업행사

구현 필드, 수정계수, 입력 해시와 미래정보 차단 기준은 승인된 [기업행사·수정주가 데이터 계약](../data/corporate-action-adjusted-price-data-contract.md)을 따른다.

- 원본 OHLCV는 비수정 가격으로 저장한다.
- 수정주가는 별도 데이터셋으로 생성하고 조정 방식과 생성 버전을 기록한다.
- 액면분할, 병합, 배당, 권리락, 합병과 상장폐지는 `corporate_action`으로 관리한다.
- 백테스트는 당시 알 수 있었던 발표일과 효력일을 구분해 미래정보 누출을 방지한다.
- ETF 분배금은 가격 조정과 현금흐름을 중복 반영하지 않는다.

## 7. 데이터 품질 규칙

수집 시 다음 규칙을 검사한다.

- `low <= open, close <= high`
- 가격과 거래량은 음수가 아니다.
- 거래량이 0인 경우와 데이터 누락을 구분한다.
- `(instrument_id, interval, exchange_timestamp, source)`가 중복되지 않는다.
- 거래일과 세션 밖 데이터는 자동 확정하지 않는다.
- 급격한 가격 변화는 기업행사와 거래소 상태를 확인하기 전까지 이상값으로 표시한다.
- 서로 다른 소스 값이 충돌하면 출처 우선순위와 차이를 모두 기록한다.

누락된 OHLCV를 직전 값으로 채우지 않는다. 보조지표의 준비 기간이 부족하면 값을 `null`로 유지하고 신호 생성을 건너뛴다.

## 8. 출처 우선순위

| 데이터 | 1차 출처 | 보완 출처 |
|---|---|---|
| 계좌·주문·체결 | KIS 계좌 API | 없음 |
| 주문 판단 현재가 | KIS 실시간·현재가 API | 없음, 실패 시 주문 차단 |
| 종목 마스터·일봉 | KIS | KRX와 대조 |
| 거래일·시장 제도 | KRX | KIS 거래 가능 상태 |
| 기업 공시·재무 | OpenDART | KRX/KIND 연결 |
| ETF 기준정보 | KRX/KIND 또는 허가된 공급자 | KIS 제공 범위 |

소스가 충돌할 때 주문과 체결 사실은 증권사 계좌 API를 기준으로 한다. 분석 데이터 충돌은 자동으로 한쪽을 덮어쓰지 않고 데이터 품질 이벤트를 생성한다.

## 9. 수집과 복구

- 모든 수집 작업에는 멱등성 키를 사용한다.
- [KIS API 호출 유량 안내](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000001/post/d0d1a83f-6f8d-4437-9700-6d26702fd989)에 따라 모의투자 REST 요청은 초당 1건 제한을 넘지 않도록 같은 자격증명의 모든 프로세스에서 인증과 시세 요청을 최소 1.05초 간격으로 직렬화한다.
- 마지막 성공 커서보다 일정 구간을 겹쳐 재수집하고 고유키로 중복을 제거한다.
- 재시도는 호출 제한과 서버의 재시도 안내를 존중한다.
- 재시도 후에도 실패하면 `api_sync_status`에 범위, 원인과 다음 재개 지점을 기록한다.
- 부분 수집 결과는 완료 상태로 표시하지 않는다.

## 10. 완료 조건

- 삼성전자와 대표 ETF의 종목 정보·현재가·일봉에 출처와 세 시각을 표시할 수 있다.
- 동일 범위를 반복 수집해도 중복 레코드가 생기지 않는다.
- 미확정·누락·지연 데이터를 사용한 신호와 주문이 차단된다.
- 기업행사 전후 수정주가와 현금흐름이 테스트 데이터에서 일치한다.
