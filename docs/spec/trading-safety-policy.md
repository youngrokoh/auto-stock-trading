# 거래 안전 정책

- 상태: 승인
- 승인일: 2026-08-11
- 적용 환경: 국내주식·국내 ETF 모의투자
- 관련 정책: [시장 데이터 및 시점 정책](market-data-policy.md), [모의투자·실전투자 전환 게이트](paper-to-live-gate.md)
- 관련 결정: [AI 신호와 주문 실행 분리](../decisions/0004-ai-execution-separation.md)

## 1. 목적과 적용 원칙

이 정책은 전략의 수익성보다 자금 보호와 주문 통제를 우선한다. 모든 한도는 주문 체결 후 예상 상태를 기준으로 검사하며, 여러 한도가 동시에 적용되면 가장 엄격한 결과를 사용한다.

- 초기에는 현금 매수와 보유 수량 이내 매도만 허용한다.
- 신용, 미수, 대출, 공매도는 허용하지 않는다.
- 레버리지·인버스 ETF의 신규 매수는 기본적으로 금지한다.
- AI, 전략, 관리자 화면은 위험관리 엔진을 우회할 수 없다.
- 실전투자에는 이 문서의 모의투자 한도를 그대로 사용하지 않고 별도 전환 게이트를 적용한다.

## 2. 기준 금액

```text
기준 NAV
= 현금
+ 보유 종목의 최신 유효 평가금액
- 미결제 비용과 확정된 세금
```

- 장 시작 NAV는 해당 거래일 최초로 계좌 조정이 성공했을 때 고정한다.
- 장중 NAV는 최신 유효 시세로 다시 계산한다.
- 시세가 오래됐거나 계좌 조정이 완료되지 않으면 신규 주문을 차단한다.
- 비중 한도는 체결된 포지션과 미체결 주문이 모두 체결된다고 가정한 예상 노출로 검사한다.

## 3. 모의투자 기본 위험 한도

| 항목 | 기본값 | 초과 시 동작 |
|---|---:|---|
| 총 투자 비중 | NAV의 80% | 신규 매수 거절 |
| 최소 현금 비중 | NAV의 20% | 신규 매수 거절 |
| 종목별 비중 | NAV의 10% | 해당 주문 거절 |
| 업종별 비중 | NAV의 30% | 해당 주문 거절 |
| 분류되지 않은 종목 합계 | NAV의 10% | 해당 주문 거절 |
| 주문 1건 금액 | NAV의 5% | 주문 분할 또는 거절 |
| 하루 신규 매수 금액 | 장 시작 NAV의 20% | 이후 신규 매수 거절 |
| 동시 미체결 주문 | 5건 | 추가 주문 거절 |
| 하루 주문 시도 | 20건 | 자동매매 일시정지 |
| 일일 손실 | 장 시작 NAV 대비 -2% | 자동매매 일시정지 |
| 고점 대비 포트폴리오 낙폭 | -5% | 자동매매 일시정지 및 검토 요구 |
| 연속 주문 거절 | 3건 | 자동매매 일시정지 |
| 외부 API 연속 실패 | 5분 내 3회 | 자동매매 일시정지 |

업종 분류가 없다는 이유로 업종 한도를 생략하지 않는다. 신규·미분류 종목은 별도 보수 한도를 적용한다.

## 4. 주문 가능 조건

초기 주문은 다음 조건을 모두 만족해야 한다.

- KRX 정규장 중 내부 주문 허용시간인 09:05~15:15 Asia/Seoul이다.
- 거래일, 장 상태, 종목 거래 상태가 정상이다.
- 주문 판단에 사용하는 현재가가 수신 후 10초 이내다.
- 계좌, 잔고, 미체결 주문 조정이 완료됐다.
- 관리·경고·위험 종목, 거래정지 종목이 아니다.
- 매수 가능 금액 또는 매도 가능 수량이 확인됐다.
- 전략 버전, 신호, 기준 데이터, 위험검사 결과가 기록됐다.

초기에는 지정가 주문만 허용한다. 매수 지정가는 기준가격보다 1%를 초과할 수 없고 매도 지정가는 기준가격보다 1% 이상 낮을 수 없다. 호가단위로 반올림한 뒤 가격 제한을 다시 검사한다.

## 5. 거래비용과 세금

백테스트와 모의투자는 다음 항목을 주문별로 분리해 기록한다.

```text
매수 비용 = 매수 수수료 + 슬리피지
매도 비용 = 매도 수수료 + 슬리피지 + 증권거래세 + 적용 가능한 부가세
```

### 연구·모의투자 기본 가정

| 항목 | 국내주식 | 국내 ETF |
|---|---:|---:|
| 매매 수수료 | 체결금액의 0.02%, 매수·매도 각각 | 체결금액의 0.02%, 매수·매도 각각 |
| 슬리피지 | 체결금액의 0.10%, 매수·매도 각각 | 체결금액의 0.05%, 매수·매도 각각 |
| 최소 비용 단위 | 주문 합계별 1원 미만 절사 | 주문 합계별 1원 미만 절사 |

위 수수료와 슬리피지는 실제 계좌 요율이 아니라 과도한 낙관을 막기 위한 연구 기본값이다. 실전 전환 전에는 실제 계좌 수수료와 체결 데이터를 반영한 비용 프로필을 별도로 승인해야 한다.

2026년 1월 1일 이후 법정 기준선은 다음처럼 버전 관리한다.

| 상품 | 매도 시 세금 기준선 | 근거 |
|---|---:|---|
| KOSPI 주식 | 증권거래세 0.05% + 농어촌특별세 0.15% | [증권거래세법 시행령](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=&chrClsCd=010202&efYd=20260101&lsId=&lsiSeq=282431&urlMode=lsEfInfoR&viewCls=lsRvsDocInfoR), [농어촌특별세법 제5조](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1027283125) |
| KOSDAQ 주식 | 증권거래세 0.20% | [증권거래세법 시행령 제5조](https://www.law.go.kr/LSW/LsiJoLinkP.do?docType=JO&joNo=000500000&languageType=KO&lsNm=%EC%A6%9D%EA%B6%8C%EA%B1%B0%EB%9E%98%EC%84%B8%EB%B2%95+%EC%8B%9C%ED%96%89%EB%A0%B9&paras=1) |
| ETF 수익증권 | 증권거래세 면제 | [KRX ETF 상품 비교](https://www.krx.co.kr/contents/OPN/01/01030201/OPN01030201T3.jsp) |

ETF의 분배금과 매매차익에 대한 소득 과세는 기초자산과 상품 유형에 따라 달라질 수 있으므로 증권거래세와 별도 필드로 관리한다. 세금 계산 결과는 투자 참고용 추정치이며 세무 신고 자료로 간주하지 않는다.

비용 규칙에는 `effective_from`, 시장, 상품 유형, 매수·매도 구분, 요율, 반올림 방식과 근거 출처를 저장한다. 과거 백테스트에는 당시 유효했던 규칙을 적용하고 현재 규칙으로 소급 덮어쓰지 않는다.

## 6. 자동매매 상태

```text
DISABLED -> ARMED -> RUNNING -> PAUSED
    |          |         |          |
    +----------+---------+----------+-> EMERGENCY_STOP
```

- `DISABLED`: 신호 생성은 가능하지만 주문 계획을 제출할 수 없다.
- `ARMED`: 사용자 확인을 마쳤지만 실행 시각 전이다.
- `RUNNING`: 위험검사를 통과한 주문만 제출한다.
- `PAUSED`: 신규 주문을 금지하며 사용자가 원인을 확인해야 한다.
- `EMERGENCY_STOP`: 신규 주문을 금지하고 미체결 주문 취소를 시도한다.

서버 재시작, 거래일 변경 또는 자격증명 환경 변경 시 상태는 항상 `DISABLED`로 돌아간다. '항상'은 경로를 가리지 않는다는 뜻이다 — 계획 생성뿐 아니라 **제출 게이트와 조회 응답도** 같은 규칙을 적용한다(2026-08-24 구현: 공용 순수 함수 `domain/orders/recovery.py`). 서버 재시작은 저장된 값에서 계산할 수 없으므로 기동 자체가 상태를 바꾼다: API 서버와 체결통보 리스너가 시작할 때 사유 `PROCESS_START`로 전이한다(2026-08-24 구현: `application/trading/startup.py`). 이미 `DISABLED`면 사유를 덮어쓰지 않는다. 조회는 저장 기록을 고쳐 쓰지 않고 지금 성립하는 상태를 계산해 노출하며, 저장된 값과 되돌린 사유를 함께 보여 근거를 감추지 않는다. 자격증명 환경 변경은 기록이 환경별로 분리돼 구조적으로 처리된다. 비상정지는 보유 종목을 자동 시장가 청산하지 않는다. 자동 청산은 급격한 가격 변동과 중복 주문 위험이 있으므로 별도 승인 기능으로만 추가할 수 있다.

## 7. 감사와 변경 통제

모든 주문 시도에는 다음 정보를 연결한다.

- 전략과 신호 버전
- 기준 데이터의 출처와 시각
- 주문 전·후 예상 포지션
- 적용된 모든 위험 규칙과 통과·거절 결과
- 증권사 요청 식별자와 응답 상태
- 사용자 활성화, 일시정지와 비상정지 이력

한도 완화, 허용 상품 확대, 시장가 주문 추가 및 자동 청산 추가는 정책 변경이다. 코드만 변경할 수 없으며 이 문서와 테스트를 먼저 갱신하고 사람의 승인을 받아야 한다.

## 8. 완료 조건

- 위험 한도가 설정값과 실행 가능한 테스트로 동일하게 표현된다.
- 한도 경계값 바로 아래·같음·초과 시나리오가 검증된다.
- 오래된 데이터, 계좌 미조정, 거래정지와 비상정지 상태에서 신규 주문이 차단된다.
- 모든 거절 사유가 감사 로그와 사용자 화면에서 같은 코드로 식별된다.
