# ADR-0020: 자리가 없는 것과 거절된 것을 구분한다

- 상태: 승인 (2026-09-01 구현)
- 결정일: 2026-09-01
- 승인: 2026-09-01 사용자 승인. 질문 1~3을 초안대로 확정했고(경계·알림 발송·구현 후 해제), 구현 중
  드러난 **결정 6(연속 거절을 마지막 재개 이후로 센다)**을 추가 승인받았다
- 관련 결정: [ADR-0007 모의투자 주문 계획과 위험검사 경계](0007-paper-order-planning-and-risk.md), [ADR-0015 자동 스케줄 주문 제출 경계](0015-scheduled-order-submission.md), [ADR-0016 실주문 신호 원천 경계](0016-live-signal-source.md)
- 관련 정책: [거래 안전 정책](../spec/trading-safety-policy.md)
- 관련 계약: [주문 계획·위험검사 데이터 계약](../data/order-planning-risk-contract.md), [백테스트·규칙형 전략 계약](../data/backtest-strategy-contract.md)

## 배경

2026-09-01 10:05에 자동매매가 `RISK_CONSECUTIVE_REJECTS`로 정지했다. 정지를 부른 세 건은 이렇다.

```
09-01 09:05  133690 rejected RISK_UNCLASSIFIED_EXPOSURE
08-31 09:50  133690 rejected RISK_UNCLASSIFIED_EXPOSURE
08-28 09:05  133690 rejected RISK_UNCLASSIFIED_EXPOSURE
```

**같은 종목이 사흘에 걸쳐 같은 이유로 거절됐다.** 정책 §3은 "연속 주문 거절 3건 → 자동매매 일시정지"에
시간 창을 두지 않으므로(외부 API 실패에는 "5분 내"를 명시한 것과 대비된다) 구현은 정책대로 동작했다.
정책을 고쳐 넘어갈 문제가 아니다.

## 측정한 사실

문제는 종목 하나가 아니다.

```
ALLOCATION_UNIVERSE  6종목, 전부 ETF (069500·360750·133690·411060·453850·357870)
ETF는 업종 사실이 없어 전부 "미분류"
미분류 합계 한도      NAV 10% = 1,005,354원
현재 보유            069500 단독 972,225원 (한도의 96.7%)
```

**ETF 배분 전략인데 ETF 전체가 한 칸(NAV 10%)을 나눠 쓴다.** 한 종목이 그 칸을 채우면 나머지 다섯은
구조적으로 통과할 수 없다. 133690을 유니버스에서 빼도 360750이 같은 자리에서 같은 거절을 받는다.

그래서 이 사슬이 반복된다.

```
매일 통과할 수 없는 후보 제안 → 거절 → 3건 누적 → 정지 → 사람이 재개 → 반복
```

## 문제의 정의

정지 자체는 안전장치가 제 역할을 한 것이다. **자동 전략이 매일 정책 밖의 주문을 요구하고 있다는 것은
사람이 알아야 할 사실이다.** 그러나 그 사실을 전달하는 수단이 "거래 전면 정지"인 것은 과하다 — 실제로
위험한 일은 아무것도 일어나지 않았고, 오히려 한도가 정확히 작동하고 있었다.

핵심은 지금 구현이 두 가지 다른 상황을 **같은 사실**로 기록한다는 것이다.

| 상황 | 의미 | 지금 기록 |
|---|---|---|
| 주문을 시도했는데 한도가 막았다 | 무언가 잘못 계산했거나 시장이 움직였다 | `rejected` |
| 한 주도 넣을 자리가 없었다 | 제안 자체가 성립하지 않는다 | `rejected` |

`_plan_buy`는 한 주도 살 수 없을 때도 거절 주문 행을 만든다(`engine.py`의 `quantity <= 0` 분기).
연속 거절 규칙은 그 행을 센다.

## 결정

### 1. 한 주도 들어가지 못하면 거절 주문을 만들지 않는다

가장 빡빡한 한도의 잔여 용량으로 **한 주도 살 수 없으면** 그 후보는 계획하지 않는다. 거절 주문 행을
만들지 않고 "자리 없음"으로 남긴다.

경계를 "잔여 0"이 아니라 "한 주"로 두는 이유는 실측이다 — 실제로 막힌 상황은 잔여 37,787원에 한 주가
177,885원이었다. 잔여가 0인 경우만 가르면 현실을 놓친다(초안은 그렇게 적었고 구현이 그것을 잡았다,
아래 §구현).

주문 1건 금액 한도로 0주가 되는 경우(`ORDER_AMOUNT`)는 다른 규칙이므로 이번 범위가 아니다.

### 2. 사실은 사라지지 않는다 — 다른 이름으로 남는다

"자리 없음"은 조용히 버리지 않는다. 계획 실행 결과에 사유와 종목을 담아 남기고, 자동매매 이벤트로
기록한다. 사유 코드는 `NO_CAPACITY`이며 어떤 한도가 막았는지(`RISK_UNCLASSIFIED_EXPOSURE` 등)를 함께
적는다.

**이것이 이 결정의 핵심 조건이다.** 거절을 세지 않기로 하면서 사실까지 지우면, 전략이 매일 불가능한
것을 요구하는 상태가 아무 흔적 없이 지나간다.

### 3. `RISK_CONSECUTIVE_REJECTS`가 세는 대상은 그대로다

규칙 자체는 손대지 않는다. 정책 §3의 "연속 주문 거절 3건"은 유지되며, 다만 **거절 주문 행이 만들어지는
조건**이 결정 1로 좁아진다. 정책 문구를 고치지 않고 구현이 정책의 "거절"을 더 정확히 해석하는 것이다.

### 4. 반복되는 자리 없음은 알린다

같은 종목이 같은 한도로 계속 자리가 없으면 그것은 전략 설정 문제다. `NO_CAPACITY`를 외부 알림 대상에
넣되 **매 슬롯마다 보내지 않는다** — 거래일당 종목별 1회로 묶는다. 하루 25번 같은 경고를 보내면 읽지
않게 되고, 읽지 않는 알림은 없는 알림과 같다(ADR-0014).

### 5. 모의 전용이다

### 6. 연속 거절은 마지막 재개 이후부터 센다 (2026-09-01 추가 승인)

`RISK_CONSECUTIVE_REJECTS`에는 **빠져나올 길이 없었다.** 3건이 되면 계획이 막히고, 막히면 새 주문이
만들어지지 않으므로 선두의 거절 연속이 영원히 유지된다. 실제로 재개해도 다음 계획에서 즉시 다시
멈췄다(2026-09-01 실측). 정지 규칙에 복구 경로가 없으면 남는 방법은 DB를 직접 고치는 것뿐이다.

정책의 숫자(3건)는 그대로 두고 **무엇부터 세는지**만 정한다. 사람이 자동매매를 `running`으로 올린
시점이 "지금은 괜찮다"고 확인한 시점이므로, 연속 거절은 그 이후 주문만 센다.

## 이 결정이 고치지 않는 것

**ETF 배분 전략은 여전히 의도한 일을 하지 못한다.** 미분류 한도가 NAV 10%인 한 이 전략이 담을 수 있는
것은 사실상 한 종목이며, 나머지는 자리가 없다. 이 문서는 **그 상태가 거래를 멈추지 않게** 할 뿐
전략을 고치지 않는다.

전략을 실제로 살리려면 둘 중 하나가 필요하고 둘 다 별도 결정이다.

- ETF에 업종 사실을 부여하는 원천을 만든다(잘못 분류하면 한도가 헐거워지므로 데이터 계약이 필요하다).
- 업종 분류가 있는 KOSPI200 종목 기반 전략으로 실가동을 옮긴다.

## 결과

- 통과할 수 없는 후보가 거래를 멈추지 않는다.
- 전략이 불가능한 것을 요구하는 사실은 `NO_CAPACITY`로 계속 보인다.
- `RISK_CONSECUTIVE_REJECTS`는 본래 잡으려던 것(시도가 반복해서 막히는 상황)에 집중한다.
- 비용: 위험 엔진의 분기 하나, 새 사유 코드, 계획 결과 형식, 알림 묶기.

## 대안

### A. 정책에 시간 창을 넣는다 ("하루 안에 연속 3건")

가장 작아 보이지만 **정책 변경**이며, 사흘 걸쳐 매일 거절되는 상태가 정상으로 취급된다. 채택하지
않는다 — 정책은 구현을 편하게 하려고 고치지 않는다.

### B. 전략 유니버스에서 문제 종목을 뺀다

133690을 빼도 360750이 같은 자리를 요구한다. 증상만 옮긴다.

### C. 전략이 잔여 한도를 미리 알고 제안하지 않는다

한도 계산이 위험 엔진과 전략 두 곳에 생긴다. 어긋나면 조용히 틀리고, 어느 쪽이 맞는지 판단할 근거가
없다. 위험검사는 한 곳이어야 한다.

### D. 아무것도 하지 않는다

현 상태다. 사람이 며칠에 한 번 정지를 풀어 주는 운영이 되며, 그 반복이 진짜 정지 사유를 가린다.

## 승인이 필요한 질문 (모두 답을 받았다 — 2026-09-01)

1. **결정 1의 경계를 받아들이는가?** "용량 0"과 "용량은 있으나 못 들어감"을 가르는 것이 이 문서의
   전부다. 다르게 가르고 싶은 지점이 있는가.
2. **`NO_CAPACITY`를 알림으로 보내는가?** 초안은 거래일당 종목별 1회를 제안한다. 보내지 않으면 감사
   기록에만 남는다.
3. **오늘의 정지를 어떻게 푸는가?** 구현 전에 수동으로 재개하면 같은 거절이 다시 쌓인다. 구현 후에
   재개하는 것이 초안의 권고다.

## 미측정

- 결정 1이 실제로 거절 건수를 줄이는지. 구현 후 며칠 관측해야 한다.
- 매도 경로에도 같은 구분이 필요한지. 지금까지 매도는 보유 수량 안에서만 계획돼 이 문제가 관측되지
  않았다.

## 재검토 조건

- ETF에 업종 사실이 생기면 미분류 한도가 더는 이 전략을 묶지 않으므로 이 결정의 전제가 바뀐다.
- `NO_CAPACITY`가 특정 종목에서 계속 쌓이면 그것은 전략을 고칠 신호이지 이 규칙을 완화할 신호가 아니다.

## 구현 (2026-09-01)

- 순수 판정: `domain/risk/engine.py`에 `NoCapacity`를 더하고 `RiskEvaluation.no_capacity`로 돌려준다.
  거절 주문 행을 만들지 않는다.
- 사실 기록: 새 자동매매 이벤트 유형 `no_capacity`(리비전 `20260901_0033`), 사유 `NO_CAPACITY`,
  상세는 `"<종목> <규칙>"`. 저장소가 **거래일당 종목별 1회**만 남기고 남겼는지를 돌려준다.
- 알림: `no_capacity`가 대상이며 심각도는 경고다. 본문은 종목과 막은 규칙을 함께 적는다 — 그것이
  없으면 받아도 할 수 있는 일이 없다. 투영은 저장된 상세를 종목·규칙으로 되돌려 쓴다.
- 결정 6: `recent_states_query`가 마지막 `running` 전이 이후 주문만 본다.

### 초안의 경계가 틀렸다 (실측이 잡음)

초안 결정 1을 `available <= 0`으로 구현했는데 **실제로 막힌 상황이 그 모양이 아니었다.**

```
미분류 한도  1,004,837
사용         967,050
잔여         37,787      ← 0이 아니다
133690 1주   177,885     ← 한 주도 못 산다
```

잔여가 0이 아니어서 분기가 발동하지 않고 거절이 계속 났다. 승인받은 개념은 "자리가 없으면 거절이
아니다"였고, 그 개념의 정확한 표현은 **"가장 작은 주문 한 주도 들어가지 못한다"**
(`int(available / limit_price) <= 0`)다. 새 결정이 아니라 초안의 표현 오류를 개념에 맞춘 것이다.

### 실데이터 검증

```
14:21:13  --from-signal → created ... rejected=0
14:21:13  no_capacity  "133690 RISK_UNCLASSIFIED_EXPOSURE"
자동매매   running (정지 해제됨)
```

거절 주문이 생기지 않고 사실은 남았으며, 결정 6으로 오늘의 정지가 실제로 풀렸다.

### 미측정

- 알림이 실제로 도착하는지. 폴러가 30초 주기로 돌므로 곧 확인된다.
- `per_order_quantity == 0`(NAV 5%로 한 주도 못 사는 경우)은 지금도 `ORDER_AMOUNT` 거절이다. 같은
  "주문할 수 없음"이지만 다른 규칙이라 이번 범위에 넣지 않았다. 관측되면 다시 본다.
