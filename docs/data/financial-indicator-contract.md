# 재무 지표 정의 계약

- 상태: 구현 기준
- 작성일: 2026-08-17
- 승인: 사용자가 2026-08-17에 재무 기반 지표(성장성·수익성·안정성) 우선, ROE 지배주주 기준과 이 계약을 구현 기준으로 승인. 같은 날 상장주식수 버전 사실 저장과 가치지표(EPS 원문·PER·시가총액, BPS·PBR은 우선주 반영 설계 확정 시 후속)를 추가 승인
- 개정 승인: 사용자가 2026-08-21에 손익 계정의 `IS` → `CIS` 우선순위 조회를 승인(유니버스 실수집에서 198종목 중 147종목이 포괄손익계산서만 제출함을 확인)
- 개정 승인: 사용자가 2026-08-21에 (1) 금융업의 매출액·영업이익 기반 지표 미제공과 업종 사유 명시, (2) 기본주당이익의 계속영업 + 중단영업 복원, (3) 표준계정을 쓰지 않는 표기의 fail-closed 유지를 승인
- 관련 계약: [재무제표 데이터 계약](financial-statement-data-contract.md)
- 관련 로드맵: [구현 로드맵](../plan/implementation-roadmap.md) 4단계

## 목적

저장된 재무제표 사실에서 성장성·수익성·안정성 지표를 파생할 때의 수식, 입력 계정, 기준과
실패 처리를 화면과 백엔드가 공유하는 단일 정의로 고정한다.

## 원칙

1. 지표는 [재무제표 데이터 계약](financial-statement-data-contract.md)의 저장 사실에서만 계산한다.
   외부 계산값(예: KIS 제공 PER)을 지표로 노출하지 않는다.
2. 백엔드가 조회 시점에 현재 버전 보고서에서 계산하고, 응답은 수식·사업연도·근거 접수번호
   (`rcept_no`)·입력 계정과 금액을 항상 포함한다. 화면은 이 응답만 표시하며 자체 계산하지 않는다.
3. 연결(CFS) 기준이 기본이며 응답에 `fs_div`를 항상 명시한다. 개별(OFS) 조회도 같은 정의를
   사용하되 개별 재무제표에 없는 계정(지배주주 구분)은 지표를 만들지 않는다.
4. 지표는 연간 사업보고서(`11011`)에서만 계산한다. 분·반기 보고서는 실적 표시용이며 연환산
   추정을 하지 않는다.
5. 각 지표는 같은 보고서 버전의 당기·전기 금액만 입력으로 사용한다. 서로 다른 보고서를 섞지
   않으므로 정정 공시가 반영되면 지표도 그 최신 버전 기준으로 바뀐다.
6. 필요한 계정이 없거나 금액이 없거나 분모가 0이면 해당 지표는 값을 만들지 않고 사유 코드와
   함께 빈 값으로 노출한다(fail-closed). 추정·보간·대체 계정 사용은 없다.

## 입력 계정

보고서 안에서 재무제표 구분(`sj_div`)과 표준 계정 ID(`account_id`)로 식별한다. 같은 구분에
같은 계정 ID가 두 번 이상 나타나면 모호하므로 사용하지 않는다(fail-closed).

손익 계정은 회사가 고른 제출 형식에 따라 손익계산서(`IS`) 또는 포괄손익계산서(`CIS`)에 실린다.
따라서 `IS`를 먼저 찾고 없으면 `CIS`에서 찾는다(2026-08-21 사용자 승인). 규칙 세 가지:

1. 순서는 고정이다. `IS`에 계정이 있으면 `CIS`를 보지 않는다. 두 구분에 모두 있는 회사(당기순이익 등)에서 값이 흔들리지 않게 하기 위한 것이다.
2. 모호성 판정은 실제로 사용한 구분 안에서만 한다. `IS`에 1행, `CIS`에 여러 행이면 `IS` 값을 쓴다.
3. 응답의 입력 계정은 **실제로 사용한 `sj_div`**를 담는다. 어느 재무제표에서 읽었는지 감출 수 없다. 두 구분 모두 없으면 `MISSING_ACCOUNT`이며 이때 표기는 선언 순서의 첫 구분(`IS`)이다.

이 정의는 화면과 백테스트가 공유한다. 종합 순위 전략은 `compute_annual_indicators`와
`basic_eps`를 그대로 호출하며 자체 계산식을 두지 않는다([백테스트 계약 §v3](backtest-strategy-contract.md)).

자본변동표(`SCE`)와 현금흐름표(`CF`)에도 당기순이익이 나타나지만 사용하지 않는다. `SCE`는 같은
계정 ID를 자본 구성요소별 여러 행이 공유해 집계가 틀릴 수 있음을 실측했다.

| 입력 | `sj_div` | `account_id` |
|---|---|---|
| 매출액 | `IS` → `CIS` | `ifrs-full_Revenue` |
| 영업이익 | `IS` → `CIS` | `dart_OperatingIncomeLoss` |
| 당기순이익 | `IS` → `CIS` | `ifrs-full_ProfitLoss` |
| 지배주주순이익 | `IS` → `CIS` | `ifrs-full_ProfitLossAttributableToOwnersOfParent` |
| 자산총계 | `BS` | `ifrs-full_Assets` |
| 부채총계 | `BS` | `ifrs-full_Liabilities` |
| 자본총계 | `BS` | `ifrs-full_Equity` |
| 지배기업 소유주지분 | `BS` | `ifrs-full_EquityAttributableToOwnersOfParent` |
| 유동자산 | `BS` | `ifrs-full_CurrentAssets` |
| 유동부채 | `BS` | `ifrs-full_CurrentLiabilities` |

## 지표 정의

모든 지표의 단위는 퍼센트이며 소수 둘째 자리로 반올림(ROUND_HALF_UP)한다. `당기`는
`thstrm_amount`, `기초`는 같은 보고서의 `frmtrm_amount`(전기 기말)다.

### 성장성

| 키 | 이름 | 수식 |
|---|---|---|
| `revenue_growth` | 매출액증가율 | (당기 매출액 − 전기 매출액) ÷ \|전기 매출액\| × 100 |
| `operating_income_growth` | 영업이익증가율 | (당기 영업이익 − 전기 영업이익) ÷ \|전기 영업이익\| × 100 |
| `net_income_growth` | 순이익증가율 | (당기 당기순이익 − 전기 당기순이익) ÷ \|전기 당기순이익\| × 100 |

### 수익성

| 키 | 이름 | 수식 |
|---|---|---|
| `operating_margin` | 영업이익률 | 당기 영업이익 ÷ 당기 매출액 × 100 |
| `net_margin` | 순이익률 | 당기 당기순이익 ÷ 당기 매출액 × 100 |
| `roe` | ROE(지배주주) | 당기 지배주주순이익 ÷ ((기초 지배기업 소유주지분 + 기말 지배기업 소유주지분) ÷ 2) × 100 |
| `roa` | ROA | 당기 당기순이익 ÷ ((기초 자산총계 + 기말 자산총계) ÷ 2) × 100 |

### 안정성

| 키 | 이름 | 수식 |
|---|---|---|
| `debt_ratio` | 부채비율 | 당기 부채총계 ÷ 당기 자본총계 × 100 |
| `current_ratio` | 유동비율 | 당기 유동자산 ÷ 당기 유동부채 × 100 |

### 가치

가치지표는 서로 기준 시점이 다른 세 가지 입력(배치 시세, 최근 연간 보고서, 상장주식수)을
조회 시점에 결합하므로, 응답은 가격 기준시각·재무 기준(사업연도와 `rcept_no`)·주식수
기준시각을 항상 별도로 명시한다. KIS 시세 응답이 제공하는 `per`·`pbr`·`eps`·`bps` 외부
계산값은 산식·기준일을 증명할 수 없으므로 지표로 노출하지 않는다.

| 키 | 이름 | 단위 | 수식 |
|---|---|---|---|
| `eps` | 기본주당이익 | 원 | 최근 연간 보고서의 `기본주당이익`(`IS` → `CIS`, `ifrs-full_BasicEarningsLossPerShare`) 원문 값. 없으면 아래 복원 규칙을 따르며, 순이익 ÷ 주식수 파생은 하지 않는다 |
| `per` | PER | 배 | 현재가 ÷ 최근 연간 기본주당이익 |
| `market_cap` | 시가총액(보통주) | 원 | 현재가 × 보통주 상장주식수 |

- 지배주주순이익을 보통주 상장주식수로 나눈 파생 EPS는 우선주가 있는 종목에서 공시
  기본주당이익과 다르므로 계산하지 않는다(실측: 삼성전자 파생 7,570.79원 vs 공시 6,605원).
- BPS·PBR은 보통주 상장주식수만으로는 우선주 자본이 분리되지 않아 왜곡되므로(실측 파생
  BPS 72,578원) 우선주 반영 설계가 승인될 때까지 계산하지 않고 화면에서 사유와 함께 빈
  값으로 둔다.
- PER은 최근 연간 실적 기준이다. 당해 반기 대비 전년 반기 데이터가 없어 TTM은 계산하지
  않는다.
- 실패 사유는 기존 코드에 `MISSING_QUOTE`(저장된 시세 없음)와
  `MISSING_SHARE_COUNT`(저장된 상장주식수 없음)를 추가해 사용한다.

## 상장주식수 사실 저장

- 출처는 KIS 현재가 응답(`FHKST01010100`)의 `lstn_stcn`이며 시세 수집 시 함께 관측한다.
- `reference.listed_share_count`에 종목별 버전 사실로 저장한다: 논리 키 = `instrument_id`,
  현재 버전은 `superseded_at IS NULL` 1행, 값이 바뀌면(증자·소각) 이전 버전을 보존한 새
  버전을 만들고, 같은 값 재관측은 버전을 늘리지 않고 최신 관측 시각 근거만 갱신한다.
- 행은 `share_count`(양수), 출처, 관측 기준시각(`as_of`), 수신 시각, `version`,
  `valid_from`, `superseded_at`, 원본 응답 참조를 포함한다.
- ETF를 포함한 모든 수집 종목의 상장주식수(ETF는 상장좌수)를 저장하되, 가치지표는 주식만
  대상으로 한다.

## 실적 원문 값

지표와 함께 파생이 아닌 원문 금액(매출액, 영업이익, 당기순이익, 지배주주순이익, 자산총계,
부채총계, 자본총계)을 계정 ID·재무제표 구분과 함께 제공한다. 실적 차트와 KPI는 이 원문 값을
사용하고 보정·환산하지 않는다.

## 기본주당이익 복원 규칙 (2026-08-21 사용자 승인)

총 기본주당이익을 표시하지 않고 계속영업·중단영업으로 나눠 표시하는 회사가 있다(2025-07-31
시점 실측 14종목). 순서는 다음과 같다.

1. `ifrs-full_BasicEarningsLossPerShare`가 있으면 그 값을 쓴다.
2. 없으면 `...FromContinuingOperations` + `...FromDiscontinuedOperations`를 더한다. IFRS 표기에서
   총액 = 계속영업 + 중단영업이고 둘 다 공시 원문이므로 순이익 ÷ 주식수 같은 파생이 아니다.
3. **중단영업 관련 행이 보고서에 아예 없으면** 계속영업 값이 총액이다. 중단영업이 없다는 뜻이며
   실측으로 교차 확인했다(삼성중공업·롯데쇼핑·효성중공업은 중단영업 계정이 0건).
4. **중단영업 행이 있는데 금액이 비어 있으면** 0으로 가정하지 않고 fail-closed다(`MISSING_AMOUNT`).
   실측 사례가 있다(씨에스윈드는 중단영업 6행 전부 금액 공란).
5. 표준 계정 ID를 쓰지 않고 계정명만으로 표기하는 회사(실측 5종목, 예: `보통주 기본/희석주당순이익`)는
   계속 fail-closed다. 계정명 문자열 매칭은 우선주 행(`구형우선주 기본/희석주당순이익`)과 섞일 수
   있고 표기가 회사마다 달라 오식별 위험이 크다.

계속영업만 쓰는 선택은 하지 않는다. 실측(태광산업)에서 계속영업 +33,256 / 중단영업 −55,240으로
실제 적자 기업이 흑자로 보이며 이익수익률 순위가 뒤집힌다.

## 금융업 지표 기준 (2026-08-21 사용자 승인)

금융업은 매출액·영업이익 표준계정을 쓰지 않는다. 실측으로 업종마다 손익 구조가 다르고
(보험=투자손익·보험서비스결과, 증권=영업외손익 중심, 은행지주=보험수익·이자수익,
카드=순리스손익·금융상품손익), 같은 이름의 계정이 다른 금액으로 동시에 존재하는 경우도 있다
(KB금융의 `dart_OperatingIncomeInsurance` 12.4조 vs `ifrs-full_InsuranceRevenue` 11.7조).

- **업종별 top-line 매핑을 만들지 않는다.** 어느 계정을 매출액으로 볼지는 회계 판단이며, 우리가
  고르면 원문에 없는 값을 만드는 것이 된다.
- 매출액·영업이익을 입력으로 쓰는 지표(매출액증가율·영업이익증가율·영업이익률·순이익률)는 값 없이
  `SECTOR_ACCOUNT_BASIS` 사유로 응답한다. 계정 누락(`MISSING_ACCOUNT`)과 구별해야 한다 — 원인이
  데이터 결손이 아니라 업종 회계이기 때문이다.
- 당기순이익·자본·자산 기반 지표(순이익증가율·ROE·ROA·부채비율)와 가치지표는 금융업에서도 그대로
  계산한다. 실측으로 삼성화재 ROE 10.96·PER 13.10, KB금융 ROE 9.98·PER 10.38이 나온다.
- 업종 판정은 [종목 유니버스 계약](stock-universe-data-contract.md)의 KOSPI200 업종 코드 `6`을
  쓴다. 실측(2026-08-21)으로 이 코드의 22종목이 전부 보험·증권·은행지주·카드이며 다른 업종이 섞이지
  않았다. 업종명 원천이 없어도 코드 자체가 판정 근거다.
- 사유 코드 치환은 값을 만들지 않는다. 금액 결측·계정 모호 같은 다른 실패는 업종 문제가 아니므로
  사유를 바꾸지 않는다.

## 실패 사유 코드

| 코드 | 의미 |
|---|---|
| `MISSING_ACCOUNT` | 보고서에 필요한 계정이 없음 |
| `AMBIGUOUS_ACCOUNT` | 같은 구분에 같은 계정 ID가 여러 번 나타남 |
| `MISSING_AMOUNT` | 필요한 기간의 금액이 원문에서 비어 있음 |
| `ZERO_DENOMINATOR` | 분모가 0 |
| `SECTOR_ACCOUNT_BASIS` | 발행사가 업종 회계상 그 계정을 쓰지 않음(금융업의 매출액·영업이익). 데이터 결손이 아니다 |

## 필수 조회 계약

- `GET /api/fundamentals/instruments/{symbol}/indicators?fs_div=`: 연간 보고서별 지표와 실적
  원문 값을 사업연도 오름차순으로 반환한다. `fs_div` 기본값은 `CFS`다.
- 연도 항목은 `bsns_year`, `reprt_code`, `rcept_no`, `currency`, `version`을 포함한다.
- 지표 항목은 키, 이름, 분류(성장성·수익성·안정성), 수식 문자열, 입력 계정(이름, `sj_div`,
  `account_id`, 기간, 금액), 값 또는 실패 사유 코드를 포함한다.
- 같은 응답의 `valuation` 블록이 가치지표를 제공한다. 연간 보고서가 하나도 없으면 `null`
  이고, 있으면 기준 블록(가격: 값·기준시각·출처, 주식수: 값·기준시각·출처·버전, 재무:
  사업연도·유형·구분·`rcept_no`·버전 — 없는 기준은 `null`)과 항목별 수식·값 또는 실패
  사유를 포함한다.
- 통화가 `KRW`가 아니어도 환산하지 않고 통화를 그대로 노출한다.

## 검증 시나리오

1. 고정 입력으로 각 지표의 수치가 손으로 계산한 값과 일치한다.
2. 필요한 계정·금액이 없거나 분모가 0이면 값 없이 사유 코드가 반환된다.
3. 같은 계정 ID가 같은 구분에 중복되면 해당 지표는 모호 사유로 계산되지 않는다.
4. 실제 삼성전자 저장 데이터로 계산한 지표를 DART 원문 금액 기반 수동 계산과 대조한다.
5. 개별(OFS) 조회에서 지배주주 계정이 없는 ROE는 `MISSING_ACCOUNT`로 빈 값이다.
6. 같은 상장주식수 재관측은 버전을 늘리지 않고, 값이 바뀌면 이전 버전을 보존한 새 버전이
   된다.
7. 실제 KIS 모의환경 수집으로 저장한 시세·상장주식수와 공시 기본주당이익으로 계산한
   PER·시가총액을 수동 계산과 대조한다. 시세·주식수가 없으면 해당 항목만 사유와 함께 빈
   값이다.
