# ADR-0005: Valkey 기반 KIS 토큰·호출 조정

- 상태: 승인
- 제안일: 2026-08-14
- 승인일: 2026-08-14
- 관련 결정: [ADR-0001](0001-modular-monolith.md), [ADR-0003](0003-data-architecture.md)
- 관련 정책: [시장 데이터 및 시점 정책](../spec/market-data-policy.md)

## 배경

KIS 시장 데이터 수집기는 접근 토큰과 요청 간격을 프로세스 메모리에서 관리한다. 같은 프로세스 안에서는 토큰을 재사용하고 호출을 직렬화하지만, 일회성 컨테이너나 여러 worker는 서로의 상태를 알 수 없다.

2026-08-14 실제 모의환경 검증에서 첫 worker가 발급한 토큰을 두 번째 worker가 재사용하지 못했다. 두 번째 프로세스의 즉시 토큰 발급은 HTTP `403`으로 거절됐고 보호 구간 이후에야 성공했다. 프로세스마다 별도의 호출 시계를 사용하면 여러 worker가 동시에 모의 REST 한도를 넘을 수도 있다.

KIS 공식 문서는 다음 운영 제약을 명시한다.

- [접근토큰발급(P)](https://apiportal.koreainvestment.com/apiservice-apiservice%3F/tryitout/H0STCNT0): 접근 토큰 유효기간은 24시간이고 1일 1회 발급이 원칙이며, 6시간 이내 갱신 요청에는 기존 발급키를 반환한다.
- [API 호출 유량 안내](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000001/post/d0d1a83f-6f8d-4437-9700-6d26702fd989): 2026-04-20 기준 모의투자 REST는 초당 1건이고 접근토큰 발급도 초당 1건이다.

따라서 주기 수집을 시작하기 전에 같은 KIS 환경과 자격증명을 사용하는 프로세스들이 토큰 발급과 REST 호출 순서를 함께 조정해야 한다.

## 결정

기존 Valkey를 KIS 접근 토큰의 단기 공유 캐시와 분산 조정 저장소로 사용한다. PostgreSQL은 계속 영속 원본이며 Valkey의 토큰이나 잠금 상태를 업무 데이터로 취급하지 않는다.

### 공유 범위

- 조정 단위는 `KIS 환경 + App Key 자격증명 지문`이다.
- 지문은 App Secret을 키로 하고 환경과 App Key를 메시지로 하는 HMAC-SHA-256으로 만든다. 원본 App Key와 App Secret은 Valkey 키, 로그와 오류에 포함하지 않는다.
- 모의투자와 실전투자는 서로 다른 키 공간을 사용한다.
- 메모리 캐시는 Valkey 조회를 줄이는 1차 캐시로 유지하되, 프로세스 간 기준은 Valkey로 통일한다.

### 토큰 캐시와 수명

- 캐시 값에는 접근 토큰과 KIS가 반환한 절대 만료시각만 저장한다.
- 유효성 판단에는 만료 1분 전 안전 여유를 적용한다.
- Valkey TTL은 `KIS 만료시각 - 현재시각 - 1분`으로 설정하며 0 이하이면 저장하지 않는다.
- 캐시 값, Authorization 헤더와 자격증명은 구조화 로그, 예외 메시지, PostgreSQL 원본 응답에 기록하지 않는다.
- Valkey AOF에 남는 토큰은 서버 측 단기 비밀정보로 취급한다. 로컬 Compose의 호스트 포트는 `127.0.0.1`에만 바인딩하고 운영 배포에서는 Valkey 포트를 공개하지 않는다. volume 접근 권한은 운영 서버 관리자에게만 허용하며 Valkey volume을 장기 백업 대상에서 제외한다.

### 단일 발급

1. 프로세스 메모리와 Valkey에서 유효한 토큰을 순서대로 확인한다.
2. 유효한 토큰이 없으면 소유자 난수를 포함한 Valkey 잠금을 `SET NX PX`로 획득한다.
3. 잠금 획득 후 공유 캐시를 다시 확인한 프로세스만 KIS 토큰을 발급한다.
4. 토큰 저장 후 소유자 값이 일치할 때만 원자적으로 잠금을 해제한다.
5. 다른 프로세스는 제한된 시간 동안 공유 캐시를 확인한다. 잠금 보유 프로세스가 종료되면 잠금 TTL 이후 다음 프로세스가 복구한다.
6. 대기 제한을 넘거나 Valkey를 사용할 수 없고 유효한 메모리 토큰도 없으면 추가 발급으로 우회하지 않고 수집을 실패 처리한다.

잠금과 대기에는 유한한 제한 시간을 두며 무한 재시도하지 않는다. 이 실패 폐쇄 방식은 일시적인 수집 누락보다 중복 토큰 발급과 호출 폭주를 더 위험하게 본다.

### 분산 REST 호출 게이트

- 같은 조정 단위의 인증 및 시세 REST 요청은 Valkey 서버 시각을 기준으로 다음 호출 가능 시점을 원자적으로 예약한다.
- 모의환경은 모든 KIS REST 호출 사이에 최소 1.05초를 유지한다.
- 프로세스 내부 요청 잠금도 유지해 동일 프로세스의 순서를 단순하게 보장한다.
- 실전환경은 현재의 보수적 간격을 유지한다. 실전 호출량 상향은 계좌 단위 제한과 주문 우선순위를 포함한 별도 ADR에서 결정한다.
- Valkey 장애 시 유효한 메모리 토큰이 있어도 새 외부 요청은 보내지 않는다. 여러 프로세스가 각자 호출해 제한을 넘지 않도록 수집을 실패 처리한다.

### 구현 경계

- KIS HTTP 어댑터는 토큰 저장소와 호출 게이트를 작은 포트로 주입받는다.
- Valkey 구현은 `redis.asyncio` 클라이언트를 사용하고 애플리케이션 종료 시 자신이 만든 연결을 닫는다.
- worker 조립 코드가 런타임 설정의 Valkey URL로 실제 구현을 구성한다.
- 단위 테스트는 메모리 대역으로 만료, 잠금 경쟁, 대기 제한과 장애 동작을 검사한다.
- 통합 테스트는 실제 Valkey에서 서로 다른 두 클라이언트가 토큰을 한 번만 발급하고 호출 간격을 공유하는지 검사한다.

## 대안

### 프로세스별 메모리 캐시 유지

구현은 단순하지만 실제 검증에서 독립 프로세스의 중복 발급이 거절됐다. 다중 worker의 호출 한도도 조정하지 못하므로 채택하지 않는다.

### 토큰 파일 공유

단일 호스트에서는 가능하지만 컨테이너 간 잠금, 원자적 갱신, TTL과 권한 관리가 어렵고 향후 여러 프로세스 배치에 맞지 않아 채택하지 않는다.

### PostgreSQL에 토큰 저장

트랜잭션 잠금을 사용할 수 있지만 단기 비밀정보와 고빈도 호출 조정이 영속 업무 데이터 저장소에 결합된다. 기존 Valkey의 단기 캐시 역할과 중복되므로 채택하지 않는다.

### Valkey 장애 시 프로세스별 발급으로 우회

가용성은 높아지지만 장애 순간에 여러 프로세스가 동시에 토큰과 시세를 요청할 수 있다. KIS 제한 위반 가능성이 커지므로 채택하지 않는다.

## 결과

- 정상 상태에서는 동일 자격증명의 모든 worker가 하나의 접근 토큰을 재사용한다.
- 프로세스가 늘어나도 토큰 발급과 모의 REST 호출 한도를 하나의 조정 단위로 지킨다.
- Valkey 장애 중에는 시장 데이터 수집이 중단될 수 있지만 중복 발급과 호출 폭주는 발생하지 않는다.
- Valkey에 민감한 접근 토큰이 저장되므로 네트워크, volume, 백업 경계가 비밀정보 기준을 따라야 한다.
- 실전 주문의 호출 우선순위와 장애 정책은 이 결정에 포함하지 않는다.

## 구현·검증 기록

2026-08-14에 메모리 1차 캐시, Valkey 공유 토큰, 분산 잠금과 호출 게이트를 구현했다. 실제 Valkey 통합 테스트에서 두 coordinator의 동시 토큰 요청이 발급 1회로 수렴하고, 만료 1분 안전 여유, 잠금 TTL 복구, 프로세스 간 호출 간격과 Valkey 장애 시 issuer 미호출을 확인했다.

실제 KIS 모의환경에서는 첫 독립 worker가 공유 토큰을 저장한 뒤 다음 독립 worker가 `KIS shared access token reused`를 기록했다. 두 번째 worker는 `/oauth2/tokenP`를 호출하지 않고 삼성전자와 KODEX 200의 현재가·일봉 요청 4건을 모두 `200`으로 완료했다. Valkey 토큰 항목은 1개였고 원본 API 응답의 인증 필드는 0건이었다.

## 완료 기준

- 두 독립 프로세스가 같은 자격증명으로 동시에 시작해도 토큰 발급 HTTP 요청은 한 번만 발생한다.
- 두 독립 프로세스의 모의 REST 호출 사이가 각각 1.05초 이상이다.
- 만료 1분 전부터 새 토큰을 한 번만 발급하고 모든 프로세스가 갱신 결과를 사용한다.
- 잠금 소유 프로세스 종료 후 TTL이 지나면 다른 프로세스가 복구한다.
- Valkey 장애 시 유효한 공유 조정 없이 KIS 요청을 보내지 않고 비밀정보 없는 오류를 기록한다.
- Compose와 배포 설정에서 Valkey가 외부 네트워크에 공개되지 않는다.
- 실제 KIS 모의환경에서 첫 worker 이후 두 번째 worker가 `/oauth2/tokenP`를 다시 호출하지 않고 삼성전자와 KODEX 200 수집을 완료한다.
- Ruff, basedpyright, 백엔드 테스트, 실제 Valkey 통합 테스트, Compose 계약 검사와 문서 검사가 통과한다.

## 재검토 조건

- KIS가 토큰 수명, 발급 주기 또는 호출 유량 정책을 변경한다.
- 여러 서버 또는 여러 계좌로 배포 범위가 확대된다.
- 실전 주문과 시장 데이터가 같은 호출 한도를 경쟁하게 된다.
- Valkey 고가용성이나 별도의 비밀정보 저장소가 필요해진다.
