# 자동매매 웹 프로그램 구현 로드맵

- 상태: 승인
- 작성일: 2026-08-11
- 승인일: 2026-08-11
- 대상: 개인 본인 계좌를 사용하는 단일 사용자 웹 프로그램
- 기술 스택: [상세 기술 스택](../architecture/tech-stack.md)

## 1. 구현 전략

이 프로젝트는 다음 순서로 구현한다.

```text
범위·안전 기준
    ↓
프로젝트 기반
    ↓
신뢰할 수 있는 시장 데이터
    ↓
읽기 전용 분석 화면
    ↓
백테스트와 규칙형 전략
    ↓
모의 자동매매
    ↓
AI 분석·예측
    ↓
소액 실전매매
    ↓
운영 안정화
```

AI나 실전 주문부터 시작하지 않는다. 데이터의 시점 정확성과 주문 안전성을 먼저 확보하고, 모든 전략은 거래비용을 포함한 백테스트와 모의투자를 통과한 뒤 다음 단계로 이동한다.

## 2. 초기 결정

- 기본 증권사: 한국투자증권 KIS Developers
- 기업 재무·공시: 금융감독원 OpenDART
- 국내 ETF 보완 데이터: KRX/KIND 또는 이용권한이 확인된 데이터 공급자
- 초기 사용자: 본인 한 명
- 초기 거래 대상: 국내주식과 국내 ETF
- 후속 거래 대상: 미국주식과 미국 ETF
- 초기 주기: 일봉 기반, 주간 또는 월간 리밸런싱
- 초기 주문 환경: 한국투자증권 모의투자
- AI 주문 권한: 없음
- 주문 승인 주체: 고정된 위험관리 규칙

키움 REST API는 한국투자증권 API에서 ETF 데이터 공백이 실제로 확인된 경우 후속 증권사로 검토한다.

## 3. 마일스톤

| 마일스톤 | 포함 단계 | 관찰 가능한 결과 |
|---|---|---|
| M0 데이터 기반 | 0~2 | 종목 마스터·현재가·일봉을 안정적으로 수집하고 조회한다. |
| M1 분석 서비스 | 3~5 | 시장, 기업, ETF 정보를 웹에서 탐색하고 순위를 확인한다. |
| M2 모의 자동매매 | 6~7 | 검증된 규칙형 전략이 모의 계좌에서 주문·체결된다. |
| M3 AI 보조 전략 | 8 | 공시 분석과 숫자 시계열 모델이 신호를 보조한다. |
| M4 실전 운영 | 9~10 | 제한된 실전 주문과 운영·복구 체계가 동작한다. |

## 4. 단계별 구현 순서

완료일: 2026-08-11

승인 문서:

- [제품 범위 및 요구사항](../spec/product-scope.md)
- [거래 안전 정책](../spec/trading-safety-policy.md)
- [시장 데이터 및 시점 정책](../spec/market-data-policy.md)
- [모의투자·실전투자 전환 게이트](../spec/paper-to-live-gate.md)

구현 내용:

- 개인 본인 계좌만 연결한다.
- 모의투자와 실전투자의 설정·자격증명·데이터를 구분한다.
- 국내주식·국내 ETF를 첫 거래 범위로 고정한다.
- 거래비용, 세금, 슬리피지 계산 기준을 정한다.
- 종목별·업종별 최대 비중과 일일 손실 한도를 정한다.
- 자동매매 활성화, 일시정지, 비상정지 정책을 정한다.
- 데이터 기준시각과 주문 가능 시각을 정의한다.

완료 기준:

- 실전 주문 없이 제공할 첫 기능 범위가 문서화되어 있다.
- 모의투자에서 실전투자로 이동하기 위한 게이트가 정의되어 있다.

### 1단계: 프로젝트 기반과 보안 구조 (기술 기반 완료 · 디자인 방향 승인)

완료일: 2026-08-11
디자인 승인일: 2026-08-12

디자인 상태:

- 실행 환경, 상태 API, 빈 웹 대시보드와 반응형 동작은 구현·검증됐다.
- 현재 실행 화면은 기능성 프로토타입이고 승인 디자인은 아직 React에 구현되지 않았다.
- 사용자는 Research Grid와 Night Watch 안전 표현을 결합한 [클로드 화면 디자인 사양](../design/claude-design/screen-design-spec.md)을 승인했다.
- 1단계의 과거 QA는 프로토타입 검증 기록이며, 승인 디자인을 구현한 뒤 새 브라우저 QA를 수행한다.
- 3단계 시장 대시보드는 승인된 토큰과 재사용 프리미티브를 기준으로 구현한다.

구현 내용:

- Python FastAPI 백엔드와 TypeScript React 웹을 구성한다.
- PostgreSQL과 데이터베이스 마이그레이션을 구성한다.
- 데이터 수집 및 전략 실행을 담당하는 별도 작업 프로세스를 구성한다.
- 개발·테스트·운영 설정을 분리한다.
- API 키와 계좌정보는 서버에서만 관리한다.
- 타입 검사, 테스트, 빌드를 CI에 연결한다.
- UI 컴포넌트보다 먼저 `docs/` 아래 디자인 시스템 문서를 작성한다.
- 공통 표, 차트, 필터, 상태표시, 오류표시의 UI 규칙을 정한다.

완료 기준:

- 백엔드 상태 확인 API와 빈 웹 대시보드가 실행된다.
- 데이터베이스 마이그레이션이 재현 가능하다.
- 브라우저 코드와 로그에 비밀정보가 노출되지 않는다.
- 타입 검사, 테스트, 프로덕션 빌드가 통과한다.

### 2단계: 증권사 API와 시장 데이터 기반

상태: 진행 중

2026-08-14 첫 수직 슬라이스 완료:

- KIS 모의·실전 호스트 분리, 접근 토큰 캐시와 만료 갱신
- 삼성전자와 KODEX 200의 종목정보·현재가·비수정 일봉 수집

- 실패·성공 수집 상태 기록과 읽기 전용 시장 데이터 API
- 공식 형태 fixture 계약 테스트와 PostgreSQL 반복 수집 통합 테스트
- 모의투자 초당 1건 제한, Docker secret 전달과 반복 검증 런북

- `reference.market_calendar` 마이그레이션, 도메인 판정, 버전 저장·현재/범위/다음/이전 조회와 출처 충돌 기록

- 종목 마스터를 수집하고 국가, 거래소, 통화, 주식·ETF 유형을 정규화한다.
- 현재가, 일봉, 분봉을 수집한다.

```text

```

완료 기준:

- 삼성전자와 대표 ETF의 종목정보, 현재가, 일봉을 조회할 수 있다.
- 반복 수집해도 중복 데이터가 생기지 않는다.
- 데이터의 출처와 기준시각을 확인할 수 있다.
- 수집 실패 후 재실행하면 안전하게 복구된다.

### 3단계: 읽기 전용 시장 대시보드

구현 내용:

- 종목 검색과 관심종목을 제공한다.
- 현재가, 등락률, 거래량을 표시한다.
- 캔들·거래량 차트를 표시한다.
- 이동평균선, RSI, MACD, 볼린저밴드를 표시한다.
- 국내·미국 시장 및 주식·ETF 필터를 제공한다.
- 데이터 지연, 장 상태, 수집 오류를 화면에 표시한다.

완료 기준:

- 브라우저에서 검색, 종목 전환, 기간 전환이 동작한다.
- 증권사 화면과 가격 및 기준시각을 대조할 수 있다.
- 모바일, 태블릿, 데스크톱 화면에서 주요 기능을 사용할 수 있다.

### 4단계: 종목별 기업 분석

구현 내용:

- 종목코드와 DART 기업 고유번호를 매핑한다.
- 재무상태표, 손익계산서, 현금흐름표를 수집한다.
- 최근 3~5년 성장성, 수익성, 안정성 지표를 계산한다.
- PER, PBR, ROE, 영업이익률, 부채비율 등을 표시한다.
- 외국인·기관 수급과 가격 흐름을 함께 표시한다.
- 배당, 유상증자, 합병, 주요주주 변경 등의 공시를 연결한다.
- 모든 계산 결과에 수식, 기준일, 원문 출처를 제공한다.

완료 기준:

- 대표 기업의 주요 수치를 DART 원문과 대조해 일치함을 확인한다.
- 재무 데이터가 없거나 정정된 경우를 명시적으로 처리한다.
- 동일 지표가 화면과 백엔드에서 같은 정의를 사용한다.

### 5단계: ETF 탐색과 순위

구현 내용:

- 국내·미국 ETF 마스터를 구축한다.
- 자산군, 지역, 운용사, 전략, 레버리지, 인버스, 환헤지를 분류한다.
- 국내 ETF의 개인·외국인·기관 순매수·순매도 순위를 제공한다.
- 거래량, 거래대금, 수익률, 괴리율 순위를 제공한다.
- 국내 ETF의 NAV와 구성종목을 제공한다.
- 분배금 이력을 저장하고 분배율을 직접 계산한다.
- 순위마다 시장, 투자자 주체, 집계 기간, 데이터 출처를 표시한다.

ETF 핵심 테이블:

```text
etf_profile
etf_constituent
etf_nav
etf_investor_flow
etf_distribution
```

분배율 정의:

```text
최근 12개월 분배율
= 최근 12개월 주당 분배금 합계 / 현재가 * 100

최근 분배금 연환산 분배율
= 최근 주당 분배금 * 연간 지급 예상 횟수 / 현재가 * 100
```

완료 기준:

- 필터 조합에 따라 국내 ETF와 미국 ETF가 정확히 구분된다.
- TOP 10 결과를 원본 데이터와 대조할 수 있다.
- 최근 12개월 분배율과 연환산 분배율을 혼동하지 않도록 표시한다.

### 6단계: 백테스트 엔진과 규칙형 퀀트 전략

구현 내용:

- 가치, 수익성, 성장성, 모멘텀, 안정성 팩터를 계산한다.
- 이동평균선, RSI, MACD, ATR, 볼린저밴드, 캔들 특징을 계산한다.
- 신호는 장 마감 데이터로 생성하고 다음 거래 가능 시점에 체결한다.
- 수수료, 세금, 슬리피지, 거래정지, 주문 불가를 반영한다.
- 전략과 파라미터, 입력 데이터 버전을 저장한다.
- 워크포워드 검증을 지원한다.
- 수익률, 벤치마크 초과수익, MDD, 샤프지수, 회전율을 계산한다.

첫 기준 전략:

- 가치·수익성·모멘텀 종합 순위 전략
- 이동평균선과 RSI를 조합한 기술적 전략
- ETF 모멘텀 자산배분 전략

완료 기준:

- 동일 입력으로 동일한 백테스트 결과를 재현한다.
- 미래정보 누출 검사가 통과한다.
- 거래비용 전후 결과를 함께 확인할 수 있다.
- 규칙형 기준 전략의 성과가 이후 AI 모델 비교 기준으로 저장된다.

### 7단계: 모의투자 자동매매

구현 내용:

- 전략 신호를 목표 포지션과 주문 계획으로 변환한다.
- 주문별 고유 식별자로 중복 주문을 방지한다.
- 주문, 정정, 취소, 체결, 미체결, 잔고를 동기화한다.
- 서버 재시작 후 주문과 포지션 상태를 복구한다.
- 종목·업종·일일 손실 한도를 주문 전에 검사한다.
- 자동매매 활성화, 일시정지, 비상정지를 제공한다.
- 주문과 위험 이벤트를 웹 또는 메신저로 알린다.

주문 상태:

```text
PLANNED -> SUBMITTED -> PARTIALLY_FILLED -> FILLED
                    \-> REJECTED
                    \-> CANCELED
```

완료 기준:

- 브라우저에서 전략을 활성화하고 모의 주문을 발생시킨다.
- 부분체결, 취소, 거절, 잔고 반영을 처리한다.
- 비상정지 이후 신규 주문이 발생하지 않는다.
- 재시작 후 증권사 상태와 내부 상태를 조정한다.

### 8단계: AI 기능

#### 8-1. 공시 AI 분석

- OpenDART 공시에서 이벤트 유형, 영향 범위, 위험도를 구조화해 추출한다.
- 원문 접수번호, 기준일, 근거 문장을 함께 저장한다.
- AI 요약은 참고정보로만 사용하고 주문 조건으로 직접 사용하지 않는다.

#### 8-2. OHLCV·보조지표 숫자 시계열 모델

이 항목은 대화에서 논의한 "OHLCV와 보조지표를 숫자 시계열로 변환해 학습"하는 범위다.

선행 의존성:

```text
2단계: 정확한 OHLCV 수집
    ↓
6단계: 보조지표 계산과 규칙형 백테스트
    ↓
8-2단계: 숫자 시계열 모델 학습
```

입력 특징:

- 가격 수익률과 변동성
- 캔들 몸통, 위꼬리, 아래꼬리, 갭
- 이동평균선 거리와 기울기
- RSI, MACD, ATR, 볼린저밴드
- 거래량 변화와 거래대금
- 외국인·기관 수급
- 시장지수와 시장 변동성

학습 형태:

```text
입력 X: 최근 60거래일 x 숫자 특징
정답 y: 향후 10~20거래일의 시장 대비 초과수익 또는 순위
```

모델 적용 순서:

1. 로지스틱 회귀 또는 단순 순위 모델을 기준선으로 만든다.
2. XGBoost 또는 LightGBM을 학습한다.
3. 워크포워드 방식으로 표본 밖 성과를 평가한다.
4. 거래비용 후 규칙형 전략보다 개선되는지 비교한다.
5. 개선이 확인된 뒤 1D CNN 또는 LSTM을 실험한다.
6. 캔들 차트 이미지 CNN은 마지막 실험으로 둔다.

#### 8-3. AI 모델 운영

- 학습 데이터, 특징, 모델, 평가 결과의 버전을 저장한다.
- 특징 중요도와 예측 신뢰도를 제공한다.
- 모의투자에서 그림자 운용으로 실제 체결 기준 성과를 확인한다.
- 성능 저하와 입력 데이터 변화 감지를 제공한다.
- AI 신호는 위험관리 엔진을 우회할 수 없다.

완료 기준:

- 규칙형 기준 전략보다 표본 밖 거래비용 후 성과가 개선된다.
- 특정 종목이나 한 시기에만 성과가 집중되지 않는다.
- AI를 비활성화해도 기존 전략과 주문 시스템이 정상 동작한다.

### 9단계: 제한된 실전매매

구현 내용:

- 모의·실전 자격증명과 설정을 분리한다.
- 실전매매는 기본 비활성 상태로 둔다.
- 실전 활성화에 이중 확인을 요구한다.
- 매우 작은 종목별·일별 주문 한도를 적용한다.
- 주문 직전에 예수금, 주문 가능 수량, 장 상태를 다시 확인한다.
- 일일 손실 한도 초과, 데이터 지연, 연결 장애 시 신규 주문을 차단한다.
- 모든 주문과 결정 근거를 감사 로그로 저장한다.

완료 기준:

- 사용자가 명시적으로 승인한 소액 범위에서 주문, 체결, 잔고, 손익, 비상정지를 관찰한다.
- 내부 주문 상태와 증권사 상태가 일치한다.

### 10단계: 운영 안정화와 확장

구현 내용:

- 데이터 수집, 전략 실행, 주문 처리 상태를 모니터링한다.
- 데이터 누락 및 지연 경보를 제공한다.
- 데이터베이스 백업과 복구를 검증한다.
- 모델 성과 저하와 전략별 손익을 감시한다.
- HTTPS, 접근제어, 2단계 인증을 적용한다.
- 장애 대응과 수동 복구 절차를 문서화한다.
- 실제 필요성이 확인되면 키움 또는 다른 증권사를 추가한다.
- 이후 분봉 전략, 실시간 전략, 다중 사용자 기능을 별도 검토한다.

완료 기준:

- 장애 상황에서 주문을 안전하게 중단하고 상태를 복구할 수 있다.
- 백업으로 서비스를 복원할 수 있다.
- 운영자가 데이터, 전략, 주문, 위험 상태를 한 화면에서 확인할 수 있다.

6. 모의매매 콘솔

8. 실전매매와 위험관리

## 6. 첫 구현 요청 범위

2단계 첫 수직 슬라이스의 구현 범위는 다음과 같이 확정했고 2026-08-14 코드·fixture·PostgreSQL과 실제 KIS 모의환경 반복 검증을 완료했다.

> 한국투자증권 모의투자 인증과 토큰 관리를 구현하고, 삼성전자와 대표 국내 ETF의 종목 마스터·현재가·일봉 데이터를 중복 없이 수집하여 출처와 기준시각을 포함한 읽기 전용 API로 조회한다.

초기 구현에서 제외한다.

- 실전 주문
- 다중 증권사
- 다중 사용자
- 초단타·틱 전략
- 차트 이미지 CNN
- 강화학습
- LLM 직접 주문
- 다수 전략의 자동 최적화

## 7. 2단계 남은 결정

- 실전 전환 기간과 손실 한도는 [모의투자·실전투자 전환 게이트](../spec/paper-to-live-gate.md)에서 확정했다.
