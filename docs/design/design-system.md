## 승인 상태와 적용 원칙

사용자는 2026-08-12에 클로드 화면 시안을 프로젝트의 공식 디자인 방향으로 승인했다. 승인된 방향은 **Research Grid의 정보 구조에 Night Watch의 안전 상태 표현을 결합한 라이트·다크 운영 및 리서치 UI**다.

- 이 문서는 전역 디자인 원칙을, [화면 디자인 사양](claude-design/screen-design-spec.md)은 화면별 토큰·구성과 상태 규칙을 정의한다.
- [HTML 시안](claude-design/screen-mockups.html)은 레이아웃과 시각 계층의 참조다. 시안 속 가격, 수익률, 계좌와 주문 값은 예시이며 구현 데이터로 사용하지 않는다.
- 제품·거래 안전 정책이 디자인 시안과 충돌하면 승인된 제품 정책을 우선한다.
- 2026-08-17에 승인 토큰과 프리미티브(좌표 셀, 데이터 표, 상태 배지, 경고 배너, 반응형 앱 셸)를 구현하고 운영 개요·시장 데이터 화면을 승인 디자인으로 재구축했다. `/showcase`가 프리미티브 상태 계약의 갤러리다.
- 이후 화면은 이 계약의 토큰과 재사용 프리미티브를 먼저 사용한 뒤 확장한다.

## 1. Atmosphere & Identity

이 제품은 리서치 워크스테이션과 자동매매 운영 콘솔을 하나의 좌표 격자 안에 결합한다. 네이비 셸과 밝은 작업면을 기본으로 사용하고, 다크 모드에서도 같은 좌표와 정보 계층을 유지한다. 데이터 셀은 얇은 격자로 구분하며, 좌표 라벨은 화면 사양과 QA에서 공통 위치 식별자로 사용한다.

핵심 인상은 `신뢰할 수 있음`, `분석 가능함`, `검증 가능함`이다. 실전거래 비활성, 차단 사유와 데이터 신선도는 Night Watch에서 가져온 높은 대비의 주황·적색 상태 표현으로 항상 먼저 식별할 수 있어야 한다. 데이터가 없거나 오래되었으면 값을 만들지 않고 이유와 기준 시각을 표시한다.

### Users and primary tasks

- 개인 퀀트 연구자: 종목·기업·ETF 데이터를 비교하고 전략과 백테스트 결과를 검증한다.
- 자동매매 운영자: 데이터 신선도, 계좌 조정, 위험 한도와 주문 상태를 빠르게 확인하고 필요하면 안전하게 중지한다.
- 투자 분석 사용자: 정보의 출처, 기준시각과 계산 근거를 확인하고 순위·필터를 통해 후보를 좁힌다.

### Inclusive personas and stress cases

- 키보드 사용자: 내비게이션, 표, 필터와 안전 행동을 포인터 없이 완료할 수 있어야 한다.
- 저시력·확대 사용자: 200% 확대와 시스템 글자 확대에서도 핵심 값, 단위, 기준시각과 행동이 잘리거나 겹치지 않아야 한다.
- 색각 차이 사용자: 상승·하락·정상·차단을 색만으로 판별하도록 만들지 않고 아이콘, 부호, 라벨과 사유 코드를 함께 제공한다.
- 긴급 상황의 운영자: 차단 원인과 안전 행동을 주변 데이터보다 먼저 찾고, 파괴적 행동의 영향 범위를 실행 전에 확인할 수 있어야 한다.

성공 기준은 `현재 상태 파악`, `데이터 출처·시점 확인`, `분석 후보 비교`, `안전 차단 원인 확인`을 각 화면에서 다른 문서를 읽지 않고 완료하는 것이다.

## 2. Color

### Palette

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-canvas` | `#f4f6f9` | 라이트 앱 배경 |
| `--color-panel` | `#ffffff` | 카드·작업면 |
| `--color-panel-muted` | `#fafbfd` | 보조·비활성 표면 |
| `--color-line` | `#d9e0ea` | 격자 경계 |
| `--color-rail` | `#0f1826` | 아이콘 레일 |
| `--color-nav` | `#131d2e` | 내비게이션 패널 |
| `--color-text` | `#131d2e` | 주요 텍스트 |
| `--color-text-muted` | `#66788f` | 보조 텍스트 |
| `--color-accent` | `#1f6feb` | 선택·포커스 |
| `--color-success` | `#12775a` | 정상·통과 |
| `--color-warning` | `#9a5f18` | 주의·차단 |
| `--color-danger` | `#b3392c` | 위험·실패 |
| `--color-market-up` | `#d33a2c` | 상승·매수 |
| `--color-market-down` | `#2563a8` | 하락·매도 |

다크 모드와 상태별 문자·배경·경계의 전체 대응값은 화면 디자인 사양 8절을 따른다. 컴포넌트 CSS는 색상 리터럴을 직접 사용하지 않고 semantic 토큰만 참조한다. 간격·글자 크기·모서리·터치 대상도 각각 `--space-*`, `--font-size-*`, `--radius-*`, `--size-touch` 토큰으로 관리한다.

색은 의미를 보조하며 단독으로 상태를 전달하지 않는다. 모든 상태에는 텍스트와 아이콘 또는 형태 차이를 함께 제공한다. 본문 대비는 WCAG AA 이상을 유지한다.

### Font Stack

로컬 시스템 글꼴만 사용한다: `Pretendard`, `Apple SD Gothic Neo`, `Noto Sans KR`, `system-ui`, `sans-serif`. 숫자와 코드 값에는 `SFMono-Regular`, `Consolas`, `monospace`를 사용한다. 외부 폰트 요청을 만들지 않는다.

## 4. Spacing & Layout

- 기본 단위: 4px
- 주요 간격: 8, 12, 16, 24, 32px
- 데스크톱 기준: 1360x908px, 52px 아이콘 레일 + 190~214px 내비게이션 + 유동 작업면
- KPI 영역: 6~7개 좌표 셀과 1px 격자
- 우측 보조 열: 292~360px
- 태블릿(768~1024px): 사용자가 2026-08-17 확정한 접기 규칙을 따른다. 52px 아이콘 레일은 유지하고 내비 패널은 숨기며(레일 아이콘으로 화면 전환), 작업면은 우측 보조 열이 주 열 아래로 내려가는 1열 구성, KPI는 3열×2행으로 접는다.
- 모바일 기준: 390px, 1열과 하단 탭 5개, 핵심 안전 상태를 데이터보다 먼저 표시
- 전체 화면 셸은 `100dvh`를 사용하고 스크롤 소유자는 주 작업 영역 하나로 제한한다.
- 고정 머리, 독립 스크롤 목록, 고정 바닥을 분리하며 `margin-top: auto`로 안전 배너를 밀어내지 않는다.

## 5. Components

### App shell

52px 아이콘 레일, 네이비 내비게이션, 작업면 헤더와 좌표 격자로 구성한다. 미래 단계 메뉴는 비활성 상태와 `준비 중` 문구를 제공하며 클릭 가능한 것처럼 보이지 않아야 한다.

### Coordinate cell

`A1`, `B2`, `D3` 같은 좌표, 지표명, 값과 기준시각을 한 셀에 표시한다. 값을 계산할 수 없으면 `—`와 이유를 표시하며, 차단 관련 셀에는 의미 색과 2px 안쪽 강조선을 함께 사용한다.

### Status badge

일반 상태와 주문 상태를 분리한다. 주문 상태는 `FILLED`, `PARTIALLY_FILLED`, `REJECTED`, `CANCELED`와 화면 문구를 1:1로 대응시키며 색상, 텍스트와 형태를 함께 사용한다.

### Service row

서비스명, 역할, 상태를 한 행에 표시한다. 응답시간·연결 수처럼 백엔드가 제공하지 않는 지표는 만들지 않는다. 로딩 시에는 폭이 고정된 스켈레톤을, 실패 시에는 원인 범주와 재시도 동작을 제공한다.

### Safety notice

모의투자와 실전거래 상태를 분리해 보여준다. 정보·주의·위험 세 단계만 사용하며 주의와 위험은 작업면 헤더 아래 전체 폭에 배치한다. 잠금 아이콘, 사유 코드, 설명, 가능한 행동과 해제 조건을 함께 표시한다.

### Empty module

아직 데이터가 없는 전략·주문·포지션 영역은 설명과 해당 기능이 열리는 단계를 표시한다. 임의 차트, 수익률 또는 건수를 채우지 않는다.

### Table, chart and filter contract

- 표: 헤더 고정은 실제 세로 스크롤이 있을 때만 사용한다. 숫자는 우측 정렬하고 단위·기준시각을 헤더에 표시한다.
- 차트: 색상 외에 선 형태·범례로 시리즈를 구분하고, 키보드로 데이터 요약을 읽을 수 있어야 한다.
- 필터: 적용 중인 조건과 초기화 동작을 항상 노출한다. 시장·상품 유형·기간을 숨은 기본값으로 두지 않는다.
- 오류: 오류 범주, 영향 범위, 마지막 정상 시각, 재시도 가능 여부를 표시한다. 자격증명이나 원문 응답은 표시하지 않는다.

## 6. Motion & Interaction

- 짧은 상태 변화: 120ms
- 패널·내비게이션 전환: 180ms
- 로딩 상태는 반복 회전 장식보다 낮은 대비의 펄스를 사용한다.
- `prefers-reduced-motion`에서는 변형과 반복 애니메이션을 제거한다.
- hover는 포인터 장치에서만 보조 신호로 사용하고, 키보드 포커스는 2px 외곽선으로 항상 보인다.

## 7. Depth & Surface

깊이는 그림자보다 네이비 셸, 밝은 작업면과 1px 격자 경계로 구분한다. 기본 패널은 그림자를 쓰지 않고, 떠 있는 메뉴나 툴팁에만 짧고 낮은 그림자를 허용한다. 모서리는 좌표 격자에서 거의 사용하지 않고 상태 배지는 3px로 제한한다. 유리 효과, 그라디언트와 장식용 3D 효과는 사용하지 않는다.

## 8. Accessibility Constraints & Accepted Debt

### Constraints

- 모든 기능은 키보드로 접근 가능해야 하며 논리적인 포커스 순서를 유지한다.
- 390px, 768px, 1360px 너비에서 가로 페이지 스크롤이 없어야 한다.
- 터치 대상은 최소 44x44px을 목표로 한다.
- 상태·오류·안전 경고는 스크린리더가 읽을 수 있는 텍스트를 포함한다.
- 로딩 완료와 연결 오류는 적절한 live region으로 알린다.
- 본문 대비는 4.5:1 이상, 라벨과 보조 문자는 3:1 이상을 유지한다.
- 9px 좌표 라벨은 위치 식별에만 사용하고 핵심 정보나 행동을 담지 않는다. 브라우저 확대와 시스템 글자 확대에서 정보가 잘리지 않아야 한다.
- 브라우저 번들에는 API 키, 계좌번호, 데이터베이스·Valkey 주소를 넣지 않는다.

### Accepted Debt

- 운영 개요·시장 데이터·기업 분석·ETF 탐색·전략 연구 화면은 실제 API로 구현했다. ETF 탐색(3a)의 순위표는 정렬 기준·기준시각을 항상 표시하고 괴리율·추적오차 정렬은 절대값 기준임을 주석에 명시한다. 2026-08-18에 전략 연구 화면을 구현하면서 모바일 하단 탭은 운영·시장·기업·ETF·전략 5개가 됐고(준비 중이던 '매매' 자리는 실제 화면이 우선), 전략 연구(2c)는 성과 KPI 7셀, 실행 선택과 누적 수익·드로다운 곡선(저장된 NAV·발행 데이터셋에서 파생한 표시 전용), 거래비용 카드, 신호·체결 기록(D 좌표 — 목표 포지션 변환은 7단계에서 원래 내용으로 확장, 사용자 승인), 워크포워드 구간 비교, 검증·입력 계보 카드로 구성한다. '실전 반영 불가' 정보 배너와 '미래정보 누출 검사 통과' 배지를 항상 표시하고 실패 실행은 사유 코드로 노출한다. 계좌·주문·이벤트처럼 백엔드가 없는 영역은 값 생성 없이 빈 상태 규칙을 유지한다. 기업 분석 KPI는 승인 시안 2b의 7셀 구성을 쓰며(데스크톱 7열, 태블릿·모바일에서는 접기 규칙에 따라 3열·2열로 접히고 7번째 셀은 전체 폭), 재무 지표 값 옆에는 항상 수식·근거 접수번호가 API 응답 그대로 노출된다. 가치 카드(C2)는 기본주당이익·PER·시가총액 실값과 가격·주식수·재무 기준 3종을 함께 표시하고, BPS·PBR은 우선주 반영 설계 확정까지 사유를 적은 빈 값이다. 수급 카드(D2)는 최근 거래일의 주체별 순매수를 상승·하락 색으로, 공시 카드(D3)는 유형·제출인 메타와 DART 원문 링크(새 창)로 표시하며 두 카드 모두 단위·출처·한계를 주석에 명시한다.
- 차트 십자선·확대 상호작용은 해당 화면 고도화 시 확정한다.
- 색맹 대응 전용 팔레트 제공 여부는 미결정이다. 결정 전에도 색 외의 아이콘·부호·라벨 중복 표시는 필수다.
- 알림 채널과 AI 모델 성과 화면은 각 로드맵 단계에서 상세화한다.
