# 시장 데이터 및 시점 정책

- 상태: 승인
- 승인일: 2026-08-11
- 초기 범위: 국내주식·국내 ETF, 일봉 전략
- 관련 정책: [거래 안전 정책](trading-safety-policy.md)
- 관련 데이터 계약: [국내 시장 달력 데이터 계약](../data/market-calendar-data-contract.md)

## 구현 기록

2026-08-14에 2단계 첫 수직 슬라이스로 KIS 모의투자 인증 어댑터, 국내주식·ETF 종목정보·현재가·비수정 일봉 저장과 읽기 API를 구현하고 실제 모의 API로 반복 수집을 검증했다.

- 일봉 요청은 `FID_ORG_ADJ_PRC=1`을 사용하며 `adjusted=false`로 저장한다.
- 원본 응답은 append-only로 보존하고 종목·최신 현재가·일봉은 고유키로 upsert한다.
- KIS 현재가 REST 응답에 거래소 체결시각이 없으므로 이번 단계의 `quote.as_of`는 UTC 수신시각이다. 실시간 스트림 도입 시 거래소 시각을 별도 필드로 보존한다.
- 수정주가 데이터셋, 시장 달력, 기업행사와 분봉은 이 정책대로 후속 2단계에서 구현한다.
- KIS 모의환경은 종목 상세 TR `CTPF1002R`을 지원하지 않으므로 현재가와 일봉만 호출하고, 최소 종목 식별정보의 이름은 일봉 응답 요약에서 구성한다. 상장일·상장폐지일·영문명은 실전 상세조회 또는 후속 종목 마스터 수집 전까지 비어 있다.
- 실제 모의 API에서 두 종목을 같은 범위로 두 번 수집해 정규화 행 수가 유지되고 원본 응답만 실행당 4건 추가됨을 확인했다.
- 승인된 [ADR-0005](../decisions/0005-kis-token-and-rate-coordination.md)에 따라 접근 토큰과 모의 REST 1.05초 호출 간격을 Valkey에서 프로세스 간 공유한다. Valkey 장애 시 개별 worker 호출로 우회하지 않는다.
- 2026-08-16에 `XKRX` 정규장의 거래일·휴장일·단축장, 사실 버전과 당일 확인 상태를 정의한 [시장 달력 데이터 계약](../data/market-calendar-data-contract.md)을 작성했다.

## 1. 시간 기준

- 저장 기준시각은 UTC로 통일한다.
- 원천 데이터의 거래소 시각과 API 수신시각을 별도 보존한다.
- 국내 시장 판단과 사용자 표시는 `Asia/Seoul`을 사용한다.
- 미래 미국 시장 지원 시 거래소별 시간대와 서머타임 규칙을 별도로 추가한다.

KRX 주식·ETF 정규장은 09:00~15:30이고 호가 접수는 08:30부터 시작한다. 초기 자동매매는 정규장 중 09:05~15:15만 주문 가능시간으로 사용하며 시간외 거래는 지원하지 않는다. 공식 기준은 [KRX 주식시장 거래시간](https://global.krx.co.kr/contents/GLB/06/0602/0602010201/GLB0602010201T1.jsp)과 [KRX ETF 거래제도](https://global.krx.co.kr/contents/GLB/06/0605/0605010101/GLB0605010101T1.jsp)를 따른다.

거래일은 평일 여부로 추정하지 않는다. KRX 공식 휴장일과 증권사 거래 가능 응답을 함께 사용하며, 임시 휴장이나 개장시간 변경은 `market_calendar`의 버전된 세션으로 반영한다.

## 2. 데이터 계층

```text
외부 API 응답
    ↓
원본 데이터: 수신 내용, 출처, 요청 식별자, 수신시각
    ↓
정규화 데이터: 종목 식별자, 거래소 시각, 가격·수량·통화
    ↓
파생 데이터: 수정주가, 보조지표, 순위, 학습 특징
```

- 원본 데이터는 인증정보와 계좌번호를 제거한 뒤 보존한다.
- 정규화 오류가 발생해도 원본 데이터를 수정하지 않는다.
- 파생 데이터에는 계산식 버전과 입력 데이터 버전을 기록한다.
- 정정 수신 시 기존 사실을 삭제하지 않고 새 버전과 정정 관계를 남긴다.

## 3. 종목 식별

종목코드 문자열만으로 종목을 식별하지 않는다.

```text
InstrumentId
= 국가 + 거래소 + 종목코드 + 상품유형 + 통화
```

종목 마스터에는 상장일, 상장폐지일, 거래 상태, 주식·ETF 구분, 업종과 원천 데이터 기준일을 저장한다. 코드 재사용과 시장 간 동일 코드 충돌을 고려해 내부 식별자는 별도로 발급한다.

## 4. 데이터 신선도

| 데이터 | 정상 | 지연 | 주문 차단 |
|---|---|---|---|
| 정규장 현재가 | 수신 후 30초 이내 | 30초 초과 120초 이하 | 10초 초과 시 해당 시세 기반 주문 차단 |
| 실시간 스트림 | 연결 및 heartbeat 정상 | 재연결 중 | 연결 상실 즉시 신규 주문 차단 |
| 분봉 | 해당 구간 종료 후 확정 | 다음 구간까지 미수신 | 미확정·누락 분봉 사용 금지 |
| 일봉 | 최종 검증 완료 | 검증 대기 | 검증 전 신호 생성 금지 |
| 종목 마스터 | 최근 거래일 기준 | 1거래일 초과 | 거래 상태 불명 종목 주문 차단 |
| 시장 달력 | 당일 07:00 이전 확인 | 재확인 필요 | 당일 세션 미확정 시 스케줄 실행 금지 |

UI가 정상으로 표시하는 30초 기준과 주문 위험검사의 10초 기준은 의도적으로 다르다. 화면 조회 가능 상태가 곧 주문 가능 상태를 의미하지 않는다.

## 5. 일봉 확정과 신호 시점

일봉 전략은 다음 순서를 지킨다.

```text
거래일 D 정규장 종료
→ 15:40 이후 일봉 1차 수집
→ 원천의 최종 상태 또는 재조회 일치 확인
→ 거래일 D 일봉 확정
→ 특징과 신호 계산
→ 다음 거래일 D+1의 09:05 이후 주문 가능
```

- 거래일 D 종가로 만든 신호를 같은 종가에 체결했다고 가정하지 않는다.
- 최종 상태 플래그가 없으면 15:40 이후 두 번 조회한 OHLCV가 일치해야 확정한다.
- 정정된 일봉은 데이터 버전을 올리고 영향을 받은 특징과 백테스트를 재계산한다.
- 미확정 일봉은 차트에 잠정값으로 표시할 수 있지만 전략 입력에는 사용하지 않는다.

## 6. 가격과 기업행사

- 원본 OHLCV는 비수정 가격으로 저장한다.
- 수정주가는 별도 데이터셋으로 생성하고 조정 방식과 생성 버전을 기록한다.
- 액면분할, 병합, 배당, 권리락, 합병과 상장폐지는 `corporate_action`으로 관리한다.
- 백테스트는 당시 알 수 있었던 발표일과 효력일을 구분해 미래정보 누출을 방지한다.
- ETF 분배금은 가격 조정과 현금흐름을 중복 반영하지 않는다.

## 7. 데이터 품질 규칙

수집 시 다음 규칙을 검사한다.

- `low <= open, close <= high`
- 가격과 거래량은 음수가 아니다.
- 거래량이 0인 경우와 데이터 누락을 구분한다.
- `(instrument_id, interval, exchange_timestamp, source)`가 중복되지 않는다.
- 거래일과 세션 밖 데이터는 자동 확정하지 않는다.
- 급격한 가격 변화는 기업행사와 거래소 상태를 확인하기 전까지 이상값으로 표시한다.
- 서로 다른 소스 값이 충돌하면 출처 우선순위와 차이를 모두 기록한다.

누락된 OHLCV를 직전 값으로 채우지 않는다. 보조지표의 준비 기간이 부족하면 값을 `null`로 유지하고 신호 생성을 건너뛴다.

## 8. 출처 우선순위

| 데이터 | 1차 출처 | 보완 출처 |
|---|---|---|
| 계좌·주문·체결 | KIS 계좌 API | 없음 |
| 주문 판단 현재가 | KIS 실시간·현재가 API | 없음, 실패 시 주문 차단 |
| 종목 마스터·일봉 | KIS | KRX와 대조 |
| 거래일·시장 제도 | KRX | KIS 거래 가능 상태 |
| 기업 공시·재무 | OpenDART | KRX/KIND 연결 |
| ETF 기준정보 | KRX/KIND 또는 허가된 공급자 | KIS 제공 범위 |

소스가 충돌할 때 주문과 체결 사실은 증권사 계좌 API를 기준으로 한다. 분석 데이터 충돌은 자동으로 한쪽을 덮어쓰지 않고 데이터 품질 이벤트를 생성한다.

## 9. 수집과 복구

- 모든 수집 작업에는 멱등성 키를 사용한다.
- [KIS API 호출 유량 안내](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000001/post/d0d1a83f-6f8d-4437-9700-6d26702fd989)에 따라 모의투자 REST 요청은 초당 1건 제한을 넘지 않도록 같은 자격증명의 모든 프로세스에서 인증과 시세 요청을 최소 1.05초 간격으로 직렬화한다.
- 마지막 성공 커서보다 일정 구간을 겹쳐 재수집하고 고유키로 중복을 제거한다.
- 재시도는 호출 제한과 서버의 재시도 안내를 존중한다.
- 재시도 후에도 실패하면 `api_sync_status`에 범위, 원인과 다음 재개 지점을 기록한다.
- 부분 수집 결과는 완료 상태로 표시하지 않는다.

## 10. 완료 조건

- 삼성전자와 대표 ETF의 종목 정보·현재가·일봉에 출처와 세 시각을 표시할 수 있다.
- 동일 범위를 반복 수집해도 중복 레코드가 생기지 않는다.
- 미확정·누락·지연 데이터를 사용한 신호와 주문이 차단된다.
- 기업행사 전후 수정주가와 현금흐름이 테스트 데이터에서 일치한다.
