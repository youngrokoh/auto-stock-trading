# ADR-0011: 모의투자 주문 정정 경계

- 상태: 승인
- 결정일: 2026-08-20
- 승인: 사용자가 2026-08-20에 네 가지 결정을 승인 — ① 사람이 CLI로 주문을 지정해 정정, ② 지정가만 정정(수량은 그대로), ③ 같은 주문 행을 유지하고 증권사 주문번호를 갱신, ④ 정정 값은 새 주문과 동일한 전수 위험검사를 받는다
- 관련 결정: [ADR-0008 모의투자 주문 제출·체결 동기화 경계](0008-paper-order-submission.md), [ADR-0009 실시간 체결통보 수신 경계](0009-realtime-fill-notification.md), [ADR-0007 모의투자 주문 계획과 위험검사 경계](0007-paper-order-planning-and-risk.md)
- 관련 정책: [거래 안전 정책](../spec/trading-safety-policy.md), [모의투자·실전투자 전환 게이트](../spec/paper-to-live-gate.md)
- 관련 계약: [주문 제출·체결 동기화 계약](../data/order-submission-contract.md), [주문 계획·위험검사 데이터 계약](../data/order-planning-risk-contract.md)

## 배경

ADR-0008은 정정을 "취소 후 재계획으로 대체한다"로 미뤘다. 이유는 목표 포지션 재계산 규칙이
필요하다는 것이었다. 2026-08-20 장중 검증에서 두 가지가 분명해졌다.

- 지정가를 시장에서 벌린 주문은 체결되지 않고 남는다. 가격만 시장에 붙이면 체결되는데, 지금은
  취소하고 새 계획을 만들어야 한다.
- 취소·정정 통보는 **자체 주문번호를 새로 받고 원주문번호로 대상을 가리킨다**(실측). 정정 이후의 체결
  통보도 새 주문번호로 오므로, 내부 주문의 증권사 주문번호를 갱신하지 않으면 그 체결이 대조되지 않는다.

이 결정은 정정을 좁게 도입한다. 수량을 건드리지 않으면 목표 포지션이 바뀌지 않으므로 ADR-0008이
문제 삼은 재계산 규칙이 필요하지 않다.

## 결정

### 1. 정정은 사람이 CLI로 주문을 지정할 때만 일어난다

worker CLI에 정정 명령을 두고, 대상 주문의 증권사 주문번호를 사람이 지정한다. 재계획이 미체결 주문을
자동으로 정정하는 경로는 만들지 않는다. HTTP 쓰기 경로도 만들지 않는다(ADR-0007 결정 1, ADR-0008
결정 1의 경계 유지). 자동 정정은 별도 승인 사항이다.

### 2. 지정가만 정정하고 수량은 건드리지 않는다

정정 입력은 기준가 대비 상대 버전트뿐이며, 새 지정가는 그 버전트로 계산한다. 절대가를 사람이
지정하는 경로는 만들지 않는다(지정가 옵션과 같은 규칙). 수량 정정은 목표 포지션 재계산 규칙이
필요하므로 이 결정의 범위가 아니다.

### 3. 같은 주문 행을 유지하고 증권사 주문번호를 갱신한다

정정은 내부에서 같은 논리적 주문이다. `client_order_id`와 주문 행을 그대로 두고 `broker_order_id`를
증권사가 준 새 번호로 갱신한다. 원래 번호는 주문 이벤트에 남겨 추적할 수 있게 한다. 이렇게 해야 정정
이후의 체결 통보가 대조된다.

주문 상태는 바뀌지 않는다(`SUBMITTED`·`PARTIALLY_FILLED` 유지). 정정은 체결 사실이 아니므로 상태
전이가 아니다.

### 4. 정정 값은 새 주문과 같은 전수 위험검사를 받는다

정정 시점에 기준가를 새로 조회하고(정책 §4의 10초 규칙) 정책 §3·§4의 모든 규칙을 다시 판정한다.
판정은 새 주문 계획과 같은 엔진·같은 규칙 코드를 쓴다. 판정에서 대상 주문 자신의 노출과 미체결
카운트는 제외한다. 정정은 주문을 하나 더 만드는 것이 아니라 기존 주문을 바꾸는 것이므로, 자신을 두 번
세면 없는 위반을 만든다.

하나라도 통과하지 못하면 증권사를 호출하지 않고 사유 코드를 남긴다.

### 5. 정정 판정도 주문별 규칙 판정으로 저장한다

정책 §7은 모든 주문 시도에 적용된 모든 위험 규칙과 통과·거절 결과를 연결하라고 요구한다. 정정은 주문
시도이므로 판정을 요약으로만 남기지 않는다. `trading.risk_decision`의 유일 제약에 시도 회차를 추가해
계획 시점 판정과 정정 시점 판정을 함께 보존한다. 회차는 주문별로 1부터 증가한다.

### 6. 실패와 거절은 fail-closed다

증권사가 정정을 거절하면(`rt_cd != 0`) 주문 상태와 주문번호를 바꾸지 않고 사유 코드를 이벤트에
남긴다. 전송 실패는 `api_failure`로 기록하고 정책 §3의 연속 실패 규칙을 따른다. 정정 응답에 새
주문번호가 없으면 상태를 추측하지 않고 실패로 남긴다.

## 결과

- 체결되지 않는 지정가를 취소·재계획 없이 시장에 붙일 수 있다.
- 정정 이후 체결이 정상 대조된다. 주문번호 갱신이 그 조건이다.
- 정정도 계획과 같은 한도 검사를 받으므로 사람이 한도를 우회하는 경로가 되지 않는다.
- 감사에서 계획 판정과 정정 판정을 회차로 구분할 수 있다.
- 수량 정정과 자동 정정은 남는다. 둘 다 목표 포지션 재계산 규칙이 필요하다.

## 대안

- **취소 후 재계획 유지**: 추가 상태가 없고 이미 검증됐다. 그러나 수량 감소로 호가 우선순위를 살리는
  정정을 영구히 포기하게 되고, 취소와 재주문 사이에 시장이 움직이는 구간이 생긴다.
- **재계획이 자동으로 정정**: 운영이 매끄럽지만 사람 개입 없이 증권사 주문이 바뀐다. 승인된 "사람이
  실행할 때만 주문이 나간다" 경계를 넘는다.
- **원주문을 취소로 종결하고 새 주문 행 생성**: 이론적으로 깔끔하지만 `client_order_id` 규칙을 고쳐야
  하고, 증권사에서는 취소가 아니라 정정이므로 내부 상태가 증권사 사실과 어긋난다.
- **정정 판정을 요약으로만 기록**: 마이그레이션이 없지만 정책 §7의 감사 요구를 충족하지 못한다.
