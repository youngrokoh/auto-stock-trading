# 백테스트·규칙형 전략 계약

- 상태: 구현 기준
- 작성일: 2026-08-18
- 승인: 사용자가 2026-08-18에 네 가지 결정을 승인 — ① 일봉을 2025-01-01부터 백필, ② 체결·평가는
  비수정 확정 일봉·배당은 락일 현금 반영·신호는 발행된 수정주가 데이터셋, ③ v1은 엔진 +
  이동평균·RSI 기술 전략 1종, ④ T일 마감 신호 → T+1 시가 체결(휴장·거래정지 시 다음 거래
  가능일로 이월)
- 관련 결정: [ADR-0004 AI 신호와 주문 실행 분리](../decisions/0004-ai-execution-separation.md)
- 관련 정책: [거래 안전 정책](../spec/trading-safety-policy.md) §5 거래비용과 세금
- 관련 계약: [기업행사·수정주가 데이터 계약](corporate-action-adjusted-price-data-contract.md),
  [국내 시장 달력 데이터 계약](market-calendar-data-contract.md)
- 관련 로드맵: [구현 로드맵](../plan/implementation-roadmap.md) 6단계

## 목적

저장된 사실 데이터만으로 규칙형 전략의 신호 생성과 모의 체결을 재현 가능하게 시뮬레이션하고,
거래비용 전후 성과를 입력 데이터 버전과 함께 보존하는 백테스트의 단일 정의를 고정한다.

## 원칙

1. **재현성.** 같은 입력 데이터 버전·전략 파라미터·엔진 알고리즘 버전이면 결과가 완전히 같다.
   실행 기록에는 입력 일봉 버전 해시, 기업행사 버전 해시, 사용한 수정주가 데이터셋 ID,
   비용 규칙 버전과 canonical JSON 파라미터를 저장한다. 난수와 실행 시각 의존을 금지한다.
2. **미래정보 차단.** T일 신호는 `trading_date ≤ T`인 데이터만 사용하고 체결은 T 이후 첫 거래
   가능일이다. 장 마감 신호를 같은 종가에 체결하지 않는다.
3. **fail-closed.** 창을 덮는 확정 일봉·검증된 달력·발행된 수정주가 데이터셋이 없으면 실행을
   거부하고 사유 코드를 기록한다. 추정·보간·대체 입력은 없다.
4. **ADR-0004 경계.** 백테스트는 신호와 모의 체결의 시뮬레이션일 뿐이다. 주문 어댑터·계좌
   자격증명에 접근하지 않으며, 결과는 이후 단계의 참고 기준일 뿐 자동으로 주문을 만들지 않는다.
5. **금액은 `Decimal`.** 시각은 UTC 저장·서울 해석이며 화면 표시는 읽기 API 응답만 사용한다.

## 입력 데이터

| 입력 | 출처 | 조건 |
|---|---|---|
| 체결·평가 가격 | `market.market_bar` 현재 버전 | `finality=confirmed`만 사용. 창의 모든 달력 거래일에 확정 일봉이 없으면 `missing_confirmed_bar` |
| 신호 가격 | `market.adjusted_market_bar` (발행된 데이터셋) | 전략 설정의 `method`(기본 `total_return`) 최신 발행 데이터셋. `range_start ≤ 창 시작`이고 `price_cutoff_date ≥ 창 끝`이 아니면 `missing_adjusted_dataset` |
| 현금 분배 | `market.corporate_action` 현재 버전 | `cash_dividend`·`etf_distribution`, `quality=verified`, `lifecycle≠cancelled`, `ex_date` 보유 건만 반영 |
| 거래일 판정 | `reference.market_calendar` 현재 버전 | 창과 체결 이월 범위를 검증된 XKRX 달력이 덮지 않으면 `missing_calendar_coverage` |

- 일봉 백필: 2025-01-01부터 기존 수집·확정 경로(두 관측 일치)를 구간 분할로 소급 실행한다.
  KIS 모의환경의 과거 조회는 2025-01-02~03-31 실호출로 확인했다(회당 최대 100건, 구간 분할 필요).
- 2025년 현금배당·분배금도 같은 수집기·락일 확정 규칙으로 소급 수집하고 수정주가 데이터셋을
  창 전체로 재발행한다.

## 신호와 미래정보 검사

- 신호는 발행된 수정주가 데이터셋의 종가 시계열에서 계산한다. 수정계수는 락일 이전 전 구간에
  균등하게 곱해지므로, 스케일 불변 지표(이동평균 교차, RSI, MACD, 볼린저 %B)의 신호는 시점별
  지식 기준 수정 시계열과 동일하다. 이 스케일 불변성은 테스트로 고정하며, 스케일 불변이 아닌
  지표(절대 가격 임계 등)를 도입할 때는 시점별 데이터셋 선택을 먼저 설계해야 한다.
- 엔진은 T일 신호 계산에 `trading_date > T` 행이 유입되면 실행을 실패시킨다(누출 검사).

## 체결 모형

- T일 신호 → T 이후 첫 거래 가능일 E의 **비수정 확정 일봉 시가**에 체결한다.
- E는 검증된 달력의 다음 거래일이며, 해당일 확정 일봉이 없으면(거래정지 등) 다음 거래
  가능일로 이월한다. 창 끝까지 체결하지 못한 신호는 미체결로 기록한다.
- 수량은 정수 주식 수다. 현금 매수와 보유 수량 이내 매도만 허용한다(공매도·신용 없음,
  안전 정책과 동일). 매수 수량은 체결가와 비용을 포함한 총액이 가용 현금을 넘지 않는 최대
  정수다.
- 배당·분배 현금은 검증된 락일(ex_date)에 직전 거래일 보유 수량 × 주당 금액으로 계좌에
  반영한다. 실제 입금은 지급일이지만 v1은 락일 반영을 근사로 사용하며 이 한계를 결과에
  기록한다.

## 거래비용

[거래 안전 정책](../spec/trading-safety-policy.md) §5의 연구 기본 가정을 그대로 사용한다.
체결가는 시가 원문 그대로 두고 비용은 별도 항목으로 기록해 비용 전·후 성과를 함께 계산한다.

```text
매수 비용 = 체결금액 × (수수료 0.02% + 슬리피지: 주식 0.10% · ETF 0.05%)
매도 비용 = 체결금액 × (수수료 0.02% + 슬리피지) + 매도세
절사     = 주문 합계별 비용 항목마다 1원 미만 절사
```

비용 규칙은 `effective_from`이 있는 버전으로 엔진에 내장하고, 실행 기록에 규칙 버전과 적용
요율 스냅샷을 저장한다. 과거 창에는 당시 유효한 규칙을 적용하며 소급 덮어쓰기를 하지 않는다.
첫 유효일(2025-01-01) 이전 창은 `uncovered_cost_date`로 거부한다.

| 규칙 버전 | `effective_from` | 매도세 기준선 |
|---|---|---|
| `research-krx-2025` | 2025-01-01 | KOSPI 주식: 증권거래세 0% + 농어촌특별세 0.15% · KOSDAQ 주식: 증권거래세 0.15% · ETF: 면제 (2025년 증권거래세법 시행령 세율) |
| `research-krx-2026` | 2026-01-01 | [거래 안전 정책](../spec/trading-safety-policy.md) §5의 2026-01-01 법정 기준선 그대로 (KOSPI 0.05%+0.15%, KOSDAQ 0.20%, ETF 면제) |

## 보조지표 정의

모두 수정주가 종가 시계열 기준의 순수 함수이며 `Decimal`로 계산한다.

| 지표 | 정의 |
|---|---|
| SMA(n) | 최근 n개 종가 단순평균 |
| EMA(n) | 승수 2/(n+1), 최초값은 SMA(n) |
| RSI(n) | Wilder 평활(기본 14). 상승·하락 평균의 RS 변환 |
| MACD | EMA(12) − EMA(26), 시그널 EMA(9) |
| ATR(n) | True Range의 Wilder 평활(기본 14, 고가·저가·전일 종가) |
| 볼린저(n, k) | SMA(20) ± 2 × 모집단 표준편차 |

화면(`frontend/src/lib/indicators.ts`)과의 정의 통일은 로드맵의 기존 항목대로 후속이며,
백테스트·전략은 이 백엔드 정의만 사용한다.

## v1 기준 전략: 이동평균·RSI

- 대상: 실행 설정의 단일 종목(수집된 유니버스 내). 파라미터: 단기 SMA 기간, 장기 SMA 기간,
  RSI 기간, RSI 과매수 임계.
- 매도 신호(우선): 단기 SMA가 장기 SMA를 하향 돌파(직전일 이상 → 당일 미만)하거나 당일 RSI가
  과매수 임계 이상.
- 매수 신호: 매도 조건이 아니고, 단기 SMA가 장기 SMA를 상향 돌파(직전일 이하 → 당일 초과)하며
  당일 RSI가 과매수 임계 미만.
- 포지션: 매수 신호 시 가용 현금 최대 매수, 매도 신호 시 전량 매도. 지표가 아직 정의되지
  않는 워밍업 구간에는 신호를 만들지 않는다.
- 종합 순위 전략과 ETF 모멘텀 자산배분은 유니버스(다종목 일봉·재무) 확장 후속이다.

## v2 기준 전략: 횡단면 모멘텀 (2026-08-20 승인)

사용자가 2026-08-20에 전략 종류(횡단면 모멘텀), 포트폴리오 규칙(상위 10종목 동일가중·월말
리밸런싱), 다종목 실행 기록 스키마(유니버스 별도 테이블)를 승인했다.

### 왜 모멘텀이 먼저인가

로드맵의 첫 기준 전략은 가치·수익성·모멘텀 종합 순위지만 **지금 데이터로 불가능하다.**
재무제표는 삼성전자 1종목만 수집돼 있고 ETF 일봉은 KODEX 200 한 종목뿐이다. 일봉만으로
성립하는 전략은 횡단면 모멘텀이므로 이것을 먼저 구현해 다종목 엔진 자체를 검증한다.

### 시그널

- 유니버스는 실행 설정이 준 종목 집합이다(기본값은 저장된 KOSPI 200 유니버스).
- 모멘텀 = `종가(T) ÷ 종가(T − lookback) − 1`. `lookback`은 **거래일 수** 파라미터다
  (기본 126일 ≈ 6개월). 캘린더 개월이 아니라 거래일로 정의해 결과를 결정적으로 만든다.
- 리밸런싱 시그널일은 창 안 **각 달의 마지막 거래일**이다. 체결은 기존 체결 모형 그대로
  다음 거래 가능일 시가다.
- 후보는 시그널일에 확정 일봉이 있고 `lookback` 이전 확정 일봉도 있는 종목이다. 둘 중
  하나가 없으면(신규 상장·거래정지) 그 회차의 후보가 아니다.
- 상위 K종목(기본 10)을 고르고, 모멘텀이 같으면 **종목코드 오름차순**으로 끊는다. 순위가
  무작위가 되면 재현성이 깨진다.
- 미래정보 검사는 단일 종목 엔진과 같은 방식으로 한다: 각 시그널일까지의 접두 시계열만으로
  같은 순위가 재현되어야 한다.

### 포지션

- 목표는 선정 종목 **동일가중**이다. 회차마다 목표 금액 = 회차 시작 NAV ÷ K.
- 실행 순서는 **매도 먼저, 매수 나중**이다. 편출 종목을 전량 매도해 현금을 만든 뒤 편입·유지
  종목을 목표 금액까지 매수한다. 현금이 부족하면 매수 가능한 정수 수량까지만 산다.
- 유지 종목은 목표 금액 미만이면 추가 매수하고, 초과분은 v2에서 팔지 않는다(회전율을 낮게
  유지한다). 이 비대칭을 한계로 기록한다.
- 정수 주식 수만 매매하며 공매도·신용은 없다.

### v2 한계 (기록)

- **모멘텀을 비수정 종가로 계산한다.** 수정주가 데이터셋이 2종목만 있어 배당·분할이
  모멘텀을 왜곡한다. 배당은 KOSPI 200 기준 수익률 대비 작지만, 분할 이력이 있는 종목은
  왜곡이 크다. 분할 사실 자체가 아직 수집되지 않았다.
- **배당 현금이 대부분 반영되지 않는다.** 배당 사실이 삼성전자·KODEX 200 두 종목만 있어
  나머지는 가격 기준 수익률이다. 유니버스 배당 수집 후 재실행해야 총수익 기준이 된다.
- 창이 2025-01-02부터라 `lookback` 126일을 쓰면 첫 시그널은 2025-07경이다. 252일(12개월)을
  쓰면 첫 시그널이 2026-01경이 되어 검증 구간이 8개월로 줄어든다.
- 유지 종목의 초과 비중을 되팔지 않으므로 동일가중이 회차 사이에 느슨해진다.

## 성과 지표

일별 NAV = 현금 + 보유 수량 × 비수정 확정 종가. 모든 비율은 퍼센트 소수 둘째 자리
ROUND_HALF_UP.

| 지표 | 정의 |
|---|---|
| 총수익률 | (기말 NAV − 초기 현금) ÷ 초기 현금 × 100 (비용 후) |
| 비용 전 수익률 | 비용 합계를 더한 기말 NAV 기준 같은 식 |
| 벤치마크 수익률 | 벤치마크 종목(기본 KODEX 200)의 `total_return` 수정 종가 창 수익률 |
| 초과수익 | 총수익률 − 벤치마크 수익률 |
| MDD | 일별 NAV 고점 대비 최대 낙폭 |
| 샤프지수 | 일별 수익률 평균 ÷ 표준편차 × √252 (무위험 0, 소수 넷째 자리) |
| 회전율 | 총 매매대금 ÷ 평균 NAV ÷ 창 연수 × 100 |

## 저장과 필수 조회 계약

`strategy` 스키마에 실행 기록을 append-only로 저장한다.

- `strategy.backtest_run`: 전략 이름·버전, 파라미터(canonical JSON), 종목, 창, 초기 현금,
  벤치마크, 신호 method, 엔진 알고리즘 버전, 비용 규칙 버전·요율 스냅샷, 입력 일봉 버전
  해시·기업행사 버전 해시·수정주가 데이터셋 ID, 상태(`completed`·`failed`)와 실패 코드,
  성과 지표.
- `strategy.backtest_trade`: 실행별 체결 순번, 신호일, 체결일, 매수·매도, 수량, 체결가,
  수수료·슬리피지·세금, 미체결 사유.
- `strategy.backtest_equity`: 실행별 일별 현금·평가액·NAV.

읽기 API는 실행 목록, 실행 상세(지표·입력 계보 포함), 체결 목록, 일별 NAV를 제공하며 실패한
실행도 사유 코드와 함께 조회된다. 응답은 항상 데이터 출처(데이터셋 ID·해시)와 기준을 포함한다.

## 워크포워드

v1 엔진은 임의 창 실행을 지원하므로 워크포워드는 같은 전략·파라미터를 창 분할로 반복 실행해
각 실행을 독립 기록하는 방식으로 수행한다. 자동 파라미터 탐색과 그 결과의 즉시 반영은
제품 범위의 비범위 그대로 제외한다.

## v1 한계 (기록)

- 배당·분배 현금을 지급일이 아닌 락일에 반영한다.
- 기업행사 사실의 지식 시점(수집 시점) 구분 없이 현재 검증 버전을 락일 기준으로 적용한다.
  배당·분배는 락일 전에 공시되므로 실무 왜곡은 없으나, 소급 정정이 있으면 결과가 최신 사실
  기준으로 재현된다.
- (v1) 유니버스가 삼성전자·KODEX 200 2종목이므로 횡단면 전략은 제외했다. 2026-08-20에
  유니버스가 KOSPI 200으로 확장돼 v2 횡단면 모멘텀이 가능해졌다.
- 거래정지·관리종목 상태 데이터가 없어 "확정 일봉 부재 = 체결 불가"로만 근사한다.
