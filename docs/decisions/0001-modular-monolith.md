# ADR-0001: 모듈형 모놀리스 채택

- 상태: 승인
- 결정일: 2026-08-11

## 배경

프로젝트는 시장 데이터 수집, 기업·ETF 분석, 백테스트, AI, 주문과 웹 API를 포함한다. 이 기능들은 주문·포지션·전략·데이터 정의를 긴밀하게 공유한다. 초기 사용자는 한 명이고 첫 배포도 단일 서버를 목표로 한다.

## 결정

하나의 Python 백엔드 패키지를 도메인 경계로 분리하고 API, worker, scheduler, stream worker를 별도 프로세스로 실행하는 모듈형 모놀리스를 채택한다.

- 프로세스 간 영속 상태는 PostgreSQL로 공유한다.
- 작업 전달과 단기 이벤트에는 Valkey를 사용한다.
- 모듈 간 직접 DB 테이블 접근 대신 애플리케이션 포트를 사용한다.
- 독립 배포가 실제로 필요해진 모듈만 후속 ADR을 통해 분리한다.

## 대안

### 처음부터 마이크로서비스

배포, 네트워크 장애, 분산 트랜잭션과 관측 비용이 현재 규모에 비해 크므로 채택하지 않는다.

### 단일 프로세스

API 요청과 장기 WebSocket, 모델 학습, 스케줄 작업이 서로 영향을 줄 수 있으므로 채택하지 않는다.

## 결과

- 도메인 타입과 전략 계산을 한 코드베이스에서 공유할 수 있다.
- 프로세스 장애를 역할별로 격리할 수 있다.
- 단일 서버 배포와 로컬 개발이 단순하다.
- 모듈 경계를 지키지 않으면 큰 모놀리스로 변질될 위험이 있으므로 파일 크기와 의존 방향을 지속적으로 검사한다.

## 재검토 조건

- 역할별 독립 확장이 필요하다.
- 서로 다른 보안 경계가 필요하다.
- 배포 주기나 장애 허용 범위가 역할별로 크게 달라진다.
