# ETF 탐색 데이터 계약

- 상태: 구현 기준
- 작성일: 2026-08-18
- 승인: 사용자가 2026-08-18에 KIS 공식 마스터 파일 출처, 전량(KOSPI ETF) NAV 스냅샷 수집,
  스냅샷 기반 순위 v1과 이 계약을 구현 기준으로 승인
- 관련 정책: [시장 데이터 및 시점 정책](../spec/market-data-policy.md)
- 관련 계약: [기업행사·수정주가 데이터 계약](corporate-action-adjusted-price-data-contract.md)
- 관련 로드맵: [구현 로드맵](../plan/implementation-roadmap.md) 5단계

## 목적

국내 ETF 전체의 마스터·분류·NAV·괴리율을 원본 근거와 함께 저장하고, ETF 탐색 화면의
목록·순위·상세가 기준시각과 출처를 항상 노출하는 기반을 제공한다.

## ETF 마스터

### 출처와 실측 확인 (2026-08-18)

- 출처는 KIS가 공식 배포하는 비인증 종목 마스터 파일(`kospi_code.mst.zip`)이다.
  KRX 정보데이터시스템은 화면 종속 세션 게이트 때문에 자동 수집 출처로 쓰지 않는다.
- 고정폭 288바이트 레코드(cp949): 단축코드 `[0:9]`, 표준코드(ISIN) `[9:21]`,
  한글명 `[21:61]`, 증권그룹코드 `[61:63]`. 그룹코드 `EF` 행만 ETF다(실측 1,163종목).
  ETN(`EN`, 370종목)은 범위에서 제외한다.
- 마스터 파일에는 상장일·운용사·분류가 없다. 이 필드들은 NAV 스냅샷의 원본 필드로 채운다.

### 저장 규칙

- `reference.etf_profile`에 단축코드 단위 버전 사실로 저장한다. 논리 키 = `symbol`.
- 행은 `symbol`, `isin`, `name`, 출처, 수신 시각, 버전 필드, 원본 참조를 포함한다.
- 같은 내용 재수집은 버전을 늘리지 않고 최신 수신 근거만 갱신한다. 이름·ISIN이 바뀌면
  이전 버전을 보존한 새 버전을 만든다.
- 마스터에서 사라진 종목(상장폐지)은 v1에서 삭제·표시하지 않는다(한계로 기록,
  후속에서 폐지 처리 설계).
- 원본 마스터 파일은 Base64 봉투로 `operations.raw_api_response`에 append-only 저장한다.

## NAV·괴리율 스냅샷

### 출처와 실측 확인 (2026-08-18)

- 출처는 KIS ETF/ETN 현재가(`FHPST02400000`, `/uapi/etfetn/v1/quotations/inquire-price`)이며
  모의환경 응답을 확인했다(KODEX 200: NAV 110,371.90 / 괴리율 `dprt` -0.28 /
  추적오차 `trc_errt` 0.39 / 추적배수 `etf_trc_ert_mltp` 1.00 / 운용사 `mbcr_name`
  삼성자산운용(ETF) / 대표지수 `etf_rprs_bstp_kor_isnm` KOSPI200).
- 괴리율·추적오차·운용사·추적배수·대표지수는 원본 필드를 그대로 저장한다. 이름 규칙으로
  분류를 추정하지 않는다.
- 순자산총액(`etf_ntas_ttam`)의 단위는 억원이다. 환산하지 않고 그대로 저장하며 조회
  응답에 단위를 명시한다.
- 실측 한계 (그대로 기록):
  1. 응답에 거래대금이 없다. 거래대금 순위는 후속(일봉 확장)이다.
  2. 스냅샷은 최신값만 정규화 저장한다. 과거 스냅샷은 append-only 원본으로 재구성할 수
     있으나 정규화 이력 테이블은 v1 범위가 아니다.
  3. 모의환경 초당 1건 제한으로 전량(1,163종목) 1회 수집은 약 21분이다. 수동 배치로
     실행하며 Valkey 호출 게이트를 공유한다.

### 저장 규칙

- `market.etf_nav`에 종목·출처별 최신 스냅샷 1행을 정규화 저장한다(유일 키
  `symbol + source`). 재수집은 스냅샷을 갱신하고 원본은 append-only로 쌓인다.
- 행은 가격·전일대비등락률·당일 누적/전일 거래량, `nav`·`dprt`·`trc_errt`·추적배수,
  순자산총액(억원)·상장좌수, 운용사명·대표지수명·상장일, 통화, 출처, 기준시각(`as_of`),
  수신 시각, 원본 참조를 포함한다.
- 전량 수집(sweep)에서 개별 종목 실패는 오류로 기록하고 나머지 수집을 계속한다.
  실패가 있으면 수집 상태(`operations.api_sync_status`, 대상 `ETF`)를 실패로 기록하되
  성공한 스냅샷은 보존한다. 전체 실패 개수는 수집 결과로 보고한다.

## 분배율 (파생)

- 로드맵 정의를 따른다: `최근 12개월 분배율 = 최근 12개월 주당 분배금 합계 ÷ 현재가 × 100`.
- 분배금 합계는 [기업행사 계약](corporate-action-adjusted-price-data-contract.md)의
  `etf_distribution` 현재 버전 사실에서 락일 기준 최근 12개월을 합산하고, 현재가는 ETF
  스냅샷 가격을 쓴다. 응답은 수식·분배금 건수·기간·가격 기준시각을 함께 노출한다.
- 분배금 이력이 저장된 ETF(현재 KODEX 200)만 계산하며, 이력이 없으면 값 생성 없이
  사유와 함께 빈 값이다(fail-closed). 연환산 분배율은 지급 예상 횟수 근거가 없어
  v1에서 계산하지 않는다.

## 필수 조회 계약

- `GET /api/market-data/etfs`: 마스터 현재 버전 전체를 최신 스냅샷과 함께 반환한다.
  스냅샷이 없는 종목은 스냅샷 필드가 `null`이다. 응답은 출처·순자산 단위(`hundred_million_krw`)
  와 종목별 `as_of`를 포함한다.
- `GET /api/market-data/etfs/{symbol}`: 단일 ETF 상세(마스터 + 스냅샷 + 분배율 블록)를
  반환한다. 미등록 종목은 404다.
- 순위는 저장된 최신 스냅샷 값(등락률·거래량·괴리율·추적오차·순자산총액)에서만 만들고,
  화면은 정렬 기준·기준시각·출처를 항상 표시한다. 거래대금·기간 수익률·투자자별 순위는
  후속이다.

## 화면 반영 (승인 시안 3a)

- A 요약 KPI: ETF 종목 수, 스냅샷 보유 수, 상승·하락 종목 수, 괴리율 최대 절대값 등
  저장 사실의 집계만 표시한다.
- B 순위표: 정렬 기준 전환(등락률·거래량·괴리율·추적오차·순자산)과 기준시각을 표시한다.
- C 투자자별 순매수: 수급 사실이 수집된 ETF만 표시하고 나머지는 빈 상태다.
- D 선택 ETF 상세: NAV·괴리율·추적오차·추적배수·운용사·대표지수·상장일·순자산·분배율.

## 검증 시나리오

1. 마스터 재수집은 버전과 행 수를 늘리지 않고, 이름 변경은 이전 버전을 보존한 새 버전이
   된다.
2. 스냅샷 재수집은 행을 늘리지 않고 최신 값으로 갱신되며 원본은 쌓인다.
3. 개별 종목 수집 실패가 나머지 수집을 막지 않고 실패 개수가 보고된다.
4. 실제 전량 수집으로 마스터 1,163종목과 스냅샷을 적재하고, KODEX 200의 NAV·괴리율·
   운용사·분배율을 원본 응답·공식 값과 대조한다.
5. 읽기 API의 단위·기준시각·404와 분배율 fail-closed를 검증한다.
